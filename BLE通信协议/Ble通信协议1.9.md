## 1. 适用范围与术语

### 1.1 连接与传输

| 项 | 值 |
| --- | --- |
| 蓝牙名称 | `JiangLing` |
| 服务 UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX（手机写入） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX（手机订阅通知） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |
| 角色 | 手机 = BLE Central，板子 = BLE Peripheral |

传输约定：

1. 协议是**字节流**，不能假设一次写入 / 通知等于一帧；接收方必须跨多次写入 / 通知重组。
2. 默认 ATT MTU 为 23，单次特征值最多 20 字节；连接后建议协商 MTU 247。
3. CMD 使用带响应写入（Write With Response）；LOG / DAT 为板子单向通知。
4. PAYLOAD 内的多字节数值一律**大端序**（高字节在前）；文本使用 UTF-8，不带 `\0` 结尾，长度由 `LEN` 控制。
5. 需要精确解析的量用**定长定点数**：整数放大 100 倍后大端传输，不用浮点。

### 1.2 命名规范

- 第 3 字节叫 `TYPE`，由 `KIND`（大类：ACK / LOG / DAT / CMD）与 `KIND_TYPE`（低 6 bit 细分）拼成。
- 载荷长度叫 `LEN`（PAYLOAD 的字节数），载荷内容叫 `PAYLOAD`（文本 / 数据 / 命令参数 / 回复消息）。
- 命令名统一 `CMD_XXX`，文档与代码必须使用同一个常量名；代码里的 `kindType` 就是文档的 `KIND_TYPE`，禁止再叫 SubType。
- 文档里的 `0xAA` 等十六进制与二进制是同一字节的不同写法，传输时发的是原始字节。

## 2. 通道方向与合法性

> **CMD 只能 App → 小车，LOG / DAT 只能 小车 → App，ACK 只回应 CMD。**
> 任何一方收到不属于自己方向的帧，一律**不执行**；只有 CMD 方向的非法帧回 `ACK_ST_ERROR`(5)，
> 其他方向静默丢弃，避免两端互相刷帧。

| KIND | 合法方向 | 谁产生 | 接收方如何处理合法帧 | 收到反方向帧（非法） |
| --- | --- | --- | --- | --- |
| CMD（命令） | **App → 小车** | **仅 App** | 小车执行并回 ACK（64 条 SEQ 去重） | **App 收到 CMD**：不执行、不建记录，回 `ACK_ST_ERROR`(5) 后丢弃 |
| LOG（日志） | **小车 → App** | **仅小车** | App 判等级后写日志表（64 条 SEQ 去重） | 小车收到 LOG：**静默丢弃** |
| DAT（数据） | **小车 → App** | **仅小车** | App 解析 / 缓存（64 条 SEQ 去重） | 小车收到 DAT：**静默丢弃** |
| ACK（应答） | **小车 → App**（只回应 CMD） | **仅小车** | App 按 SEQ 回填命令；不判重 | 小车收到 App 发来的 ACK：**静默丢弃** |

强制约束：

1. **小车绝不主动发 CMD**。需要请求动作时只能发 `DAT_REQ`，由 App 映射成正常 CMD 发出。
2. **App 绝不发 LOG / DAT**；App 是纯显示端，日志与数据只能由小车产生。
3. **ACK 只用于回应 CMD**。经 DAT（含 `DAT_REQ`）触发的动作不占用 ACK 语义，`DAT_REQ` 本身不回 ACK。
4. 唯一例外：App 收到方向非法的 CMD 时可以回一条 `ACK_ST_ERROR`(5)，因为 ACK 属于 CMD 通道。
5. 目的：命令始终由 App 单点发出，保证小车不可能伪造命令，ACK 也只有一个可对账来源。

非法帧处理策略：

| 接收方 | 收到的帧 | 处理 |
| --- | --- | --- |
| App | CMD | **非法**：不执行、不建记录，回 `ACK_ST_ERROR`(5) 后丢弃 |
| App | LOG / DAT / ACK | 合法，正常处理 |
| 小车 | CMD | 合法，执行并回 ACK |
| 小车 | LOG / DAT / ACK | **非法**：静默丢弃，不回任何帧 |
| 任一端 | CRC 校验失败 | 静默丢弃 |
| 任一端 | 长度不符（`LEN` 非法） | 丢弃该帧；DAT 静默丢弃，CMD 回 `ACK_ST_ERROR`(5) |

## 3. 帧结构

```text
帧序列：[HEAD] [SEQ] [TYPE] [LEN] [PAYLOAD] [CRC8]
         1B    1B    1B     1B    0~255B     1B
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| `HEAD` | 1 Byte | 固定 `0xAA`，帧同步头 |
| `SEQ` | 1 Byte | 序列号；CMD 为 `1~255`（`0` 专用于初始化命令），LOG / DAT / ACK 为 `0~255` |
| `TYPE` | 1 Byte | 含 KIND（高 2 bit）+ KIND_TYPE（低 6 bit） |
| `LEN` | 1 Byte | PAYLOAD 的字节数，0~255 |
| `PAYLOAD` | 0~255 Byte | 文本 / 数据 / 命令参数 / 回复消息 |
| `CRC8` | 1 Byte | CRC-8/ATM 校验，范围 `HEAD` 到 `PAYLOAD` |

- **最小帧**：`LEN=0`，总长 5 Byte；**最大帧**：`LEN=255`，总长 261 Byte。
- **实现建议**：BLE 传输层建议单帧不超过 128 Byte，避免 MTU 分片过于频繁。

## 4. TYPE 字节

TYPE = **KIND（高 2 bit）+ KIND_TYPE（低 6 bit）**，整字节 8 bit，共 256 种可能；每个 KIND 独占 64 个编号（0~63）。

| bit | 字段 | 位数 | 说明 |
| --- | --- | --- | --- |
| 7~6 | KIND | 2 | 大类：ACK=00、LOG=01、DAT=10、CMD=11 |
| 5~0 | KIND_TYPE | 6 | 类型细分编号，每个 KIND 独立编号 0~63 |

| KIND | 二进制 | 十进制 | TYPE 基础值 | 对应章节 |
| --- | --- | --- | --- | --- |
| ACK | `00` | `0` | `0x00` | 第 10 节 |
| LOG | `01` | `1` | `0x40` | 第 13 节 |
| DAT | `10` | `2` | `0x80` | 第 11 节 |
| CMD | `11` | `3` | `0xC0` | 第 9 节 |

```text
TYPE = (KIND << 6) | KIND_TYPE
```

- 示例：`CMD_FORWARD` = `(3 << 6) | 1` = `0xC1`；其 ACK = `(0 << 6) | 1` = `0x01`；`LOG_WARN` = `(1 << 6) | 2` = `0x42`。
- **ACK 的 KIND_TYPE = 被应答命令的 KIND_TYPE**，结果不放在 TYPE 里，而是放在 `PAYLOAD[0]`。
- 新增类型必须在对应 KIND_TYPE 表里登记编号，不得复用已废弃编号；6 bit 共 64 项，旧实现已用其中一部分。

## 5. SEQ 与去重

| 帧类型 | SEQ 范围 | 计数者 | 说明 |
| --- | --- | --- | --- |
| CMD | `1~255` | 发送 CMD 的一方 | `0` 专用于 `CMD_SESSION_INIT`；接收方维护最近 64 条去重列表 |
| ACK | `0~255` | 无独立计数器 | 原样回显对应 CMD 的 `SEQ`（可能为 0）；不判重 |
| LOG | `0~255` | 板子 | 接收方维护最近 64 条去重窗口 |
| DAT | `0~255` | 板子 | 接收方维护最近 64 条去重窗口 |

> **只有命令的 SEQ 是 1~255，ACK / LOG / DAT 都是 0~255；CMD / LOG / DAT 各维护一份 64 条列表，ACK 不判重。**

规则：

1. CMD 序号 `1~255`，到 255 后回到 1；`0` 只用于 `CMD_SESSION_INIT`，不参与普通递增。
2. 板子每次上电 / 复位时，自己的 CMD / LOG / DAT 计数器归零；后台自动重连不清空序号。
3. 手动重发同一条命令时 SEQ 保持不变（幂等，避免同一条命令被执行两次）。
4. **CMD / LOG / DAT 各维护一份「最近 64 条 SEQ」列表**（接收方维护，FIFO 淘汰）：
   - CMD：由小车维护，命中重复**只回 ACK、不重复执行**；
   - LOG / DAT：由 App 维护，命中重复**直接丢弃**，不重复写日志表 / 不重复更新状态；
   - 三份列表彼此独立（CMD 的 64 条与 LOG / DAT 的 64 条互不占位）。
5. 列表只在以下情况清空：App 侧收到 `resetDone=1` 的 ACK 时清空 LOG / DAT 两份窗口；板子侧收到生效的 `CMD_SESSION_INIT`（SEQ=0）或自身复位。
6. 后台自动重连、App 切前后台、普通断连都**不清空**列表（断连保留才能挡住重连后的重发）。
7. `SEQ=0`（初始化命令）不写入 CMD 去重列表；LOG / DAT 的 `SEQ=0` 正常参与窗口。
8. ACK 丢失后重发的 ACK 直接接受，不做去重。

**App 侧待确认命令队列**：最多 64 条，仅内存；条目 = `seq / 命令类型 / 发送时间 / 状态`。
发出 CMD 入队、收到 ACK 出队（任何状态都算「已回复」）；超出上限丢弃最旧，同 SEQ 手动重发覆盖旧条目；
断连**不出队、不清空**，重连后仍能看出哪些命令没有回复。

## 6. 会话初始化

**每次传输层连接建立后，手机发送的第一帧必须是 `CMD_SESSION_INIT`，`SEQ=0`。**

请求 PAYLOAD（1 Byte）：

| 偏移 | 参数名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `CMD_SESSION_INIT_PROTOCOL_VERSION` | u8 | 手机协议版本，取值 `18` |

- 请求**不带 `mode` 参数**：板子只看自己的 `isInit` 决定是否重置，手机只看 ACK 的 `resetDone` 决定是否清空本地。
- 固件必须用**等于**判断版本（`version == 18`），不接受「大于 / 小于都算兼容」的宽松判断。
- 版本不匹配（如手机发 `17`）→ 回 `ACK_ST_ERROR`(5) 且 `resetDone=0`，双方都不执行清空 / 重置，也不得继续按本格式解析 DAT。

板子端 `isInit` 状态机：

| 时刻 | `isInit` | 含义 |
| --- | --- | --- |
| `setup()` 里 | `true` | 刚启动，从未处理过普通命令 |
| 收到第一条普通命令（SEQ≠0）后 | `false` | 已正常开始工作 |
| 板子再次上电 / 复位 | 变回 `true` | 从零开始 |

| 板子自身 `isInit` | 板子动作 | ACK `resetDone` | 手机动作 |
| --- | --- | --- | --- |
| `true`（刚启动） | 重置（清空 CMD 去重列表、命令序号归零） | `1` | 清空 LOG / DAT 窗口、待确认队列，命令序号归零 |
| `false`（已正常工作中） | 保留（不清空） | `0` | 窗口、队列、命令序号全部保留 |

统一场景对照：

| 场景 | 板子 `isInit` | 板子动作 | ACK `resetDone` | 手机动作 |
| --- | --- | --- | --- | --- |
| 第一次连接 | `true` | 重置 | `1` | 清空 |
| 自动重连（板子没重启） | `false` | 保留 | `0` | 保留 |
| 自动重连（板子刚重启） | `true` | 重置 | `1` | 清空 |
| 用户主动连接（板子没重启） | `false` | 保留 | `0` | 保留 |
| 用户主动连接（板子刚重启） | `true` | 重置 | `1` | 清空 |

初始化 ACK（`KIND_TYPE=8`，`LEN=2`）：

| 偏移 | 参数名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | 状态 | u8 | `已执行`(3) = 成功；`错误异常`(5) = 版本不兼容；`无法执行`(6) = 板子未就绪 |
| 1 | `ACK_SESSION_INIT_RESET_DONE` | u8 | `1` = 板子已重置；`0` = 未重置 |

- 握手成功判定：`SEQ=0` 的 ACK，且状态 ∈ {`收到`(0), `已执行`(3)}。
- 握手成功后，小车紧接着发一轮 `DAT_INFO`（三子帧 1→2→3），App 内存缓存。

## 7. CRC-8/ATM 校验

- 多项式 `0x07`，初始值 `0x00`，输入 / 输出反射：否，结果异或：`0x00`。
- 计算范围：`HEAD + SEQ + TYPE + LEN + PAYLOAD`。
- 校验失败：整帧丢弃，不回复任何内容。

---

## 8. 接收解析

1. 字节追加到接收环形缓冲区（建议 ≥ 512 Byte），查找帧头 `0xAA`；不足 5 Byte（最小帧）时等待下一批数据。
2. 读取 `SEQ`、`TYPE`、`LEN`；`LEN` 超过实现上限（BLE 建议 128）时从 `HEAD+1` 继续扫描；缓冲区不足 `5 + LEN` 时等待，半帧超时建议 1 s。
3. 校验 CRC8：失败则丢弃 HEAD 这 1 个字节并从下一个字节继续扫描；成功则按 KIND 分流，处理后移除整帧。
4. 缓冲区溢出时丢弃最旧数据并本地记录警告。

## 9. CMD 命令

| 项 | 值 |
| --- | --- |
| KIND | `11`（二进制），十进制 `3`；TYPE 基础值 `0xC0` |
| TYPE 计算 | `0xC0 \| KIND_TYPE` |
| SEQ 范围 | `1~255`；`0` 专用于 `CMD_SESSION_INIT` |
| 方向 | **App → 小车（单向，强制）** |
| 是否需要 ACK | 是，收到 CMD 的一方必须回 ACK |
| 是否判重 | 是，接收方按「接收到的 CMD SEQ」维护最近 64 条；`SEQ=0` 不入列表 |

### 9.1 KIND_TYPE 表（已实现 13 项）

| 编号 | 名称 | TYPE | LEN | PAYLOAD | 说明 |
| --- | --- | --- | --- | --- | --- |
| **0** | `CMD_STOP` | `0xC0` | 0 | 无 | 急停，最高优先级，立即停止所有运动 |
| **1** | `CMD_FORWARD` | `0xC1` | 1 | `LEVEL` u8 0~100 | 前进：最大直线速度的百分比 |
| **2** | `CMD_BACK` | `0xC2` | 1 | `LEVEL` u8 0~100 | 后退：最大直线速度的百分比 |
| **3** | `CMD_LEFT` | `0xC3` | 1 | `TURN` u8 0~100 | 原地左转：最大回转角速度的百分比（左轮倒、右轮正） |
| **4** | `CMD_RIGHT` | `0xC4` | 1 | `TURN` u8 0~100 | 原地右转：最大回转角速度的百分比（左轮正、右轮倒） |
| **5** | `CMD_PITCH` | `0xC5` | 1 | `ANGLE` u8 0~255 | 云台俯仰，线性映射 0°~180°（角度，不是百分比） |
| **6** | `CMD_YAW` | `0xC6` | 1 | `ANGLE` u8 0~255 | 云台水平，线性映射 0°~360°（角度，不是百分比） |
| **7** | `CMD_REQ_RECORD` | `0xC7` | 0 | 无 | 请求开始录音：由 `DAT_REQ`(请求码 2) 触发 |
| **8** | `CMD_SESSION_INIT` | `0xC8` | 1 | `PROTOCOL_VERSION` u8 | 会话初始化，SEQ=0，每次连接第一帧 |
| **9** | `CMD_LEFT_SHIFT` | `0xC9` | 1 | `LEVEL` u8 0~100 | 麦轮横向左移：最大横移速度的百分比 |
| **10** | `CMD_RIGHT_SHIFT` | `0xCA` | 1 | `LEVEL` u8 0~100 | 麦轮横向右移：最大横移速度的百分比 |
| **16** | `CMD_QUERY_SEQ` | `0xD0` | 1 | `TARGET_SEQ` u8 | 手动查询：接收去重列表里有没有这条 SEQ |
| **19** | `CMD_REQ_INFO` | `0xD3` | 0 | 无 | 请求补发一轮 `DAT_INFO`（三子帧） |

> 表中所有命令都只有 **App → 小车** 一个方向；小车要请 App 做事，走 `DAT_REQ` 请求码。

### 9.2 命令参数

| 命令 | 适用底盘 | 物理含义 | 单位 | 范围 / 映射 |
| --- | --- | --- | --- | --- |
| `CMD_FORWARD` / `CMD_BACK` | 全部 | 直线行驶速度挡位 | % | 0~100 |
| `CMD_LEFT` / `CMD_RIGHT` | 差速轮 / 麦轮 | 原地回转角速度幅度 | % | 0~100 |
| `CMD_LEFT_SHIFT` / `CMD_RIGHT_SHIFT` | 麦轮 / 全向轮 | 横向平移速度挡位 | % | 0~100 |
| `CMD_PITCH` | 带云台车型 | 绝对角度 | u8 | 0~255 → 0°~180°（`raw × 180 / 255`） |
| `CMD_YAW` | 带云台车型 | 绝对角度 | u8 | 0~255 → 0°~360°（`raw × 360 / 255`） |

- 挡位语义：`90` = 最大速度的 90%；`0` = 以 0 幅度执行，等效停止该动作。
- 不做绝对速度传递：协议里没有 m/s、没有 PWM、没有轮转速目标值；固件按自己的标定表换算。
- 原地转弯不是半径转弯；带转弯半径的弧线行驶属未来扩展，本版本不实现。
- 普通差速轮不实现麦轮 / 万向轮命令，收到后回 ACK `无法识别`(4)。

无参数命令（`LEN = 0`）：

| 命令 | 说明 |
| --- | --- |
| `CMD_STOP` | 立即停止并清除待执行运动命令 |
| `CMD_REQ_RECORD` | 由 `DAT_REQ`(请求码 2) 触发，小车执行并回 ACK |
| `CMD_REQ_INFO` | 请求补发一轮 `DAT_INFO` |

> 只有上表三条是 `LEN=0`。**所有运动命令固定 `LEN=1`**，参数为 `0` 时也必须发 1 个字节的 `0x00`。

### 9.3 `CMD_QUERY_SEQ` 与 `CMD_REQ_INFO`

`CMD_QUERY_SEQ` 的参数 = 要查询的序列号；板子只看自己的接收去重列表里有没有这条 SEQ：

| 列表里有 | 回 ACK 状态 | 人工结论 |
| --- | --- | --- |
| 有 | `是（有）`(1) | 命令已收到，只是 ACK 丢了 → 不必再发 |
| 无 | `否（无）`(2) | 命令确实丢了 → 重新发送（分配新 SEQ） |

- 只查「在不在列表里」，不区分它是否已经被 64 条上限顶掉；顶掉了按「无」回复。
- 只用于手动调试，App 不会自动发送；这条查询命令本身也要回 ACK。
- `CMD_REQ_INFO`（`LEN=0`）用于 App 重装 / 清缓存、或 `DAT_INFO` 丢帧后的手动补拉；小车回 ACK（`已执行`(3) / `无法识别`(4)）后补发一轮 `DAT_INFO`。
  App 不得周期发送本命令；该 ACK 只表示受理，信息帧随后异步到达。

### 9.4 命令规则

1. **最后一条命令生效**：新的运动命令覆盖当前动作，`CMD_STOP` 清空动作。
2. **运动命令固定 `LEN=1`**：参数 `0` 表示 0 幅度，但 PAYLOAD 仍必须是 1 字节。
3. **参数范围一律校验**：运动命令 >100、云台 / 查询 >255 都属非法，回 ACK `错误异常`(5)，不执行。
4. 运动控制 KIND_TYPE 按车型选择性实现；未实现的 KIND_TYPE 回 ACK `无法识别`(4)，不得静默丢弃。
5. **`CMD_STOP` 最高优先级**：不受忙状态阻挡，重复收到也回 ACK。
6. **每个 CMD 必须回 ACK**；`CMD_REQ_RECORD` 成功 `已执行`(3)、正在录音 `无法执行`(6)、无权限 `错误异常`(5)。
7. **不自动重发**：App 只发一次，无超时定时器、不自动重发、不自动重查；无回复显示「未收到回复」。
8. **手动重发沿用原 SEQ**：接收去重列表命中重复时只回 ACK、不重复执行。
9. **失联保护**：建议固件在超过约 1 s 未收到运动命令时自动停车。
10. **命令只有一个来源：App**。小车绝不主动发 CMD，需要动作时发 `DAT_REQ`。
11. **一条 CMD + 一条 ACK = 一条完整命令对象**：先建记录，ACK 按 `SEQ` 匹配回填。
12. **手机侧数据不主动推送**：小车要录音等数据时发 `DAT_REQ`(请求码 2)，App 再发 `CMD_REQ_RECORD`。
13. **ESP32 侧不建回复栈**：收到 CMD 立即回 ACK（`收到`(0) 或 `已执行`(3)），靠 64 条去重表防重复执行。

> 所有车型都必须实现 `CMD_SESSION_INIT`(8)、版本校验、`CMD_REQ_INFO`(19) 与握手后的一轮 `DAT_INFO`；
> `CMD_QUERY_SEQ`(16) 建议实现，便于手动排查丢帧。

## 10. ACK 应答

| 项 | 值 |
| --- | --- |
| KIND | `00`（二进制），十进制 `0`；TYPE 基础值 `0x00` |
| TYPE 计算 | `0x00 \| KIND_TYPE` |
| KIND_TYPE | **与它应答的那条 CMD 的 KIND_TYPE 完全一致** |
| 方向 | 正常：**小车 → App**；唯一例外：App 回 `ACK_ST_ERROR`，仅用于方向非法的 CMD |
| 是否需要 ACK | 否（禁止套娃） |
| 是否判重 | **否**（重复的 ACK 直接接受） |

帧结构：

```text
[HEAD] [SEQ] [TYPE = 0x00 | CMD 的 KIND_TYPE] [LEN = 1 + n] [状态(1B)] [附加参数(nB)] [CRC8]
```

| 字段 | 说明 |
| --- | --- |
| `SEQ` | 原样回显被应答 CMD 的 SEQ（含 `SEQ=0`）；范围 `0~255` |
| `TYPE` | `0x00 \| 被应答 CMD 的 KIND_TYPE` |
| `LEN` | PAYLOAD 字节数 = `1 + 附加参数长度`；最小 `1`，永远 ≥ 1 |
| `状态` | `PAYLOAD[0]`，取值见下表 |
| 附加参数 | 从 `PAYLOAD[1]` 开始，含义由具体命令定义 |

回复状态表：

| 值 | 名称 | 中文 | 含义 | 典型场景 |
| --- | --- | --- | --- | --- |
| **0** | `ACK_ST_RECEIVED` | 收到 | 命令已进入接收方队列，尚未执行完成 | 普通运动命令的即时回应 |
| **1** | `ACK_ST_YES` | 是（有） | 肯定结果 | `CMD_QUERY_SEQ`：列表里有该 SEQ |
| **2** | `ACK_ST_NO` | 否（无） | 否定结果 | `CMD_QUERY_SEQ`：列表里没有该 SEQ |
| **3** | `ACK_ST_DONE` | 已执行 | 命令已执行完成 | 停止、云台到位、初始化成功 |
| **4** | `ACK_ST_UNKNOWN` | 无法识别 | 不认识这个 KIND_TYPE | 未实现的命令（如麦轮命令用在差速轮车上） |
| **5** | `ACK_ST_ERROR` | 错误异常 | 执行过程出错 | 堵转、过流、过热、参数非法、版本不兼容 |
| **6** | `ACK_ST_CANNOT` | 无法执行 | 条件不满足，本次不执行 | 设备忙、未初始化完成、保护状态中 |
| 7~255 | 预留 | - | 全局共享同一张状态表 | 未来扩展 |

应答对应关系：

| 收到的 CMD | 回复的 ACK |
| --- | --- |
| 普通命令（如 `CMD_FORWARD`，`0xC1`） | TYPE=`0x01`、`LEN=1`、`PAYLOAD=[状态]` |
| `CMD_QUERY_SEQ`（`0xD0`） | TYPE=`0x10`、`LEN=1`、`PAYLOAD=[1 有 / 2 无]` |
| `CMD_SESSION_INIT`（`0xC8`） | TYPE=`0x08`、`LEN=2`、`PAYLOAD=[状态, resetDone]` |
| `CMD_REQ_INFO`（`0xD3`） | TYPE=`0x13`、`LEN=1`、`PAYLOAD=[已执行(3) / 无法识别(4)]` |
| App 收到方向非法的 CMD | TYPE = 该 CMD 的 KIND_TYPE、`LEN=1`、`PAYLOAD=[5]` |

**一对一**：收到哪条命令，ACK 的 KIND_TYPE 就是哪条命令的 KIND_TYPE，绝不借用别的编号。

方向非法 CMD 的处理：

| 步骤 | App 动作 |
| --- | --- |
| 1 | 不执行、不建命令记录、不改任何状态 |
| 2 | 回 ACK：`SEQ` 与 `KIND_TYPE` 与该 CMD 一致，`LEN=1`，`PAYLOAD=[ACK_ST_ERROR(5)]` |
| 3 | 调试页提示「收到方向非法的 CMD」 |

ACK 规则：

1. 只有 CMD 需要 ACK；LOG、DAT 不需要。
2. ACK 的 SEQ 与 KIND_TYPE 必须与对应 CMD 完全一致（含 `SEQ=0`）；`LEN` 永远 ≥ 1，`PAYLOAD[0]` 必须是状态字节。
3. ACK 不再被应答；发送方按「SEQ + 方向」匹配，同一条 CMD 只回一个 ACK。
4. `收到` 不等于动作完成，`已执行` 才表示完成；`无法执行`(6) 是最终结论，App 不自动重试。
5. 版本不兼容时 ACK 必须回 `错误异常`(5) 且 `resetDone=0`，此后双方不按本格式解析 DAT。

## 11. DAT 数据

| 项 | 值 |
| --- | --- |
| KIND | `10`（二进制），十进制 `2`；TYPE 基础值 `0x80` |
| TYPE 计算 | `0x80 \| KIND_TYPE` |
| PAYLOAD 字节序 | **多字节数值一律大端** |
| SEQ 范围 | `0~255` |
| 方向 | **小车 → App（单向，强制）**；App 永不发 DAT |
| 是否需要 ACK | **否**（包括 `DAT_REQ`：DAT 通道无 ACK 语义） |
| 是否判重 | **是**：接收方维护最近 64 条已处理 SEQ，命中重复直接丢弃 |
| 产生方 | **仅小车** |

### 11.1 KIND_TYPE 表（已实现 6 项）

| 编号 | 名称 | TYPE | PAYLOAD | 说明 |
| --- | --- | --- | --- | --- |
| **0** | `DAT_BAT` | `0x80` | 电压 u16（0.01V），2 B | 只报电压原始值，电量由 App 换算 |
| **1** | `DAT_US` | `0x81` | 距离 u16（cm），2 B | 超声波距离 |
| **2** | `DAT_WHEEL` | `0x82` | 左轮 int16 + 右轮 int16（0.01 r/s），4 B | 左右轮转速 |
| **10** | `DAT_INFO` | `0x8A` | 按 `PAYLOAD[0]` 子类型拆 3 帧，21 / 6 / 7 B | 一次性静态信息 |
| **11** | `DAT_MEM` | `0x8B` | 16 B | 内存与运行状态 |
| **12** | `DAT_REQ` | `0x8C` | 请求码 u8 + 参数 u8，2 B | 小车请求通道 |

> 所有定点数都是「放大后取整」再大端传输：`2.50 r/s` → `250` → 字节 `00 FA`。
> 无效值统一用**全 `0xFF` 的字段**；App 收到无效值时不更新该字段，界面显示 `—`。

### 11.2 `DAT_BAT` — 电池电压（`LEN = 2`）

| 偏移 | 参数名 | 类型 | 单位 | 换算 | 范围 |
| --- | --- | --- | --- | --- | --- |
| 0 | `DAT_BAT_VOLTAGE` | u16 大端 | 0.01 V | `电压V = raw / 100` | 0~65534（0.00~655.34 V） |

- 固件只上报电压原始值，不计算、不上报电量百分比；电量由 App 按电压曲线换算。
- `0xFFFF` → 电压无效；App 保留上一次的电压与电量，界面显示 `—`，不用 `0` 冒充。
- 固件动作：把 ADC / 分压采样换算成 `round(voltage × 100)` 的整数，按大端写入。
- 示例：`7.24V` → `724` = `0x02D4` → `PAYLOAD = 02 D4`。

### 11.3 `DAT_US` — 超声波距离（`LEN = 2`）

| 偏移 | 参数名 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | `DAT_US_DISTANCE` | u16 大端 | cm | 直接使用；建议量程 2~400 cm；`0xFFFF` = 无效 |

- 不保留小数；`0xFFFF` 表示未采样 / 超量程 / 传感器故障。

### 11.4 `DAT_WHEEL` — 左右轮转速（`LEN = 4`）

| 偏移 | 参数名 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | `DAT_WHEEL_LEFT` | int16 大端（有符号） | 0.01 r/s | 正值 = 前进，负值 = 后退 |
| 2 | `DAT_WHEEL_RIGHT` | int16 大端（有符号） | 0.01 r/s | 符号规则同左轮 |

- 范围 ±327.67 r/s；`DAT_WHEEL_LEFT/RIGHT = 0xFFFF`（即 `-1`）表示该轮无效。
- 固件只上报轮转速，不换算成线速度，也不上报「速度百分比」。
- 示例：左轮 `2.50 r/s` → `0x00FA`；右轮 `-1.20 r/s` → `0xFF88` → `PAYLOAD = 00 FA FF 88`；
  App 取平均 `0.65 r/s`，显示约 `0.14 m/s`。

### 11.5 `DAT_INFO` — 一次性静态信息

**发送时机（强制）**：只在 `CMD_SESSION_INIT` 版本校验通过、**且回完 ACK 之后**发一轮（3 帧，顺序固定 1→2→3），
之后**不得周期重发**。语义是「每次握手成功发一次」，不是「每次开机发一次」；App 可发 `CMD_REQ_INFO`(19) 补拉一轮。

| 子类型 | 名称 | LEN | 内容 |
| --- | --- | --- | --- |
| 1 | `DAT_INFO_SUB_VERSION` | 21 | 固件版本 + 协议版本 + 设备型号 |
| 2 | `DAT_INFO_SUB_POWER` | 6 | 电池串数 / 电芯 + 轮胎直径 + 最大挡位 |
| 3 | `DAT_INFO_SUB_STORAGE` | 7 | Flash / PSRAM 容量 + 能力位图 |

子类型 1：`DAT_INFO_SUB_VERSION`（`LEN = 21`）

| 偏移 | 参数名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | 子类型 | u8 | 固定 `1` |
| 1 | `DAT_INFO_FW_MAJOR` | u8 | 固件主版本 |
| 2 | `DAT_INFO_FW_MINOR` | u8 | 固件次版本 |
| 3 | `DAT_INFO_FW_PATCH` | u8 | 固件修订号 |
| 4 | `DAT_INFO_PROTOCOL_VERSION` | u8 | 固件实现的本协议版本（`18`） |
| 5 | `DAT_INFO_MODEL` | ASCII 16 B | 设备型号，不足 16 B 补 `0x00`，不得含中文 |

子类型 2：`DAT_INFO_SUB_POWER`（`LEN = 6`）

| 偏移 | 参数名 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 子类型 | u8 | - | 固定 `2` |
| 1 | `DAT_INFO_BATTERY_CELLS` | u8 | 串 | 电池串数（如 2S = `2`）；未知填 `0` |
| 2 | `DAT_INFO_BATTERY_CHEMISTRY` | u8 | - | `0` 锂离子 / `1` 磷酸铁锂 / `2` 镍氢 / `3` 铅酸 |
| 3 | `DAT_INFO_WHEEL_DIAMETER` | u16 大端 | mm | 轮胎直径（如 68）；`0xFFFF` = 未知 |
| 5 | `DAT_INFO_MAX_GEAR` | u8 | % | 最大挡位上限（0~100，通常 `100`） |

子类型 3：`DAT_INFO_SUB_STORAGE`（`LEN = 7`）

| 偏移 | 参数名 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 子类型 | u8 | - | 固定 `3` |
| 1 | `DAT_INFO_FLASH` | u16 大端 | MB | Flash 容量；`0xFFFF` = 未知 |
| 3 | `DAT_INFO_PSRAM` | u16 大端 | KB | PSRAM 容量；`0x0000` / `0xFFFF` = 无 PSRAM |
| 5 | `DAT_INFO_CAPABILITY` | u16 大端 | 位图 | 能力位图 |

能力位图：

| bit | 掩码 | 名称 | 含义 |
| --- | --- | --- | --- |
| 0 | `0x0001` | `CAP_VOICE` | 支持语音识别 / 播报 |
| 1 | `0x0002` | `CAP_GIMBAL` | 有云台（支持 `CMD_PITCH/YAW`） |
| 2 | `0x0004` | `CAP_DISPLAY` | 板载屏幕 |
| 3 | `0x0008` | `CAP_US` | 有超声波（`DAT_US` 有效） |
| 4 | `0x0010` | `CAP_CAMERA` | 有摄像头 |
| 5 | `0x0020` | `CAP_IMU` | 有 IMU |
| 6 | `0x0040` | `CAP_MECANUM` | 麦轮（支持 `CMD_LEFT_SHIFT/RIGHT_SHIFT`） |
| 7~15 | - | 预留 | 未来扩展 |

### 11.6 `DAT_MEM` — 内存与运行状态（`LEN = 16`）

发送频率：建议 **1 s 一次**（`DAT_MEM_INTERVAL_MS = 1000`，固件可配置）；禁止跟随 500 ms 遥测同一节奏发送。

| 偏移 | 参数名 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | `DAT_MEM_RAM_FREE` | u16 大端 | KB | 内部 RAM 当前空闲；`0xFFFF` = 无效 |
| 2 | `DAT_MEM_PSRAM_FREE` | u16 大端 | KB | PSRAM 当前空闲；`0xFFFF` = 无效 / 无 PSRAM |
| 4 | `DAT_MEM_RAM_MIN` | u16 大端 | KB | 内部 RAM 历史最小空闲 |
| 6 | `DAT_MEM_PSRAM_MIN` | u16 大端 | KB | PSRAM 历史最小空闲 |
| 8 | `DAT_MEM_UPTIME` | u32 大端 | s | 运行时长 |
| 12 | `DAT_MEM_LOG_QUEUE` | u8 | 条 | 日志发送队列水位；`0xFF` = 无效 |
| 13 | `DAT_MEM_DAT_QUEUE` | u8 | 条 | DAT 发送队列水位；`0xFF` = 无效 |
| 14 | `DAT_MEM_LOG_DROPPED` | u16 大端 | 条 | 日志累计丢弃计数 |

- internal RAM 与 PSRAM **两份独立**，不混成一个 free 值，最小空闲同理；无效值一律全 `0xFF`。

### 11.7 `DAT_REQ` — 小车请求 App 发命令（`LEN = 2`）

小车「发起命令」的唯一合法方式：小车不能发 CMD，只能发一条 `DAT_REQ`，由 App 按请求码映射成一条正常 CMD。

| 偏移 | 参数名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `DAT_REQ_CODE` | u8 | 请求码；未知码 App 丢弃并提示 |
| 1 | `DAT_REQ_PARAM` | u8 | 参数，含义与范围由请求码决定；App 会裁剪到合法区间 |

请求码表：

| 请求码 | 名称 | 映射 CMD | 参数范围 | 允许重复 |
| --- | --- | --- | --- | --- |
| 1 | `REQ_STOP` | `CMD_STOP`(0) | `0`（固定 `0x00`） | **是**（急停可连发） |
| 2 | `REQ_RECORD` | `CMD_REQ_RECORD`(7) | `0` | 否（1000 ms 防抖） |
| 3 | `REQ_SHIFT_LEFT` | `CMD_LEFT_SHIFT`(9) | `0~100` | 否（1000 ms 防抖） |
| 4 | `REQ_SHIFT_RIGHT` | `CMD_RIGHT_SHIFT`(10) | `0~100` | 否（1000 ms 防抖） |
| 5 | `REQ_PITCH` | `CMD_PITCH`(5) | `0~255` | 否（1000 ms 防抖） |
| 6 | `REQ_YAW` | `CMD_YAW`(6) | `0~255` | 否（1000 ms 防抖） |
| 7 | `REQ_FORWARD` | `CMD_FORWARD`(1) | `0~100` | 否（1000 ms 防抖） |
| 8 | `REQ_BACK` | `CMD_BACK`(2) | `0~100` | 否（1000 ms 防抖） |
| 9 | `REQ_LEFT` | `CMD_LEFT`(3) | `0~100` | 否（1000 ms 防抖） |
| 10 | `REQ_RIGHT` | `CMD_RIGHT`(4) | `0~100` | 否（1000 ms 防抖） |

标准时序：

```text
小车 → App : DAT_REQ(SEQ=m, LEN=2, [请求码, 参数])        ← 只是请求，不回 ACK
App 内部    : 请求码表 → CMD KIND_TYPE → 参数裁剪 → 防抖判断
App → 小车 : CMD_xxx(SEQ=n, LEN=1, [参数])                 ← 命令由 App 单点发出
小车 → App : ACK(KIND_TYPE=xxx, SEQ=n, [状态])             ← 唯一一次 ACK
```

- `DAT_REQ` 本身不回 ACK；映射出的 CMD 照常回 ACK，ACK 的 SEQ 是 App 新分配的 CMD SEQ。
- 参数越界时 App 裁剪到合法范围，不拒绝整条请求；小车请求了它自己未实现的 CMD 时会收到 `无法识别`(4)，属正常闭环。

### 11.8 `LEN` 定长对照

| 类型 | 要求 |
| --- | --- |
| `DAT_BAT` | 2 |
| `DAT_US` | 2 |
| `DAT_WHEEL` | 4 |
| `DAT_INFO` | 按 `PAYLOAD[0]` 子类型分别 21 / 6 / 7（未知子类型直接丢弃） |
| `DAT_MEM` | 16 |
| `DAT_REQ` | 2 |

长度不符的帧视为无效，App 丢弃不解析。

### 11.9 DAT 规则

1. 单向上报，无 ACK、无重发；App 收到即解析展示。
2. `SEQ` 由板子独立计数，范围 `0~255`（与 CMD、LOG 分开）；板子上电 / 复位时归零，断线重连不清空。
3. DAT 维护最近 64 条 SEQ，命中重复直接丢弃；窗口只在 `resetDone=1` 或 App 进程重启时清空，普通断连不清空。
4. 定点数为整数：固件负责四舍五入，协议层不接受「带小数的原始值」。
5. 无效值统一为 `0xFFFF`；App 保留上一次的值，显示 `—`，不得用 `0` 冒充。
6. 高频数据必须合并上报并限速（BLE 建议每帧间隔 ≥ 20 ms）。
7. DAT 是**有价值的确认数据**；运动命令的执行结果用 DAT 回传，不要用 LOG。
8. App 端不主动推送任何数据，也不得在本地伪造 DAT；断开后数值冻结在最后一次收到的值。
9. 固件只上报原始量（电压 0.01V、距离 cm、轮转速 0.01 r/s）；电量百分比与线速度由 App 换算。
10. DAT 只能 小车 → App；小车收到 DAT 一律静默丢弃。`DAT_INFO` 禁止周期重发；`DAT_MEM` 默认 1 s 一次。

## 12. 数据责任与换算

> **小车只交原始量，所有换算统一放 App。** 换电池、换电芯串数、换轮径、换电机 → 只改 App 常量 / 曲线表。

| 量 | 产生方 | 原始编码 | App 计算 | 固件禁止 |
| --- | --- | --- | --- | --- |
| 电池电压 | 小车（ADC / 分压采样） | `DAT_BAT_VOLTAGE` u16 0.01V | `电压V = raw / 100`，显示 2 位小数 | 不换算成电量、不上报百分比 |
| 电量百分比 | App | 无（协议不传） | 电压 → 曲线插值 | 固件不查表、不估算 |
| 轮转速 | 小车（编码器测速） | `DAT_WHEEL_LEFT/RIGHT` int16 0.01 r/s | `rps = raw / 100` | 不换算 m/s、不设轮径常量 |
| 线速度 | App | 无（协议不传） | `v = rps × π × 0.068` | 不上报 m/s |
| 超声波距离 | 小车 | `DAT_US_DISTANCE` u16 cm | 直接使用 | 不做单位变换 |
| 挡位 / 转弯幅度 | App（用户操作） | CMD 参数 u8 0~100 | 不做换算 | 按标定表转 PWM / 轮转速 |

电池电压 → 电量百分比（仅 App，分段线性插值；默认按 2S 锂离子标定，整组 6.00 ~ 8.40 V）：

| 电压（V） | 6.00 | 6.40 | 6.60 | 6.80 | 7.00 | 7.20 | 7.40 | 7.60 | 7.80 | 8.00 | 8.20 | 8.40 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 电量（%） | 0 | 3 | 6 | 12 | 22 | 35 | 50 | 65 | 78 | 88 | 95 | 100 |

```text
给定电压 v：
  v ≤ 6.00  → 0%
  v ≥ 8.40  → 100%
  否则找到相邻区间 [v0, v1]，按 p = p0 + (v - v0) / (v1 - v0) × (p1 - p0) 插值
```

- 曲线表放在 App 常量里，两张表必须等长、电压严格递增；固件永远只传电压。
- 显示：电量 1 位小数（如 `67.8%`），电压 2 位小数（如 `7.24 V`）；未收到 DAT 时显示 `—`。

轮转速 → 线速度（App）：`v = rps × π × D`，`D = 0.068 m`（轮胎直径 6.8 cm，App 常量 `WHEEL_DIAMETER_M`）；
取左右轮平均 `(left + right) / 2` 代入，显示保留 2 位小数，示例 `2.50 r/s` ≈ `0.534 m/s`。换轮胎只改 App 常量。

## 13. LOG 日志

| 项 | 值 |
| --- | --- |
| KIND | `01`（二进制），十进制 `1`；TYPE 基础值 `0x40` |
| TYPE 计算 | `0x40 \| KIND_TYPE` |
| SEQ 范围 | `0~255` |
| 方向 | **小车 → App（单向，强制）**；App 永不发 LOG |
| 是否需要 ACK | 否 |
| 是否判重 | **是**：App 维护最近 64 条已处理 SEQ，命中重复直接丢弃 |
| 产生方 | **仅小车**；App 绝不本地生成日志 |

### 13.1 KIND_TYPE 表（已实现 5 项）

| 编号 | 名称 | TYPE | PAYLOAD | 说明 |
| --- | --- | --- | --- | --- |
| **0** | `LOG_DEBUG` | `0x40` | UTF-8 文本 | 调试打印，开发时用 |
| **1** | `LOG_INFO` | `0x41` | UTF-8 文本 | 普通运行信息（如「蓝牙已连接」「运动命令已执行」） |
| **2** | `LOG_WARN` | `0x42` | UTF-8 文本 | 警告（如「低电量」「电机堵转但未触发保护」） |
| **3** | `LOG_ERROR` | `0x43` | UTF-8 文本 | 错误（如「BLE 断线重连失败」「写入 Flash 失败」） |
| **4** | `LOG_FATAL` | `0x44` | UTF-8 文本 | 严重故障（如「看门狗复位」「核心驱动异常」） |

### 13.2 PAYLOAD 文本规则

| 项 | 约定 |
| --- | --- |
| 编码 | UTF-8 文本 |
| 长度 | `LEN` 为字节数，不是字符数 |
| 结束符 | 无，不使用 `\0` 或换行 |
| 单帧上限 | `LEN ≤ 255`；BLE 传输层建议 ≤ 128 |
| 超长处理 | 固件自行截断并追加 `...`，或拆成多条日志；协议层不做分片 |

### 13.3 LOG 规则

1. 单向上报，无 ACK、无重发；App 收到即展示。
2. `SEQ` 由板子独立计数，范围 `0~255`（与 CMD、DAT 分开）；板子上电 / 复位时归零，断线重连不清空板子自己的计数器。
3. LOG 维护最近 64 条 SEQ：App 按接收顺序保留最近 64 条已处理 SEQ（FIFO 淘汰），命中重复直接丢弃；
   窗口只在 `resetDone=1` 或 App 进程重启时清空，普通断连保留。
4. 固件必须限速，避免占满 BLE 通知缓冲；溢出的日志本地丢弃，不阻塞控制命令。
5. 串口可继续输出纯文本；BLE 日志必须按本文件组帧。
6. LOG 是诊断用，不保证可靠送达——高价值的状态确认应该用 DAT。
7. 日志只能由板子产生。App 侧事件（连接成功 / 断开、发送命令、握手结果、ACK 失败）一律不写日志表，
   只做界面提示（Toast / Snackbar）；App 的定位是「用手机查看小车串口」的显示端。
8. 首次连接与重连必须由板子主动推送：
   - 首次连接：`CMD_SESSION_INIT` 握手成功后，板子立即推送当前运行日志；
   - 断线重连：链路恢复后，板子先**补推断线期间缓存的历史日志**，再恢复实时推送；
   - 推送多少、补多久由固件决定（建议环形缓冲区内全补）；协议层不做分片，App 不发「请求历史日志」。
9. LOG 只能 小车 → App；小车收到 LOG 帧一律静默丢弃、不写日志表、不回任何帧。
10. 日志不代表命令：小车不得用 LOG 表达「请求 App 做事」，需要动作只能发 `DAT_REQ`。

## 废弃原因

V1.9 的帧格式（`HEAD/SEQ/TYPE/LEN/PAYLOAD/CRC8`，TYPE = KIND(2 bit) + KIND_TYPE(6 bit)）在 V2.0 被整体替换：

1. **帧里的 `LEN` 字节是冗余的。** PAYLOAD 长度完全由 TYPE 的静态表决定，每个类型都是定长；再传一个 `LEN` 只是重复表达同一件事，
   还给了发送方「长度可以自由变」的错觉，接收方也必须额外做长度校验。V2.0 直接取消 `LEN`，帧长由 TYPE 查表得出。
2. **旧 TYPE 只有 6 bit KIND_TYPE，无法同时表达「分区 + 条目 + 等级」。** 每个 KIND 只有 64 个扁平编号，语义层级只能靠编号顺序约定；
   结果是 ACK 必须按命令逐条复制一份 KIND_TYPE（新增一条命令就要新增一个 ACK 编号），LOG 的 5 个等级
   （DEBUG / INFO / WARN / ERROR / FATAL）也塞不进 4 个分区的划分里。V2.0 改为 KIND + 分区 + 条目的三段布局，
   ACK 收敛为少数通用类型，LOG 等级落到分区维度。
3. **LOG 携带 UTF-8 文本，代价过高。** 每条日志都要在固件里做 `String` 格式化，配合按 64 条容量设计的回填环形区，
   等于要维护 64 份大文本缓冲，并在补推时把文本再复制进环形区；既浪费 RAM，也把 BLE 带宽耗在人读字符串上。
   V2.0 改为纯码点定长帧，板端只存码，文本由 App 侧渲染。
4. **`DAT_INFO` 把三个子类型塞进同一个 TYPE，且长度各不相同。** 同一个 `0x8A` 对应 21 / 6 / 7 三种 `LEN`，必须先读 `PAYLOAD[0]`
   才知道该按哪种长度解析，导致「一个 TYPE 对应一个固定长度」的静态表根本无法建立，解析路径被迫分成两段。
   V2.0 把三个子帧拆成三个独立 TYPE，每个 TYPE 长度唯一。
5. **文本载荷长度可变，解析只能信任 `LEN`，抗损坏能力差。** 一旦 `LEN` 被干扰、截断或错位，接收方要么少读、要么越界等待，
   只能靠 CRC 与超时兜底；在 BLE 20 字节分片、跨包重组的场景下尤其脆弱。V2.0 的定长表让每帧长度先验可知，
   错位能在帧头阶段立即被发现并丢弃，不必依赖载荷内的长度字段。
