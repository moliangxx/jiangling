## 1. 适用范围与角色

- 适用端：ESP32-S3 小车（BLE Peripheral） ↔ Android App（BLE Central）。
- **小车是唯一数据源，App 是唯一命令源**：小车推 `LOG`/`DAT`，App 发 `CMD`，小车只对 `CMD` 回 `ACK`。
- 应用层与传输介质无关；当前使用 BLE NUS。
- 当前固件的真实硬件状态：无电机驱动、无云台、无超声波、无轮速传感器；运动/云台命令只更新本地目标变量并回 ACK，`DAT_US`/`DAT_WHEEL` 编码已实现但**不上报**。

## 2. BLE 连接信息

| 项 | 值 |
| --- | --- |
| 蓝牙名称 | `JiangLing` |
| 服务 | Nordic UART Service（NUS） |
| 服务 UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX 特征（App 写入） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，`WRITE` + `WRITE_NR` |
| TX 特征（App 订阅） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`，`NOTIFY` + `READ` |
| 协议版本字段 | `PROTOCOL_VERSION = 20`（十进制；即文档 V2.0） |
| 固件版本 | `FW_MAJOR=1`、`FW_MINOR=10`、`FW_PATCH=0` |

传输约定：BLE 是字节流，**不能**假设一次写入或一次通知等于一帧。单次通知按 20 字节分块发送；
默认 MTU 23 时 App 单次写入最多 20 字节，建议协商 MTU 247。CMD 用带响应写入，LOG/DAT/ACK 为通知。

## 3. 帧格式

```text
[HEAD 1B] [SEQ 1B] [TYPE 1B] [PAYLOAD nB] [CRC8 1B]
```

| 字段 | 位宽 | 说明 |
| --- | --- | --- |
| `HEAD` | 8 bit（1 B） | 固定 `0xAA` |
| `SEQ` | 8 bit（1 B） | CMD：`1~255`，`0` 专用于 `CMD_SESSION_INIT`；ACK/LOG/DAT：`0~255` |
| `TYPE` | 8 bit（1 B） | 见第 4 节；高 2 bit = `KIND`，中间 2 bit = 分区 `ZONE`，低 4 bit = `ITEM` |
| `PAYLOAD` | n × 8 bit（n B） | 长度由第 5 节静态表决定；**没有 LEN 字节**；n 可以为 0 |
| `CRC8` | 8 bit（1 B） | CRC-8/ATM，多项式 `0x07`、初值 `0x00`、不反转、无输出异或；覆盖 `HEAD` 到最后一个 PAYLOAD 字节 |

- **协议所有字段以字节为最小单位，1 B = 8 bit，不存在半字节字段**：任何字段都从字节边界开始、占整数个字节；
  `PAYLOAD` 里即使只有一个布尔量，也占满 1 B（`0x00`/`0x01`），不会压成 1 bit。
- **帧总长 = 3 + PAYLOAD 长度 + 1**，例：`CMD_STOP` 为 `3+0+1=4` 字节；`DAT_MEM` 为 `3+16+1=20` 字节。
- 所有多字节数值**一律大端**（高字节在前）。
- 固件接收上限 128 字节；超过表内长度的帧不存在。
- 两端必须硬编码同一张 `TYPE → 长度` 表；表中没有的 `TYPE` 视为未知。

## 4. TYPE 三段布局

```text
bit7-6  KIND   00=ACK  01=LOG  10=DAT  11=CMD
bit5-4  ZONE   同一 KIND 下的 4 个子域
bit3-0  ITEM   子域内具体类型 0~15
```

`TYPE = (KIND << 6) | (ZONE << 4) | ITEM`。

| KIND | 值 | 分区 | 名称 | 说明 |
| --- | --- | --- | --- | --- |
| ACK | 0 | 0 | 确认结果 | `ACK_RESULT`、`ACK_SESSION_INIT` |
| | | 1 | 错误码 | `ACK_ERROR`（已定义，固件不发送） |
| | | 2/3 | 预留 | — |
| LOG | 1 | 0 | 等级 D | 固件的 `Info` 并入 D |
| | | 1 | 等级 E | 固件的 `Fatal` 并入 E |
| | | 2 | 等级 W | — |
| | | 3 | 预留 | — |
| DAT | 2 | 0 | 状态上报 | 电压/距离/轮速/静态信息 |
| | | 1 | 内存/统计 | `DAT_MEM` |
| | | 2 | 请求与应答 | `DAT_REQ` |
| | | 3 | 预留 | — |
| CMD | 3 | 0 | 系统/信息 | 握手、查重、补拉信息 |
| | | 1 | 音频 | 自检、音量、录音 |
| | | 2 | 动作/运动 | 停止、前后左右、云台、横移 |
| | | 3 | 预留 | — |

### 4.1 TYPE 的读法：整字节查表，位段只是编号规则

- **`TYPE` 是一个完整的 8 位字节，本身承载语义。** `KIND(2) + ZONE(2) + ITEM(4)` 只是**编号分配规则**，
  用来在 256 个值里划分归属、留出扩展位；它**不是**把字节拆成 4 段分别存储或分别传输，帧里永远是 1 个字节。
- **实现上按整字节查表**：两端硬编码同一张 `TYPE(0x00~0xFF) → 名称 / PAYLOAD 长度 / 处理分支` 表。
  `0xC0` 就是 `0xC0`，收到后直接查表得到“`CMD_SESSION_INIT`、长度 1、进命令分支”，不需要先做位移才知道类型。
- 位运算只在三处做**粗筛**，都属于允许用法：
  1. **方向校验**：`kind = type >> 6`，只有 `kind == CMD` 才进入命令处理，其余整帧静默丢弃；
  2. **LOG 特例**：`kind == LOG` 时帧长固定 19 字节，不查长度表；
  3. **文档/调试展示**：把 `0xD1` 显示成 `CMD / 音频 / 1`，仅供人读，不参与判定。
- **结论：精确判定靠整字节查表，粗分类才用 KIND 两位。** 同一张表里不要再为“位段”另建一套映射，
  否则等于维护两份真源，迟早不一致。

## 6. 方向约束

| 帧 | 允许方向 | 违规处理 |
| --- | --- | --- |
| `CMD` | App → 车 | 车端不做反向发送 |
| `ACK` | 车 → App | 车端收到 App 的 ACK 静默丢弃 |
| `LOG` | 车 → App | 车端收到 App 的 LOG 静默丢弃 |
| `DAT` | 车 → App | 车端收到 App 的 DAT 静默丢弃 |

- 只有**非法/未实现的 CMD 回错误 ACK** 这一个例外。
- 车端收到非 `CMD` 帧：整帧静默丢弃，不回复、不记日志。
- 车端永不主动发 `CMD`；需要 App 做事时发 `DAT_REQ`。

## 7. 接收解析流程

1. 字节追加到 512 B 接收缓冲。
2. 扫描 `0xAA`，丢弃其前面的字节。
3. 不足 3 字节（`HEAD+SEQ+TYPE`）时等待；半帧超过 1 s 丢弃帧头并继续扫描。
4. 读 `TYPE`：
   - `KIND=LOG` → 帧长固定 19；
   - 否则查长度表：未登记 → **整帧丢弃并重扫 `0xAA`**；已登记 → 帧长 `3+长度+1`。
5. 字节不足整帧长度时等待；CRC8 失败 → 丢弃 1 个字节重扫，不回复、不记日志。
6. CRC 通过后按 `KIND` 分流：`CMD` 进入命令处理；`LOG`/`DAT`/`ACK` 整帧消费并静默丢弃。

## 8. SEQ 与去重

| 通道 | SEQ 规则 | 去重 |
| --- | --- | --- |
| CMD | App 分配 `1~255`，`0` 专用于 `CMD_SESSION_INIT` | 车端保留最近 **64** 条；重复 CMD 回 `ACK_ST_DONE` 且不重复执行；`SEQ=0` 的非初始化命令回 `ACK_ST_ERROR` |
| ACK | 与被应答 CMD 的 SEQ 相同 | App 侧按需处理 |
| LOG | 车端帧序号，上电归零、断连重连**不**重置 | App 侧按 SEQ 去重 |
| DAT | 车端帧序号，上电归零、断连重连**不**重置 | App 侧按 SEQ 去重 |

- 不自动重发、不自动重查；重复命令由去重窗口吞掉。
- `CMD_QUERY_SEQ` 只查 CMD 的 64 条窗口。
- 握手的 `resetDone=1` 表示车端清空了 CMD 去重表；LOG/DAT 的 SEQ 计数器不受握手影响。

## 9. 数值、单位与书写约定

- **参数、状态码、请求码、长度、模块号、等级、SEQ 一律用十进制书写**；只有 `TYPE`、帧头、原始字节序列用**十六进制**。
- 定点数：电压 `u16`，单位 `0.01 V`；轮速 `int16`，单位 `0.01 r/s`；轮径 `u16`，单位 `mm`。
- 无效值：`u16` 用 `0xFFFF`；`int16` 用 `0xFFFF`（即有符号 `-1`）。
- 固件只上报原始量：**不换算 m/s、不报速度百分比、不计算电量百分比**。
- 参数越界一律由固件明确回错误码，不静默裁剪、不静默丢弃（具体见 [CMD.md](./CMD.md)）。
- **十进制参数按整字节写入**：取值范围 `0~255`，一个参数恒占 1 B（8 bit）。例：十进制 `10` 写成 `0x0A` = `0000 1010`，
  高 4 位补 0；不存在只发半字节（4 bit）的情况，`0x0A` 与 `0x0A00` 也不是一回事。
