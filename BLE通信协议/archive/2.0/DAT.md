> **项目唯一标准来源：`d:\Esp32Project`。** 本项目所有文档以 `d:\Esp32Project\index` 下的内容为准；
> `d:\AndroidProject\LingYuan\BLE通信协议\` 与固件目录下的协议文件都是**逐字副本**，冲突一律以 `index` 为准。
> 本文所列行为全部来自 `d:\Esp32Project\JiangLing_ai\src\communication\Protocol.h` 与 `BLE.cpp`
> 的 `sendDatIfDue()`、`sendDatMemIfDue()`、`sendDeviceInfoRound()`、`sendDatRequest()`。
> 数值书写约定：**字段值、长度、状态码一律十进制；只有 TYPE 与原始字节用十六进制。多字节数值一律大端。**

> `u32` 占 **4 B（32 bit）**，一律**大端**（高字节在前）；`16 B` 的型号字段为 16 × 8 bit；
> 协议不存在半字节字段。

## 1. 方向、节拍与去重

| 项 | 规则 |
| --- | --- |
| 方向 | **只允许 车 → App**；车端收到 DAT 帧静默丢弃 |
| 帧格式 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN |
| SEQ | 全部 DAT 帧共用**一个** 8 位计数器：每发一帧 +1，255 后回绕到 0；**握手与断连重连都不重置** |
| 去重 | App 侧按 SEQ 去重（建议保留最近 64 条）；车端不重发、不补帧 |
| 发送前提 | 已连接 **且** 已完成 `CMD_SESSION_INIT`；未握手时车端不发任何 DAT |
| 分片 | 每 20 字节一个 notify；`DAT_INFO_VERSION` 24 字节会拆成 20 + 4 两片 |

| TYPE | 名称 | 多发 / 单发 | 周期或触发 | 仅握手时上报 |
| --- | --- | --- | --- | --- |
| `0x80` | `DAT_BAT` | 多发 | 每 **500 ms** | 否 |
| `0x81` | `DAT_US` | 单发 | **无调用点**，当前不上报 | — |
| `0x82` | `DAT_WHEEL` | 单发 | **无调用点**，当前不上报 | — |
| `0x83` | `DAT_INFO_VERSION` | 单发（成组 3 帧） | 握手成功后一轮 + `CMD_REQ_INFO` 后一轮 | 否（也响应补拉） |
| `0x84` | `DAT_INFO_POWER` | 单发（成组 3 帧） | 同上，紧跟 `0x83` | 否 |
| `0x85` | `DAT_INFO_STORAGE` | 单发（成组 3 帧） | 同上，紧跟 `0x84` | 否 |
| `0x90` | `DAT_MEM` | 多发 | 每 **1000 ms** | 否 |
| `0xA0` | `DAT_REQ` | 单发 | 板端需要 App 做事时（当前只有“请求录音”） | 否 |

- `DAT_BAT` 与 `DAT_MEM` 是两个独立节拍，相位不对齐；两者共用 SEQ 计数器，所以正常情况下每秒约 +3。
- `DAT_INFO` 三帧一轮、连续发出，SEQ 取连续三个值；**不做周期重发**，App 漏收只能用 `CMD_REQ_INFO` 补拉。

## 2. 状态上报分区

`KIND = 2 (DAT)`、`分区 = 0`、`类型 = item`。

### 2.1 `DAT_BAT` — TYPE `0x80`

| 项 | 值 |
| --- | --- |
| TYPE | `0x80` = DAT(2) \| 分区 0 \| 类型 0 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 2 |
| 帧总长 | 6 |
| 多发/单发 | **多发**，500 ms |
| 去重 | App 按 SEQ |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `voltage` | u16 大端 | 0.01 V | 0~65534 | `0xFFFF` = 电压无效 |

- **只报原始电压**，不报电量百分比：百分比由 App 用 `DAT_INFO_POWER` 的电芯数与化学体系自行换算。
- 当前固件为**固定模拟值** `680`（即 6.80 V），没有 ADC 采样；数值不会随电量变化。
- 帧内无状态位、无充电标志。

**校验 / 参数**：无（车端只发不收）。

**ACK 行为**：不需要，App **不得**对 DAT 回 ACK。

**触发时机**：`update()` 中每 500 ms 一次，前提是已连接且已握手；未握手期间不累计、不补发。

**完整示例**

```text
AA 00 80 02 A8 5E
 |  |  |  |  |  └ CRC8 = 5E
 |  |  |  |  └ 0x02A8 = 680 → 6.80 V
 |  |  |  └ DAT_BAT
 |  |  └ SEQ = 0
 |  └ HEAD
 └ （注：首字节 AA 在前，此处对齐仅为阅读方便）
```

无效值示例：`AA 00 80 FF FF 01`。

### 2.2 `DAT_US 0x81`（不上报）

| 项 | 值 |
| --- | --- |
| TYPE | `0x81` = DAT(2) \| 分区 0 \| 类型 1 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 2 |
| 帧总长 | 6 |
| 当前状态 | **编码已实现，固件不上报**（无超声波传感器，`sendDatUs` 无调用点） |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `distance` | u16 大端 | 厘米 | 0~65534 | `0xFFFF` = 距离无效 |

- App 解析器应保留该 TYPE 的帧长（2），收到时按距离处理；但不要把“没收到”当成故障。
- 示例（仅格式，固件不产生）：`AA 07 81 00 64 17`（100 cm）。

### 2.3 `DAT_WHEEL 0x82`（不上报）

| 项 | 值 |
| --- | --- |
| TYPE | `0x82` = DAT(2) \| 分区 0 \| 类型 2 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 4 |
| 帧总长 | 8 |
| 当前状态 | **编码已实现，固件不上报**（无轮速传感器；`sendDatWheel()` 只被定义、无周期调用） |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `leftRps` | int16 大端 | 0.01 r/s | −32768~32767 | `0xFFFF`（−1）视为该轮无效 |
| 2~3 | `rightRps` | int16 大端 | 0.01 r/s | −32768~32767 | 同上 |

- **只报轮转速**，不换算 m/s、不报速度百分比；换线速度请用 `DAT_INFO_POWER` 的轮径（mm）。
- 左右独立无效：一侧无效不影响另一侧。
- 示例（仅格式，固件不产生）：`AA 06 82 01 F4 FF FF 28`（左 5.00 r/s，右无效）。

### 2.4 `DAT_INFO_VERSION` — TYPE `0x83`

| 项 | 值 |
| --- | --- |
| TYPE | `0x83` = DAT(2) \| 分区 0 \| 类型 3 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 20 |
| 帧总长 | 24（20 B 分片 + 4 B 分片） |
| 多发/单发 | **单发**，握手后一轮、`CMD_REQ_INFO` 后一轮 |
| 仅握手时上报 | 否（`CMD_REQ_INFO` 可补拉） |
| 去重 | App 按 SEQ |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 当前值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0 | `fwMajor` | u8 | — | `1` | 固件主版本 |
| 1 | `fwMinor` | u8 | — | `10` | 固件次版本 |
| 2 | `fwPatch` | u8 | — | `0` | 固件补丁号 |
| 3 | `protocol` | u8 | — | `20` | **等于 `PROTOCOL_VERSION`**，即本文档的 V2.0 |
| 4~19 | `model` | 16 B ASCII | — | `JiangLing-AI`（11 B）+ 5 B `0x00` | **固定 16 字节、右补 `0x00`**，不得含中文、不截断 |

- 型号字段整体 16 字节（偏移 4~19），不是变长；App 必须按“遇到 `0x00` 截止”解析，再补空。
- 三帧一轮的发送顺序固定：`0x83 → 0x84 → 0x85`；任一帧发送失败会中止本轮（后续帧不发）。

**完整示例**

```text
AA 01 83 01 0A 00 14 4C 69 6E 67 59 75 61 6E 2D 41 49 00 00 00 00 00 60
 |  |  |  |  |  |  |  └ "JiangLing-AI"（4C…49），随后 5 个 00
 |  |  |  |  |  |  └ protocol = 20
 |  |  |  |  |  └ patch = 0
 |  |  |  |  └ minor = 10
 |  |  |  └ major = 1
 |  |  └ DAT_INFO_VERSION
 |  └ SEQ = 1
 └ HEAD
（末尾 60 为 CRC8）
```

| 方向 | 车 → App |


## 3. 统计分区 `DAT_MEM 0x90`

| 项 | 值 |
| --- | --- |
| TYPE | `0x90` = DAT(2) \| 分区 1 \| 类型 0 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 16 |
| 帧总长 | 20（正好一个 notify 分片） |
| 多发/单发 | **多发**，1000 ms |
| 仅握手时上报 | 否 |
| 去重 | App 按 SEQ |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `ramFree` | u16 大端 | KB | 0~65534 | `0xFFFF` 保留，实际不出现 |
| 2~3 | `psramFree` | u16 大端 | KB | 0~65534 | `0xFFFF` = 无 PSRAM |
| 4~5 | `ramMinFree` | u16 大端 | KB | 0~65534 | 上电以来内部 RAM 最低空闲 |
| 6~7 | `psramMinFree` | u16 大端 | KB | 0~65534 | `0xFFFF` = 无 PSRAM |
| 8~9 | `uptimeHigh` | u16 大端 | — | — | 运行秒数的高 16 位 |
| 10~11 | `uptimeLow` | u16 大端 | — | — | 运行秒数的低 16 位 |
| 12 | `logPending` | u8 | 条 | 0~255 | `255` = 队列已满/饱和（真实值更大） |
| 13 | `logQueueDepth` | u8 | — | 固定 `255` | `255` = **该字段恒无效**（DAT 通道无发送队列） |
| 14~15 | `logDropped` | u16 大端 | 条 | 0~65534 | `65534` = 饱和（真实值更大）；`0xFFFF` 不会出现 |

- **运行秒数由两个 u16 拼成**：`uptime = (uptimeHigh << 16) | uptimeLow`，不是“高/低各一半的独立量”。
- 容量换算：字节 / 1024 取整后写入；超过 65534 KB 一律写 `65534`（保留 `65535` 给“无效”）。
- `logPending` 是 `Logger` 中待出队的条数（不含断连补发环），饱和写 `255`。
- `logDropped` 是队列满时丢弃的累计条数（上电后累计），饱和写 `65534`。
- 字节 13 在设计上留给“DAT 通道队列水位”，本固件该通道没有软件队列，**值恒为 `0xFF`**，App 应显示“无效”而不是 255 条。

**触发时机**：独立 1000 ms 节拍，与 `DAT_BAT` 的 500 ms 节拍互不影响；均要求已连接且已握手。

**完整示例**（RAM 256 KB、PSRAM 4096 KB、RAM 最低 160 KB、PSRAM 最低 128 KB、运行 0 s、待发 4 条、丢 3 条）

```text
AA 04 90 01 00 10 00 00 A0 00 80 00 00 00 00 04 FF 00 03 B6
 |  |  |  └ … 16 字节 PAYLOAD …                              └ CRC8 = B6
 |  |  └ DAT_MEM
 |  └ SEQ = 4
 └ HEAD
```

## 4. 请求分区 `DAT_REQ 0xA0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xA0` = DAT(2) \| 分区 2 \| 类型 0 |
| 方向 | **车 → App**（板端请求 App 执行动作；车端永不发 CMD） |
| PAYLOAD 长度 | 2 |
| 帧总长 | 6 |
| 多发/单发 | **单发**，事件驱动 |
| 需已握手 | **是**（未连接或未握手直接拒绝，不发帧） |
| 去重 | App 按 SEQ |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `code` | u8 | — | 1~10，见下表 | 0 或 > 10：车端拒绝整条请求，**不发帧** |
| 1 | `param` | u8 | — | 含义随 `code` | 见下表；越界由车端**静默裁剪**（这是全协议唯一的裁剪点） |

| `code` | 含义 | `param` 语义 | 车端处理 |
| --- | --- | --- | --- |
| 1 | 请求停车 | 无 | 强制置 `0` |
| 2 | **请求录音** | 无 | 强制置 `0` |
| 3 | 请求左横移 | 等级 0~100 | `> 100` 裁到 `100` |
| 4 | 请求右横移 | 等级 0~100 | `> 100` 裁到 `100` |
| 5 | 请求云台俯仰 | 角度 0~255 | 不裁剪 |
| 6 | 请求云台偏航 | 角度 0~255 | 不裁剪 |
| 7 | 请求前进 | 等级 0~100 | `> 100` 裁到 `100` |
| 8 | 请求后退 | 等级 0~100 | `> 100` 裁到 `100` |
| 9 | 请求左转 | 等级 0~100 | `> 100` 裁到 `100` |
| 10 | 请求右转 | 等级 0~100 | `> 100` 裁到 `100` |

**当前实际发送情况**

- 固件只有 `requestRecording()` 一个调用点，它固定发 `code = 2`、`param = 0`。
- 其余 `code` 有编码与裁剪路径，但**当前没有调用点**，属于“协议已定义、固件暂不产生”。
- `code = 3/4`（横移）即使 App 收到，映射回 CMD 后也只会得到 `ACK_ST_UNKNOWN(4)`，因为本车是差速轮。

**App 应如何响应**

1. 按 `code` 映射成对应 CMD（`2 → CMD_RECORD 0xD2`，参数按 App 的录音秒数策略决定；`1 → CMD_STOP` 等）。
2. 用**新的 SEQ** 发送该 CMD，并等待 `ACK_RESULT`。
3. 不对 `DAT_REQ` 本身回 ACK（ACK 只对应 CMD）。

**拒绝路径（不发帧，只写 W 日志）**

| 条件 | 日志 |
| --- | --- |
| 未连接 / 未握手 / TX 特征不可用 | `W/DAT 事件码 2` |
| `code` 不在 1~10 | `W/DAT 事件码 3` |

**完整示例**（请求录音）

```text
AA 05 A0 02 00 02
 |  |  |  |  |  └ CRC8 = 02
 |  |  |  |  └ param = 0
 |  |  |  └ code = 2（请求录音）
 |  |  └ DAT_REQ
 |  └ SEQ = 5
 └ HEAD
```

其他请求码示例（仅格式，当前无调用点）：

```text
AA 05 A0 03 32 89   ← code = 3（左横移），param = 50
```

## 5. 数值与无效值约定

| 约定 | 内容 |
| --- | --- |
| 大小端 | 所有 u16/int16 **一律大端**（高字节在前） |
| 定点数 | 电压 `0.01 V`；轮速 `0.01 r/s`；轮径 `mm`；距离 `cm` |
| 无符号无效值 | `0xFFFF`（65535） |
| 有符号无效值 | `0xFFFF`（即 `-1`） |
| 饱和值 | 内存与计数类字段饱和到 `65534` / `254`，保留 `65535` / `255` 给无效 |
| 百分比 | 全部 0~100 整数，不出现小数 |
| 单位换算 | 固件只发原始量，换算与显示全部由 App 完成 |

## 6. 完整帧示例

```text
DAT_BAT（6.80 V）：        AA 00 80 02 A8 5E
DAT_BAT（电压无效）：      AA 00 80 FF FF 01
DAT_INFO_VERSION：         AA 01 83 01 0A 00 14 4C 69 6E 67 59 75 61 6E 2D 41 49 00 00 00 00 00 60
DAT_INFO_POWER：           AA 02 84 02 00 00 44 64 6E
DAT_INFO_STORAGE：         AA 03 85 00 10 20 00 00 04 FF
DAT_MEM：                  AA 04 90 01 00 10 00 00 A0 00 80 00 00 00 00 04 FF 00 03 B6
DAT_REQ（请求录音）：      AA 05 A0 02 00 02
```

以上 SEQ 均为示例值；实际 SEQ 为车端递增计数，App 应以帧内 SEQ 为准。
CRC8 为 CRC-8/ATM（`0x07` 多项式、初值 `0x00`），覆盖 `AA` 到最后一个 PAYLOAD 字节。
