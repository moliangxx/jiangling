## 2. 连接与传输

### 2.1 BLE 连接信息

| 项 | 值 |
| --- | --- |
| 蓝牙名称 | `JiangLing` |
| 服务 | Nordic UART Service（NUS） |
| 服务 UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX 特征（App 写入） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，`WRITE` + `WRITE_NR` |
| TX 特征（App 订阅） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`，`NOTIFY` + `READ` |
| CCCD UUID | `00002902-0000-1000-8000-00805F9B34FB` |
| 默认 MTU | 23（单次特征值最多 20 字节） |
| 建议协商 MTU | 247 |
| 扫描超时（App 约定） | 15 秒 |

### 2.2 传输约定

1. BLE 是**字节流**，不能假设一次写入 / 一次通知等于一帧；接收方必须跨多次写入 / 通知重组。
2. 单次通知按 **20 字节**分块发送；`DAT_INFO_VERSION` 帧 24 字节会拆成 20 + 4 两片。
3. `CMD` 使用带响应写入（Write With Response）；`ACK` / `LOG` / `DAT` 为板子单向通知。
4. `PAYLOAD` 内多字节数值一律**大端序**（高字节在前）；文本使用 ASCII / UTF-8，不带 `\0` 结尾。
5. 协议所有字段以字节为最小单位，**1 B = 8 bit**，不存在半字节字段。
6. 固件接收上限 **128 字节**；超过长度表所登记长度的帧不存在。

### 2.3 连接、握手与断连

- 每次传输层连接建立后，App 发送的第一帧必须是 `CMD_SESSION_INIT`（`SEQ = 0`）。
- 握手成功后，小车紧接着发一轮 `DAT_INFO_VERSION → DAT_INFO_POWER → DAT_INFO_STORAGE`（顺序固定）。
- 断连后车端立即把会话置为未初始化；App 重连后必须重新握手。
- 握手不影响 `LOG` / `DAT` 的 SEQ 计数器；它们上电归零后一直递增，断连重连**不**重置。

## 3. 帧格式与 CRC

### 3.1 帧结构

```text
普通帧：[HEAD] [SEQ] [TYPE] [PAYLOAD] [CRC8]
         1B     1B    1B     nB        1B

LOG 帧：[HEAD] [SEQ] [TYPE0][param0] … [TYPE7][param7] [CRC8]
         1B     1B       8 × 2B = 16B                   1B
```

| 字段 | 位宽 | 说明 |
| --- | --- | --- |
| `HEAD` | 8 bit（1 B） | 固定 `0xAA`，帧同步头 |
| `SEQ` | 8 bit（1 B） | CMD：`1~255`，`0` 专用于 `CMD_SESSION_INIT`；ACK / LOG / DAT：`0~255` |
| `TYPE` | 8 bit（1 B） | 高 2 bit = `KIND`，中间 2 bit = 分区 `ZONE`，低 4 bit = `ITEM` |
| `PAYLOAD` | n × 8 bit（n B） | 长度由第 5 节静态表决定；**没有 LEN 字节**；n 可以为 0 |
| `CRC8` | 8 bit（1 B） | CRC-8/ATM，覆盖 `HEAD` 到最后一个 `PAYLOAD` 字节 |

- **帧总长 = 3 + PAYLOAD 长度 + 1**。例：`CMD_STOP` 为 `3 + 0 + 1 = 4` 字节；`DAT_MEM` 为 `3 + 16 + 1 = 20` 字节。
- `PAYLOAD` 里即使只有一个布尔量，也占满 1 B（`0x00` / `0x01`），不会压成 1 bit。

### 3.2 CRC-8/ATM 参数

| 参数 | 值 |
| --- | --- |
| 多项式 | `0x07` |
| 初始值 | `0x00` |
| 输入反射 | 否 |
| 输出反射 | 否 |
| 结果异或 | `0x00` |
| 覆盖范围 | `HEAD + SEQ + TYPE + PAYLOAD`（不含 `CRC8` 本身） |
| 校验失败 | 整帧丢弃，不回复任何内容，不记日志 |

### 3.3 CRC 测试向量

| 输入（CRC 覆盖范围，十六进制） | CRC8 结果 |
| --- | --- |
| `31 32 33 34 35 36 37 38 39`（ASCII 字符串 `123456789`） | `F4` |
| `AA 00 C0 14`（`CMD_SESSION_INIT`，protocol = 20） | `E2` |
| `AA 00 01 03 01`（`ACK_SESSION_INIT[3, 1]`） | `7D` |
| `AA 00 01 05 00`（`ACK_SESSION_INIT[5, 0]`） | `04` |
| `AA 08 E1 5A`（`CMD_FORWARD`，level = 90） | `E5` |
| `AA 08 00 E1 01`（`ACK_RESULT[0xE1, 1]`） | `CF` |
| `AA 07 E0`（`CMD_STOP`，无 PAYLOAD） | `0A` |
| `AA 03 D0 00`（`CMD_AUDIO_TEST`，action = 0） | `64` |
| `AA 04 D1 64`（`CMD_VOLUME`，volume = 100） | `5C` |
| `AA 05 D2 05`（`CMD_RECORD`，seconds = 5） | `28` |
| `AA 01 C1 05`（`CMD_QUERY_SEQ`，targetSeq = 5） | `EB` |
| `AA 02 C2`（`CMD_REQ_INFO`，无 PAYLOAD） | `A5` |
| `AA 06 D3`（`CMD_REQ_RECORD`，无 PAYLOAD） | `86` |
| `AA 0C E5 5A`（`CMD_PITCH`，angle = 90） | `1A` |
| `AA 0D E6 2D`（`CMD_YAW`，angle = 45） | `0C` |

- 上表结果与 App 侧 `M.kt` 的 `crc8()` 及 V2.0 分册中的示例帧一致。
- 校验范围从 `0xAA` 起、到最后一个 `PAYLOAD` 字节止；帧的最后一个字节必须等于该结果。

## 4. TYPE 布局与容量

### 4.1 三段布局

```text
bit7-6  KIND   00=ACK  01=LOG  10=DAT  11=CMD
bit5-4  ZONE   同一 KIND 下的 4 个子域
bit3-0  ITEM   子域内具体类型 0~15
```

`TYPE = (KIND << 6) | (ZONE << 4) | ITEM`。

| KIND | 值 | 分区 | 名称 | 说明 |
| --- | --- | --- | --- | --- |
| ACK | 0 | 0 | 确认结果 | `ACK_RESULT`、`ACK_SESSION_INIT` |
| | | 1 | 错误码 | `ACK_ERROR`（已定义，固件不发送） |
| | | 2 / 3 | 预留 | — |
| LOG | 1 | 0 | 等级 D | 固件的 `Info` 并入 D |
| | | 1 | 等级 E | 固件的 `Fatal` 并入 E |
| | | 2 | 等级 W | — |
| | | 3 | 预留 | — |
| DAT | 2 | 0 | 状态上报 | 电压 / 距离 / 轮速 / 静态信息 |
| | | 1 | 内存 / 统计 | `DAT_MEM` |
| | | 2 | 请求与应答 | `DAT_REQ` |
| | | 3 | 预留 | — |
| CMD | 3 | 0 | 系统 / 信息 | 握手、查重、补拉信息 |
| | | 1 | 音频 | 自检、音量、录音 |
| | | 2 | 动作 / 运动 | 停止、前后左右、云台、横移 |
| | | 3 | 预留 | — |

### 4.2 TYPE 是整字节语义编号，位段只是编号规则

- **`TYPE` 是一个完整的 8 位字节，本身承载语义。** `KIND(2) + ZONE(2) + ITEM(4)` 只是**编号分配规则**，
  用来在 256 个值里划分归属、留出扩展位；它**不是**把字节拆成 4 段分别存储或分别传输，帧里永远是 1 个字节。
- **实现上按整字节查表**：两端硬编码同一张 `TYPE(0x00~0xFF) → 名称 / PAYLOAD 长度 / 处理分支` 表。
  `0xC0` 就是 `0xC0`，收到后直接查表得到“`CMD_SESSION_INIT`、长度 1、进命令分支”，不需要先做位移才知道类型。
- 位运算只在三处做**粗筛**，都属于允许用法：
  1. **方向校验**：`kind = type >> 6`，只有 `kind == CMD` 才进入命令处理，其余整帧静默丢弃；
  2. **LOG 特例**：`kind == LOG` 时帧长固定 19 字节，不查长度表；
  3. **文档 / 调试展示**：把 `0xD1` 显示成 `CMD / 音频 / 1`，仅供人读，不参与判定。
- **结论：精确判定靠整字节查表，粗分类才用 KIND 两位。** 同一张表里不要再为“位段”另建一套映射，
  否则等于维护两份真源，迟早不一致。

### 4.3 容量

| 项 | 值 |
| --- | --- |
| 全协议 TYPE 总数 | 256（`0x00`~`0xFF`） |
| 每个 KIND 的类型数 | 64（4 个分区 × 每分区 16 个类型） |
| 每分区类型数 | 16（`ITEM` 0~15） |
| 已登记 TYPE 数 | 27（ACK 3 + DAT 8 + CMD 16，另 LOG 以 19 B 帧单独处理） |
| `TYPE` 书写 | 十六进制（如 `0xC0`） |
| 参数 / 状态码 / 请求码 / 长度 / 模块号 / 等级 / SEQ | 十进制 |

### 5.2 LOG 是唯一例外

- `LOG` 帧第 3 字节是**第一条日志记录的 TYPE**，整帧固定 **19 字节** = `HEAD(1) + SEQ(1) + 8×2 + CRC8(1)`，不查上表。
- 该字节最高 2 bit 恒为 `01`，解析器据此把帧长定为 19；这是本协议唯一“帧长不查表”的例外。
- 长度表中未列出的 `TYPE` 一律未登记，收到即整帧丢弃。

### 5.3 未登记 TYPE

- 未登记 `TYPE` 在**解析阶段**就被整帧丢弃，**无任何 ACK**。
- App 不得把“未登记 TYPE 无响应”当成超时重试的依据；重发也同样没有响应，只能使用表内命令。

## 6. 方向约束

| 帧 | 允许方向 | 谁产生 | 接收方处理合法帧 | 收到反方向帧（非法） |
| --- | --- | --- | --- | --- |
| `CMD` | **App → 车** | **仅 App** | 车执行并回 `ACK`（64 条 SEQ 去重） | 车端不会发 CMD；App 若收到 CMD：不执行、不回帧，本地记录后丢弃 |
| `ACK` | **车 → App**（只回应 CMD） | **仅车** | App 按 `SEQ + PAYLOAD[0]` 对账 | 车端收到 App 的 ACK：整帧静默丢弃 |
| `LOG` | **车 → App** | **仅车** | App 按日志表展示（按 SEQ 去重） | 车端收到 App 的 LOG：整帧静默丢弃 |
| `DAT` | **车 → App** | **仅车** | App 解析 / 缓存（按 SEQ 去重） | 车端收到 App 的 DAT：整帧静默丢弃 |

强制约束：

1. **车端永不主动发 CMD**。需要 App 做事时只能发 `DAT_REQ`，由 App 映射成正常 CMD 发出。
2. **App 绝不发 LOG / DAT**；App 是纯显示端，日志与数据只能由车产生。
3. **ACK 只用于回应 CMD**；`DAT_REQ` 本身不回 ACK。
4. 车端收到非 `CMD` 帧：整帧静默丢弃，不回复、不记日志。
5. **唯一例外**：车端收到非法 / 未实现的 CMD 时回错误 `ACK`（`ACK_RESULT[TYPE, 4/5]`）。
6. App 收到 `CMD` 属方向非法：不执行、不建命令记录、不回帧（`ACK` 方向固定为车 → App），只在 App 本地调试记录中提示。

## 7. 接收解析与未知 TYPE

### 7.1 标准解析流程（车端）

1. 字节追加到接收缓冲区（固件 512 B；App 实现为 2048 B）。
2. 扫描帧头 `0xAA`，丢弃其前面的字节。
3. 不足 3 字节（`HEAD + SEQ + TYPE`）时等待；半帧超过 **1 s** 丢弃帧头并继续扫描。
4. 读 `TYPE`：
   - `KIND = LOG` → 帧长固定 19；
   - 否则查长度表：未登记 → **整帧丢弃并重扫 `0xAA`**；已登记 → 帧长 `3 + PAYLOAD 长度 + 1`。
5. 字节不足整帧长度时等待；`CRC8` 失败 → 丢弃 1 个字节重扫，不回复、不记日志。
6. CRC 通过后按 `KIND` 分流：
   - 车端：`CMD` 进入命令处理；`LOG` / `DAT` / `ACK` 整帧消费并静默丢弃。
   - App：`ACK` / `LOG` / `DAT` 进入业务处理；`CMD` 整帧丢弃并提示方向非法。

### 7.2 未知 TYPE 处理

- **不猜长度**：长度表查不到就整帧丢弃，从下一个字节重新扫描 `0xAA`。
- 未登记 TYPE 不产生任何应答，也不写日志（App 侧可本地提示“未知 TYPE，已丢弃并重新同步”）。
- 已登记但语义未实现的 `TYPE`（`0xD3` / `0xE7` / `0xE8`）仍按表内长度正常解析，进入命令分支后回 `ACK_RESULT[TYPE, 4]`。

### 7.3 缓冲区与超时

| 项 | 固件 | App |
| --- | --- | --- |
| 接收缓冲区 | 512 B | 2048 B |
| 半帧超时 | 1 s | 1 s |
| 缓冲区溢出 | 丢弃最旧字节 / 数据 | 丢弃前一半，保留最近一半继续解析 |
| CRC 失败 | 丢弃 1 字节重扫 | 丢弃 1 字节重扫 |
| 未知 TYPE | 整帧丢弃重扫 | 整帧丢弃、回调错误提示、重扫 |

### 7.4 LOG 帧解析

1. 读偏移 2 的字节，确认 `KIND = 该字节 >> 6 == 1`。
2. 固定取 19 字节整帧，校验 CRC。
3. 从偏移 2 起每 2 字节一条记录，共 8 条。
4. 跳过 `TYPE == 0x00` 且 `param == 0x00` 的空槽。
5. 按 `模块号 = TYPE & 0x0F`、`等级 = (TYPE >> 4) & 0x03`、`param` 查表显示。

## 8. SEQ 与去重

| 通道 | SEQ 范围 | 计数者 | 去重规则 |
| --- | --- | --- | --- |
| CMD | `1~255`；`0` 仅 `CMD_SESSION_INIT` | App | 车端保留最近 **64** 条；重复 CMD 回 `ACK_RESULT[TYPE, 3]`，不重复执行 |
| ACK | `0~255`；`ACK_SESSION_INIT` 恒为 0 | 无独立计数器 | 原样回显对应 CMD 的 `SEQ`；App 按需处理，不判重 |
| LOG | `0~255` | 车 | App 保留最近 **64** 条；命中重复直接丢弃 |
| DAT | `0~255` | 车 | App 保留最近 **64** 条；命中重复直接丢弃 |

规则：

1. CMD 序号 `1~255`，到 255 后回到 1；`0` 只用于 `CMD_SESSION_INIT`，不参与普通递增。
2. `SEQ = 0` 用在非 `CMD_SESSION_INIT` 的命令上 → 回 `ACK_RESULT[TYPE, 5]`，并记 `W/BLE 事件码 14`。
3. 车端每次上电 / 复位时，自己的 CMD / LOG / DAT 计数器归零；后台自动重连不清空。
4. 手动重发同一条命令时 `SEQ` 保持不变：车端未处理过就执行，处理过就按重复应答（只回 `ACK`、不重复执行）。
5. **CMD / LOG / DAT 各维护一份「最近 64 条 SEQ」列表**（接收方维护，FIFO 淘汰）：
   - CMD：车端维护；命中重复只回 `ACK_RESULT[TYPE, 3]`；
   - LOG / DAT：App 维护；命中重复直接丢弃，不重复写日志表 / 不重复更新状态；
   - 三份列表彼此独立。
6. 列表只在以下情况清空：
   - App 侧收到 `ACK_SESSION_INIT` 且 `resetDone = 1` 时，清空 LOG / DAT 两份窗口；
   - 车端收到生效的 `CMD_SESSION_INIT`（`SEQ = 0`）或自身复位时，清空 CMD 窗口。
7. 普通断连、后台自动重连、App 切前后台都**不清空**列表（断连保留才能挡住重连后的重发）。
8. `SEQ = 0`（初始化命令）不写入 CMD 去重列表；LOG / DAT 的 `SEQ = 0` 正常参与窗口。
9. `CMD_QUERY_SEQ` 与 `CMD_SESSION_INIT` **不做自身判重**；重复查询仍会应答，查询成功后会把本查询自身的 `SEQ` 记入窗口。
10. `CMD_QUERY_SEQ` 只查 CMD 的 64 条窗口，**查不到** LOG / DAT / ACK 的 SEQ。
11. 握手的 `resetDone = 1` 表示车端清空了 CMD 去重表；LOG / DAT 的 SEQ 计数器不受握手影响。
12. App 侧不自动重发、不自动重查；普通命令约 **4000 ms** 收不到 `ACK` 只判失败，由用户手动用同一 `SEQ` 重发或先发 `CMD_QUERY_SEQ` 确认。

## 9. 数值单位约定

### 9.1 书写约定

- **参数、状态码、请求码、长度、模块号、等级、SEQ 一律用十进制书写**；只有 `TYPE`、帧头、原始字节序列用**十六进制**。
- 一个 `u8` 参数占 **8 bit（1 B）**，取值范围 `0~255`；十进制 `10` 写成 `0x0A` = `0000 1010`（高 4 位补 0）。
- 不存在只发半字节（4 bit）的情况；`0x0A` 与 `0x0A00` 也不是一回事。

### 9.2 定点数、字节序与无效值

| 约定 | 内容 |
| --- | --- |
| 大小端 | 所有 `u16` / `int16` / `u32` **一律大端**（高字节在前） |
| 电压 | `u16`，单位 `0.01 V` |
| 轮速 | `int16`，单位 `0.01 r/s` |
| 轮径 | `u16`，单位 `mm` |
| 距离 | `u16`，单位 `cm` |
| 内存容量 | `u16`，单位 KB；Flash 容量用 MB |
| 无符号无效值 | `0xFFFF`（65535） |
| 有符号无效值 | `0xFFFF`（即 `-1`） |
| 饱和值 | 内存与计数类字段饱和到 `65534` / `254`，保留 `65535` / `255` 给无效 |
| 百分比 | 全部 `0~100` 整数，不出现小数 |

- 定点数为「放大后取整」再大端传输：`2.50 r/s` → `250` → 字节 `00 FA`。
- 无效值统一用**全 `0xFF` 的字段**；App 收到无效值时不更新该字段，界面显示 `—`，不得用 `0` 冒充。
- 固件只上报原始量：**不换算 m/s、不报速度百分比、不计算电量百分比**。

### 9.3 运动参数单位

| 参数 | 单位 | 范围 / 映射 |
| --- | --- | --- |
| 前进 / 后退 `level` | % | `0~100`，相对最大直线速度 |
| 左转 / 右转 `level` | % | `0~100`，相对最大回转角速度 |
| 横移 `level`（未实现） | % | `0~100`，相对最大横移速度 |
| `CMD_PITCH` `angle` | 原始角值 | `0~255` → App 侧显示 `raw × 180 / 255`（0°~180°） |
| `CMD_YAW` `angle` | 原始角值 | `0~255` → App 侧显示 `raw × 360 / 255`（0°~360°） |
| 音量 `volume` | % | `0~100`（0 = 静音，100 = 满量程） |
| 录音 `seconds` | 秒 | `1~10` |

- 挡位语义：`90` = 最大速度的 90%；`0` = 以 0 幅度执行，等效停止该动作。
- 固件按自己的标定表换算：目标轮转速 = `level × 500 / 100`（最大 5.00 r/s），目标 PWM = `level × 255 / 100`。
- 原地转弯不是半径转弯；带转弯半径的弧线行驶不在 V2.0 范围内。

### 9.4 数据责任与换算

> **小车只交原始量，所有换算统一放 App。** 换电池、换电芯串数、换轮径、换电机 → 只改 App 常量 / 曲线表。

| 量 | 产生方 | 原始编码 | App 计算 | 固件禁止 |
| --- | --- | --- | --- | --- |
| 电池电压 | 车（当前为固定模拟值） | `DAT_BAT` 的 `voltage`，u16 0.01 V | `电压V = raw / 100`，显示 2 位小数 | 不换算成电量、不上报百分比 |
| 电量百分比 | App | 协议不传 | 电压 → 曲线插值 | 固件不查表、不估算 |
| 轮转速 | 车（当前无传感器） | `DAT_WHEEL` 的左右 `int16`，0.01 r/s | `rps = raw / 100` | 不换算 m/s、不设轮径常量 |
| 线速度 | App | 协议不传 | `v = rps × π × D` | 不上报 m/s |
| 超声波距离 | 车（当前无传感器） | `DAT_US` 的 `distance`，u16 cm | 直接使用 | 不做单位变换 |
| 挡位 / 转弯幅度 | App（用户操作） | CMD 参数 u8 0~100 | 不做换算 | 按标定表转 PWM / 轮转速 |

电池电压 → 电量百分比（仅 App，分段线性插值；默认按 2S 锂离子，整组 6.00~8.40 V）：

| 电压（V） | 6.00 | 6.40 | 6.60 | 6.80 | 7.00 | 7.20 | 7.40 | 7.60 | 7.80 | 8.00 | 8.20 | 8.40 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 电量（%） | 0 | 3 | 6 | 12 | 22 | 35 | 50 | 65 | 78 | 88 | 95 | 100 |

```text
给定电压 v：
  v ≤ 6.00  → 0%
  v ≥ 8.40  → 100%
  否则找到相邻区间 [v0, v1]，按 p = p0 + (v - v0) / (v1 - v0) × (p1 - p0) 插值
```

- 曲线表放在 App 常量里，两张表必须等长、电压严格递增；固件永远只传电压。
- 显示：电量 1 位小数（如 `67.8%`），电压 2 位小数（如 `7.24 V`）；未收到 DAT 时显示 `—`。
- 轮转速 → 线速度（App）：`v = rps × π × D`，默认 `D = 0.068 m`（轮胎直径 6.8 cm，App 常量 `WHEEL_DIAMETER_M`）；
  取左右轮平均 `(left + right) / 2` 代入，显示保留 2 位小数。换轮胎只改 App 常量，或使用 `DAT_INFO_POWER` 的 `wheelDiameter`（mm）。

## 10. CMD 全表

### 10.1 通用规则

| 项 | 规则 |
| --- | --- |
| 方向 | **只允许 App → 车**；车端永不主动发 CMD |
| 帧格式 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，**无 LEN** |
| PAYLOAD 长度 | 由第 5 节 TYPE 静态表决定，两端硬编码同一张表 |
| 帧总长 | `3 + PAYLOAD 长度 + 1` |
| `SEQ` | App 分配 `1~255`；`0` 仅 `CMD_SESSION_INIT` |
| 判重 | 车端保留最近 64 条 CMD 的 `SEQ`；重复只回 `ACK`，不重复执行 |
| 应答 | 每条 CMD 都必须回 ACK；`CMD_SESSION_INIT` 用 `ACK_SESSION_INIT`，其余用 `ACK_RESULT` |

**车端 `processCmd()` 的判定顺序固定，前一步返回就不进入后续步骤：**

1. `TYPE == CMD_SESSION_INIT 0xC0` → 走握手分支，不再往下。
2. `SEQ == 0` → 回 `ACK_RESULT[TYPE, 5]`，记 `W/BLE 事件码 14`。
3. `TYPE == CMD_QUERY_SEQ 0xC1` → 走查重分支，不再往下。
4. 白名单判定：`0xD3`、`0xE7`、`0xE8` → 回 `ACK_RESULT[TYPE, 4]`；其他未登记 TYPE 在**解析阶段**就被整帧丢弃（**无任何应答**）。
5. 参数校验（音频动作 / 音量 / 录音秒数 / 运动等级），越界回 `ACK_RESULT[TYPE, 5]`。
6. 会话门控：未完成 `CMD_SESSION_INIT` 时，除 `CMD_STOP` 外一律回 `ACK_RESULT[TYPE, 6]`，记 `W/BLE 事件码 15`。
7. 判重：命中 64 条窗口 → 回 `ACK_RESULT[TYPE, 3]`，不执行。
8. 记入去重窗口、执行动作、回 `ACK_RESULT[TYPE, 最终状态]`。
9. 音频 / 录音动作在 **ACK 发出之后**才开始；最后把 `CMD <item> LEVEL=<value>` 或 `ANGLE=<value>` 画到屏幕。

> **注意：第 5 步在第 6 步之前。** 会话未建立时，一条参数非法的命令回的是 `5`（错误），不是 `6`（不能执行）。

### 10.3 `CMD_SESSION_INIT` — TYPE `0xC0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xC0` = CMD(3) << 6 \| 分区 0 << 4 \| 类型 0 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |
| SEQ | **必须为 0** |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `protocol` | u8（8 bit / 1 B） | — | 必须等于 `20` | 其他值视为版本不匹配 |

**校验**

- `SEQ != 0` → 回 `ACK_RESULT[0xC0, 5]`（ACK 的 `SEQ` 用该非法 `SEQ`），记 `W/BLE 事件码 14`，不建立会话。
- `protocol != 20` → 会话标记为未初始化，回 `ACK_SESSION_INIT[5, 0]`，记 `W/SYSTEM 事件码 6`；**不清空去重表**。
- `protocol == 20` → 成功。

**ACK 行为**

- 成功：`ACK_SESSION_INIT[3, resetDone]`，`SEQ = 0`。
- `resetDone = 1` 表示车端**清空了 64 条 CMD 去重表**；`resetDone = 0` 表示没有清空。
- `resetDone` 只在「上电 / 复位后还没成功执行过任何普通 CMD」时为 1（内部 `_isInit` 标志）；同一会话再次握手一律为 0。
- 握手**不影响** LOG / DAT 的 SEQ 计数器，它们不归零。

**触发时机**

- 连接建立后 App 必须先发这一条，之后才能发其他命令（`CMD_STOP` 除外）。
- 成功后车端**立即**连发一轮 `DAT_INFO_VERSION → DAT_INFO_POWER → DAT_INFO_STORAGE`，不等待 App 回应。
- 断连后车端把会话置为未初始化，重连需重新握手。

```text
AA 00 C0 14 E2
 |  |  |  |  └ CRC8 = E2（覆盖 AA 00 C0 14）
 |  |  |  └ 协议版本 = 20
 |  |  └ CMD_SESSION_INIT
 |  └ SEQ = 0
 └ HEAD
```

### 10.4 `CMD_QUERY_SEQ` — TYPE `0xC1`

| 项 | 值 |
| --- | --- |
| TYPE | `0xC1` = CMD(3) \| 分区 0 \| 类型 1 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `targetSeq` | u8（8 bit / 1 B） | — | `0~255` | 无 |

**校验 / 门控**

- 未完成会话握手 → 回 `ACK_RESULT[0xC1, 6]`，记 `W/BLE 事件码 15`。
- `SEQ == 0` 在第 2 步已被拦截，回 `ACK_RESULT[0xC1, 5]`。
- 本命令**不做自身判重**：同一 `SEQ` 重复查询仍会应答，并按结果把该 `SEQ` 记入窗口。

**ACK 行为**

- `targetSeq` 在车端 64 条 CMD 窗口内 → `ACK_RESULT[0xC1, 1]`（是），记 `D/SYSTEM 事件码 7`。
- 不在窗口内 → `ACK_RESULT[0xC1, 2]`（否），记 `D/SYSTEM 事件码 8`。
- 查询成功后，若本查询自身的 `SEQ` 不在窗口内，则记入窗口并把 `_isInit` 置假。

**触发时机**

- App 在发送超时 / 重连后，用来确认「某条 CMD 是否已经执行过」，事件驱动，非常规节拍。
- 只查 CMD 窗口；**查不到** LOG / DAT / ACK 的 `SEQ`。

```text
AA 01 C1 05 EB
 |  |  |  |  └ CRC8 = EB
 |  |  |  └ targetSeq = 5
 |  |  └ CMD_QUERY_SEQ
 |  └ SEQ = 1
 └ HEAD
```

### 10.5 `CMD_REQ_INFO` — TYPE `0xC2`

| 项 | 值 |
| --- | --- |
| TYPE | `0xC2` = CMD(3) \| 分区 0 \| 类型 2 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 0 |
| 帧总长 | 4 |

**校验 / 门控**：需要已完成握手，否则 `ACK_RESULT[0xC2, 6]`；无参数可越界。

**ACK 行为**：`ACK_RESULT[0xC2, 3]`；随后**在同一轮**连发 `DAT_INFO_VERSION → POWER → STORAGE`，与握手后那一轮内容完全相同。

**触发时机**：事件驱动；车端不会周期性重发 `DAT_INFO`。App 若错过握手时的三帧，用本命令补拉。

```text
AA 02 C2 A5
```

### 10.6 `CMD_AUDIO_TEST` — TYPE `0xD0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xD0` = CMD(3) \| 分区 1 \| 类型 0 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `action` | u8（8 bit / 1 B） | — | `0` = 上电提示音；`1` = 1 kHz / 200 ms 测试音；`2` = 立即停止 | `> 2` 视为非法 |

**校验**

- `action > 2` → `ACK_RESULT[0xD0, 5]`，记 `W/BLE 事件码 48`（`0x30 + 0`）。
- 需要已完成握手，否则 `ACK_RESULT[0xD0, 6]`。

**ACK 行为**

| `action` | 条件 | 状态码（十进制） |
| --- | --- | --- |
| 2（停止） | 恒可执行，不检查硬件 | 3 |
| 0 / 1 | `AudioCue` 未初始化 → 记 `W/AUDIO 事件码 3` | 6 |
| 0 / 1 | 正在录音或回放（`Record::isBusy()`）→ 记 `W/AUDIO 事件码 4` | 6 |
| 0 / 1 | 另一段提示音还在播（`AudioCue::isBusy()`）→ 记 `W/AUDIO 事件码 5` | 6 |
| 0 / 1 | 以上都不成立 | 3 |

- 被拒时**不会**播放任何声音，状态码不会是 3。
- `3` 只代表「已受理」，播放由 `AudioCue::update()` 分块推进，不阻塞。

**触发时机**：事件驱动，单次；ACK 先发，播放后启动。

```text
AA 03 D0 00 64
 |  |  |  |  └ CRC8 = 64
 |  |  |  └ action = 0
 |  |  └ CMD_AUDIO_TEST
 |  └ SEQ = 3
 └ HEAD
```

### 10.7 `CMD_VOLUME` — TYPE `0xD1`

| 项 | 值 |
| --- | --- |
| TYPE | `0xD1` = CMD(3) \| 分区 1 \| 类型 1 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `volume` | u8（8 bit / 1 B） | % | `0` = 静音，`100` = 满量程 | `> 100` 视为非法 |

**校验**

- `> 100` → `ACK_RESULT[0xD1, 5]`，记 `W/BLE 事件码 49`（`0x30 + 1`）。
- **不做裁剪**：不会把 200 悄悄改成 100。
- 需要已完成握手，否则 `ACK_RESULT[0xD1, 6]`。

**ACK 行为**

- `Speaker` 未就绪 → `ACK_RESULT[0xD1, 6]`，记 `W/SPEAKER 事件码 1`，音量不变。
- 就绪 → `Speaker::setVolume(volume)`，`ACK_RESULT[0xD1, 3]`。

**触发时机**：事件驱动；设置是持久的，断电 / 复位后回到驱动默认值（固件不做 NVS 保存）。

```text
AA 04 D1 64 5C
 |  |  |  |  └ CRC8 = 5C
 |  |  |  └ volume = 100
 |  |  └ CMD_VOLUME
 |  └ SEQ = 4
 └ HEAD
```

### 10.8 `CMD_RECORD` — TYPE `0xD2`

| 项 | 值 |
| --- | --- |
| TYPE | `0xD2` = CMD(3) \| 分区 1 \| 类型 2 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `seconds` | u8（8 bit / 1 B） | 秒 | `1~10` | `0` 或 `> 10` 视为非法 |

**校验（顺序固定）**

1. `seconds < 1` 或 `> 10` → `ACK_RESULT[0xD2, 5]`，记 `W/BLE 事件码 50`（`0x30 + 2`）。
2. 需要已完成握手，否则 `ACK_RESULT[0xD2, 6]`。

**ACK 行为**

| 条件 | 状态码（十进制） | 日志 |
| --- | --- | --- |
| 录音缓冲未就绪（`Record::isReady()` 假） | 6 | `W/RECORD 1` |
| 麦克风未就绪（`Mic::isReady()` 假） | 6 | `W/RECORD 2` |
| 正在录音或回放 | 6 | `W/RECORD 4` |
| 提示音 / 测试音还在播 | 6 | `W/RECORD 5` |
| `seconds > Record::maxSeconds()`（PSRAM 缺失时缓冲只够 1~2 s） | 6 | `W/RECORD 6` |
| 以上都不成立 | 3 | — |

- 回 `3` 后车端才调用 `Record::start(seconds)`。若 `start` 当场失败（`START_BUSY` / `START_NO_MIC` / `START_TOO_LONG` / `START_NO_BUFFER`），车端**只写 W 日志（事件码 7/8/9/10）**，不会补发第二个 ACK。
- 因此 `3` 的语义是「参数通过并已尝试启动」，不是「已录完」。
- 录满 `seconds` 秒后**自动回放**，不需要 App 再发命令。

**触发时机**：事件驱动，单次；录音 / 回放全程非阻塞，由 `Record::update()` 推进。

```text
AA 05 D2 05 28
 |  |  |  |  └ CRC8 = 28
 |  |  |  └ seconds = 5
 |  |  └ CMD_RECORD
 |  └ SEQ = 5
 └ HEAD
```

### 10.9 `CMD_STOP` — TYPE `0xE0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xE0` = CMD(3) \| 分区 2 \| 类型 0 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 0 |
| 帧总长 | 4 |

**校验 / 门控**

- **唯一**允许在握手完成前执行的命令（急停不能被会话状态挡住）。
- 无参数可越界；重复 `SEQ` 仍按通用判重处理（回 `3`，不重复执行，但也不算错误）。

**ACK 行为**：恒 `ACK_RESULT[0xE0, 3]`，随后清空目标轮速 / PWM / 运动等级，并刷新失联计时（使超时不会再把停车当异常记录）。

> 注意：重复 `SEQ` 的 `CMD_STOP` 走通用判重，**不会再次执行**停车（只回 `3`）。若担心重发撞上已用 `SEQ`，请使用新的 `SEQ`。

**触发时机**：App 松开方向键、切换模式、退出遥控时发送；也用于握手前的安全兜底。

```text
AA 07 E0 0A
 |  |  |  └ CRC8 = 0A
 |  |  └ CMD_STOP（无 PAYLOAD）
 |  └ SEQ = 7
 └ HEAD
```

### 10.10 运动四命令 `0xE1`~`0xE4`

| 项 | 值 |
| --- | --- |
| TYPE | `0xE1` / `0xE2` / `0xE3` / `0xE4` = CMD(3) \| 分区 2 \| 类型 1 / 2 / 3 / 4 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `level` | u8（8 bit / 1 B） | % | `0~100`，相对最大速度 / 最大回转角速度 | `> 100` 视为非法 |

| TYPE | 名称 | 运动语义 |
| --- | --- | --- |
| `0xE1` | `CMD_FORWARD` | 前进：两轮同正 |
| `0xE2` | `CMD_BACK` | 后退：两轮同负 |
| `0xE3` | `CMD_LEFT` | 原地左转：左轮负、右轮正 |
| `0xE4` | `CMD_RIGHT` | 原地右转：左轮正、右轮负 |

**校验**

- `level > 100` → `ACK_RESULT[TYPE, 5]`，记 `W/BLE 事件码 0x30 + item`。
- 需要已完成握手（`CMD_STOP` 除外），否则 `ACK_RESULT[TYPE, 6]`。

**ACK 行为**

| `level` | 状态码（十进制） | 是否更新执行状态 |
| --- | --- | --- |
| 0 | 3 | 是，等价于 `CMD_STOP` |
| 1~100 | 1（已受理） | 是 |

- 状态码 `1` 是「持续运动已受理」，不是失败；`3` 只用于 `level = 0` 的停车语义。

**执行状态（当前无电机硬件，只算目标值）**

- 目标轮转速（`int16`，单位 `0.01 r/s`）= `level × 500 / 100`（最大 5.00 r/s）。
- 目标 PWM = `level × 255 / 100`。
- 差速解算：前进两轮同正；后退两轮同负；左转左负右正；右转左正右负。
- 每收到一条运动命令刷新「失联计时」。

**触发时机 / 节拍**

- **必须重复发送**：车端在最后一次运动命令后 **1000 ms** 内没有新的运动命令，就自动停车并记 `W/MOTOR 事件码 1`。
- 因此 App 需以明显小于 1 s 的周期持续重发（例如 200~500 ms 一条），每条用**新的 SEQ**；重复 `SEQ` 会被判重，不会刷新计时。

```text
AA 08 E1 5A E5   ← CMD_FORWARD，level = 90
AA 09 E2 32 AE   ← CMD_BACK，level = 50
AA 0A E3 28 40   ← CMD_LEFT，level = 40
AA 0B E4 3C 2C   ← CMD_RIGHT，level = 60
```

### 10.11 云台 `CMD_PITCH 0xE5` / `CMD_YAW 0xE6`

| 项 | 值 |
| --- | --- |
| TYPE | `0xE5` / `0xE6` = CMD(3) \| 分区 2 \| 类型 5 / 6 |
| 方向 | App → 车 |
| PAYLOAD 长度 | 1（8 bit / 1 B） |
| 帧总长 | 5 |

| 偏移（B） | 字段 | 类型 | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `angle` | u8（8 bit / 1 B） | 度（原始角值） | `0~255` 全部接受，**不做范围校验** | 无 |

**校验 / ACK**

- 只校验握手和判重；`angle` 全 `0~255` 都接受。
- 回 `ACK_RESULT[TYPE, 3]`；角度写入 `_gimbalPitchAngle` / `_gimbalYawAngle`。
- **不参与**运动失联计时（不会因为只发云台命令触发自动停车，也不会被自动停车清零）。
- 本固件**没有云台硬件**，角度只保存不驱动。
- 角度显示属于 App 侧约定：旧版 App 用 `角度 = raw × 180 / 255`（俯仰）、`raw × 360 / 255`（偏航）；
  固件**不做**这个换算，只存原始字节。

```text
AA 0C E5 5A 1A   ← CMD_PITCH，angle = 90
AA 0D E6 2D 0C   ← CMD_YAW，angle = 45
```

## 11. ACK 全表

### 11.1 方向与总览

| 项 | 规则 |
| --- | --- |
| 方向 | **只允许 车 → App**；车端收到 App 的 ACK 整帧静默丢弃 |
| 帧格式 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN |
| PAYLOAD 长度 | 三种 ACK 全部固定 2 字节（2 × 8 bit = 16 bit） |
| 帧总长 | 6 |
| 发送方式 | 20 字节分片的 notify；6 字节一帧一个分片发完 |
| 应答时机 | 在处理完一条 CMD 的同步路径内发出；音频 / 录音动作在 ACK 之后才启动 |
| 应答范围 | **只对 CMD 应答**；LOG / DAT 不需要应答，App 也不得对它们回 ACK |
| 配对 | App 用 `PAYLOAD[0]` 反查命令、用 `SEQ` 匹配自己发出的那一条 |

| TYPE | 名称 | KIND / 分区 / 类型（十进制） | PAYLOAD |
| --- | --- | --- | --- |
| `0x00` | `ACK_RESULT` | ACK / 0 / 0 | `[CMD 的 TYPE, 状态码]` |
| `0x01` | `ACK_SESSION_INIT` | ACK / 0 / 1 | `[状态码, resetDone]` |
| `0x10` | `ACK_ERROR` | ACK / 1 / 0 | `[CMD 的 TYPE, 错误码]`（**固件不发送**） |

- ACK 的 `SEQ` 与被应答 CMD 的 `SEQ` 相同（原样回填）；`ACK_SESSION_INIT` 例外，`SEQ` 恒为 0。
- ACK 不做去重；App 按需处理，不把 ACK 的 `SEQ` 写入 LOG / DAT 窗口。

### 11.2 `ACK_RESULT` — TYPE `0x00`

| 项 | 值 |
| --- | --- |
| TYPE | `0x00` = ACK(0) \| 分区 0 \| 类型 0 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 2（2 × 8 bit = 16 bit） |
| 帧总长 | 6 |
| `SEQ` | 与对应 CMD 相同 |

| 偏移（B） | 字段 | 类型（1 B = 8 bit） | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `cmdType` | u8 | — | 被应答 CMD 的完整 TYPE（如 `0xE1`） | 无 |
| 1 | `status` | u8 | — | 0~6，见 11.5 | 7 及以上当前固件不产生，App 按未知处理 |

**用途**：除 `CMD_SESSION_INIT` 以外的所有 CMD 都用它应答。

**不会出现的组合**

- `PAYLOAD[0]` 不会是 `0xC0`（`CMD_SESSION_INIT` 只走 `ACK_SESSION_INIT`）。
- `PAYLOAD[0]` 不会是 `0xD3` / `0xE7` / `0xE8` 以外的任何“未登记 TYPE”，因为那些帧在解析阶段就被丢弃，不会走到应答环节。

**典型状态映射**

| 情形 | `status` |
| --- | --- |
| 会话未初始化就发普通命令（`CMD_STOP` 除外） | 6 |
| 参数越界（音频 `> 2`、音量 `> 100`、录音不在 1~10、运动等级 `> 100`） | 5 |
| `SEQ = 0` 用在非握手命令 | 5 |
| 重复 `SEQ`（64 条窗口命中） | 3（不重复执行） |
| 硬件 / 状态不满足（喇叭未就绪、录音忙、音频未初始化等） | 6 |
| 运动命令 `level = 0`、停车、云台、查询无参数命令 | 3 |
| 运动命令 `level = 1~100` | 1 |
| `CMD_QUERY_SEQ` 命中窗口 / 未命中 | 1 / 2 |
| `CMD_REQ_RECORD`、`CMD_LEFT_SHIFT`、`CMD_RIGHT_SHIFT` | 4 |

**完整示例**（对 `CMD_FORWARD 0xE1`、`SEQ 8` 的受理应答）

```text
AA 08 00 E1 01 CF
 |  |  |  |  |  └ CRC8 = CF
 |  |  |  |  └ status = 1（已受理，持续运动）
 |  |  |  └ cmdType = 0xE1
 |  |  └ ACK_RESULT
 |  └ SEQ = 8（与命令一致）
 └ HEAD
```

### 11.3 `ACK_SESSION_INIT` — TYPE `0x01`

| 项 | 值 |
| --- | --- |
| TYPE | `0x01` = ACK(0) \| 分区 0 \| 类型 1 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 2（2 × 8 bit = 16 bit） |
| 帧总长 | 6 |
| `SEQ` | **恒为 0** |

| 偏移（B） | 字段 | 类型（1 B = 8 bit） | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `status` | u8 | — | `3` = 握手成功；`5` = 协议版本不符 | 其他值当前不产生 |
| 1 | `resetDone` | u8 | — | `1` = 车端清空了 64 条 CMD 去重表；`0` = 未清空 | 无 |

**触发条件**

| 条件 | `status` | `resetDone` |
| --- | --- | --- |
| `CMD_SESSION_INIT` 的 `protocol == 20` 且上电后还没执行过普通 CMD | 3 | 1 |
| 同上，但上电后已执行过普通 CMD（如断连重连） | 3 | 0 |
| `protocol != 20` | 5 | 0（并把会话标记为未初始化） |

- `resetDone = 1` 时，App 可以放心复用 1~255 的旧 `SEQ`，不会撞上旧记录。
- `resetDone = 0` 时，App 必须继续使用未用过的 `SEQ`，或先发 `CMD_QUERY_SEQ` 确认。
- 握手**不影响** LOG / DAT 的 `SEQ` 计数器；它们上电归零后一直递增，断连不重置。
- `CMD_SESSION_INIT` 用了非 0 的 `SEQ` 时不会走到这里，而是回 `ACK_RESULT[0xC0, 5]`。

**完整示例**

```text
AA 00 01 03 01 7D   ← 握手成功，已清空去重表（随后紧跟 DAT_INFO 三帧）
AA 00 01 05 00 04   ← 协议版本不符（App 应改用 protocol = 20 重新握手）
```

### 11.4 `ACK_ERROR` — TYPE `0x10`（已定义，不发送）

| 项 | 值 |
| --- | --- |
| TYPE | `0x10` = ACK(0) \| 分区 1 \| 类型 0 |
| 方向 | 车 → App |
| PAYLOAD 长度 | 2（2 × 8 bit = 16 bit；长度表已登记） |
| 帧总长 | 6 |
| 固件发送情况 | **从不发送** |

| 偏移（B） | 字段 | 类型（1 B = 8 bit） | 说明 |
| --- | --- | --- | --- |
| 0 | `cmdType` | u8 | 被应答 CMD 的 TYPE |
| 1 | `errorCode` | u8 | 错误码（当前无发送路径，无实际值定义） |

- 当前所有错误都用 `ACK_RESULT` 的状态码 `5` / `6` 表达。
- App 侧解析器应容忍收到 `0x10`（长度表一致即可），但**不能依赖它**判断错误。
- 不要把它文档化成“可用能力”：本固件没有发送它的代码路径。

**示例（仅用于说明格式，固件不产生）**

```text
AA 08 10 E1 05 71   ← 仅示例格式（CRC 已按同规则算出），实际不会出现
```

### 11.5 状态码表

| 值（十进制） | 名称 | 含义 | 谁会产生 |
| --- | --- | --- | --- |
| 0 | `ACK_ST_RECEIVED` | 已接收（预留，当前无使用点） | — |
| 1 | `ACK_ST_YES` | 是 / 已受理 | `CMD_QUERY_SEQ` 命中；运动命令 `level 1~100` |
| 2 | `ACK_ST_NO` | 否 | `CMD_QUERY_SEQ` 未命中 |
| 3 | `ACK_ST_DONE` | 完成 / 已执行 | 大多数命令、重复 `SEQ`、`level = 0` |
| 4 | `ACK_ST_UNKNOWN` | 无法识别 | `0xD3`、`0xE7`、`0xE8` |
| 5 | `ACK_ST_ERROR` | 参数 / 版本错误 | 越界参数、`SEQ = 0`、版本不符 |
| 6 | `ACK_ST_CANNOT` | 当前不能执行 | 未握手、硬件未就绪、忙 |

- 状态码一律**十进制**书写。
- `1` 与 `3` 都不是失败：“已受理”表示运动已开始，App 需继续发新命令维持。
- App 不要把 `1` 当成功终态而停止重发——运动会在 1000 ms 后自动停车。

### 11.6 握手时序

```text
App                                                  车
 |  AA 00 C0 14 E2   CMD_SESSION_INIT(protocol=20)  →
 |                                                   | 清空去重表（仅首帧）
 |  ←  AA 00 01 03 01 7D   ACK_SESSION_INIT[3,1]
 |  ←  AA 01 83 ...        DAT_INFO_VERSION
 |  ←  AA 02 84 ...        DAT_INFO_POWER
 |  ←  AA 03 85 ...        DAT_INFO_STORAGE
 |  AA 01 D1 64 5C   CMD_VOLUME(100)                →
 |  ←  AA 01 00 D1 03 XX   ACK_RESULT[0xD1,3]
```

- 三条 `DAT_INFO` 与握手 ACK 在同一轮发出，App 必须按顺序收，不能假设它们跨轮。
- 握手前只允许 `CMD_STOP`；其他任何命令回 `6`。
- 断连后车端立即把会话置为未初始化并重新广播；App 重连后必须重新握手。
- 握手失败（`status = 5`）时会话保持未初始化，App 修正 `protocol` 后重发即可。

### 11.7 ACK 规则汇总

1. 一条 CMD 对应**一个** ACK；除 `CMD_SESSION_INIT` 外都用 `ACK_RESULT`。
2. `ACK` 不重发、不补发；App 超时后只能手动重发 CMD 或先查 `CMD_QUERY_SEQ`。
3. `ACK` 的 `SEQ` 原样回填；App 必须同时核对 `SEQ` 与 `PAYLOAD[0]`，防止串线。
4. `ACK` 不进入任何去重窗口；重复 ACK 由 App 按需幂等处理。
5. `ACK_ERROR` 已定义但无发送路径；不要为它编写依赖逻辑。

## 12. DAT 全表

### 12.1 方向、节拍与去重

| 项 | 规则 |
| --- | --- |
| 方向 | **只允许 车 → App**；车端收到 DAT 帧静默丢弃 |
| 帧格式 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN |
| `SEQ` | 全部 DAT 帧共用**一个** 8 位计数器：每发一帧 +1，255 后回绕到 0；**握手与断连重连都不重置** |
| 去重 | App 侧按 `SEQ` 去重（保留最近 64 条）；车端不重发、不补帧 |
| 发送前提 | 已连接 **且** 已完成 `CMD_SESSION_INIT`；未握手时车端不发任何 DAT |
| 分片 | 每 20 字节一个 notify；`DAT_INFO_VERSION` 24 字节拆成 20 + 4 两片 |

| TYPE | 名称 | 多发 / 单发 | 周期或触发 | 仅握手时上报 |
| --- | --- | --- | --- | --- |
| `0x80` | `DAT_BAT` | 多发 | 每 **500 ms** | 否 |
| `0x81` | `DAT_US` | 单发 | **无调用点**，当前不上报 | — |
| `0x82` | `DAT_WHEEL` | 单发 | **无调用点**，当前不上报 | — |
| `0x83` | `DAT_INFO_VERSION` | 单发（成组 3 帧） | 握手成功后一轮 + `CMD_REQ_INFO` 后一轮 | 否（也响应补拉） |
| `0x84` | `DAT_INFO_POWER` | 单发（成组 3 帧） | 同上，紧跟 `0x83` | 否 |
| `0x85` | `DAT_INFO_STORAGE` | 单发（成组 3 帧） | 同上，紧跟 `0x84` | 否 |
| `0x90` | `DAT_MEM` | 多发 | 每 **1000 ms** | 否 |
| `0xA0` | `DAT_REQ` | 单发 | 板端需要 App 做事时（当前只有“请求录音”） | 否 |

- `DAT_BAT` 与 `DAT_MEM` 是两个独立节拍，相位不对齐；两者共用 `SEQ` 计数器，所以正常情况下每秒约 +3。
- `DAT_INFO` 三帧一轮、连续发出，`SEQ` 取连续三个值；**不做周期重发**，App 漏收只能用 `CMD_REQ_INFO` 补拉。
- 所有 DAT 帧都是**车 → App**，App 不得回 ACK。

| --- | --- |
| TYPE | `0x90` = DAT(2) \| 分区 1 \| 类型 0 |

| 偏移（B） | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值含义 |

| 2~3 | `psramFree` | u16 大端 | KB | 0~65534 | `0xFFFF` = 无 PSRAM |

| 10~11 | `uptimeLow` | u16 大端 | — | — | 运行秒数的低 16 位 |

- **运行秒数由两个 u16 拼成**：`uptime = (uptimeHigh << 16) | uptimeLow`，不是“高 / 低各一半的独立量”。
- 容量换算：字节 / 1024 取整后写入；超过 65534 KB 一律写 `65534`（保留 `65535` 给“无效”）。
- `logPending` 是 `Logger` 中待出队的条数（不含断连补发环），饱和写 `255`。
- `logDropped` 是队列满时丢弃的累计条数（上电后累计），饱和写 `65534`。
- 字节 13 留给“DAT 通道队列水位”，本固件该通道没有软件队列，**值恒为 `0xFF`**；App 应显示“无效”而不是 255 条。
- 触发：独立 1000 ms 节拍，与 `DAT_BAT` 的 500 ms 节拍互不影响；均要求已连接且已握手。

```text

 |  |  |  └ … 16 字节 PAYLOAD …                              └ CRC8 = B6
 |  |  └ DAT_MEM

 └ HEAD
```

### 12.9 `DAT_REQ` — TYPE `0xA0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xA0` = DAT(2) \| 分区 2 \| 类型 0 |
| 方向 | **车 → App**（板端请求 App 执行动作；车端永不发 CMD） |
| PAYLOAD 长度 | 2（2 × 8 bit = 16 bit） |
| 帧总长 | 6 |
| 多发 / 单发 | **单发**，事件驱动 |
| 需已握手 | **是**（未连接或未握手直接拒绝，不发帧） |

| 偏移（B） | 字段 | 类型（1 B = 8 bit） | 单位 | 取值 | 无效值含义 |
| --- | --- | --- | --- | --- | --- |
| 0 | `code` | u8 | — | 1~10，见下表 | 0 或 > 10：车端拒绝整条请求，**不发帧** |
| 1 | `param` | u8 | — | 含义随 `code` | 见下表；越界由车端**静默裁剪**（全协议唯一裁剪点） |

| `code`（十进制） | 含义 | `param` 语义 | 车端处理 |
| --- | --- | --- | --- |
| 1 | 请求停车 | 无 | 强制置 `0` |
| 2 | **请求录音** | 无 | 强制置 `0` |
| 3 | 请求左横移 | 等级 0~100 | `> 100` 裁到 `100` |
| 4 | 请求右横移 | 等级 0~100 | `> 100` 裁到 `100` |
| 5 | 请求云台俯仰 | 角度 0~255 | 不裁剪 |
| 6 | 请求云台偏航 | 角度 0~255 | 不裁剪 |
| 7 | 请求前进 | 等级 0~100 | `> 100` 裁到 `100` |
| 8 | 请求后退 | 等级 0~100 | `> 100` 裁到 `100` |
| 9 | 请求左转 | 等级 0~100 | `> 100` 裁到 `100` |
| 10 | 请求右转 | 等级 0~100 | `> 100` 裁到 `100` |

**当前实际发送情况**

- 固件只有 `requestRecording()` 一个调用点，它固定发 `code = 2`、`param = 0`。
- 其余 `code` 有编码与裁剪路径，但**当前没有调用点**，属于“协议已定义、固件暂不产生”。
- `code = 3/4`（横移）即使 App 收到，映射回 CMD 后也只会得到 `ACK_ST_UNKNOWN(4)`，因为本车是差速轮。

**App 响应流程**

1. 按 `code` 映射成对应 CMD（`2 → CMD_RECORD 0xD2`，参数按 App 的录音秒数策略决定；`1 → CMD_STOP` 等）。
2. 用**新的 `SEQ`** 发送该 CMD，并等待 `ACK_RESULT`。
3. 不对 `DAT_REQ` 本身回 ACK（ACK 只对应 CMD）。

**拒绝路径（不发帧，只写 W 日志）**

| 条件 | 日志 |
| --- | --- |
| 未连接 / 未握手 / TX 特征不可用 | `W/DAT 事件码 2` |
| `code` 不在 1~10 | `W/DAT 事件码 3` |

```text
AA 05 A0 02 00 02
 |  |  |  |  |  └ CRC8 = 02
 |  |  |  |  └ param = 0
 |  |  |  └ code = 2（请求录音）
 |  |  └ DAT_REQ
 |  └ SEQ = 5
 └ HEAD
```

其他请求码示例（仅格式，当前无调用点）：

```text
AA 05 A0 03 32 89   ← code = 3（左横移），param = 50
```

### 12.10 DAT 数值与无效值约定

| 约定 | 内容 |
| --- | --- |
| 大小端 | 所有 u16 / int16 **一律大端**（高字节在前） |
| 定点数 | 电压 `0.01 V`；轮速 `0.01 r/s`；轮径 `mm`；距离 `cm` |
| 无符号无效值 | `0xFFFF`（65535） |
| 有符号无效值 | `0xFFFF`（即 `−1`） |
| 饱和值 | 内存与计数类字段饱和到 `65534` / `254`，保留 `65535` / `255` 给无效 |
| 百分比 | 全部 0~100 整数，不出现小数 |
| 单位换算 | 固件只发原始量，换算与显示全部由 App 完成 |

## 13. LOG 全表

### 13.1 方向与帧结构

| 项 | 规则 |
| --- | --- |
| 方向 | **只允许 车 → App**；车端收到 LOG 帧静默丢弃 |
| 帧格式 | `AA | SEQ | 8×[TYPE+参数] | CRC8` |
| 帧长 | **固定 19 B** = `1 + 1 + 16 + 1`，与任何 TYPE 静态表项无关 |
| 每帧记录数 | 恒为 8 条；不足 8 条用 `0x00 0x00` 补齐 |
| 单条记录 | **2 B = 16 bit**（TYPE 1 B + param 1 B） |
| CRC8 | CRC-8/ATM（`0x07`、初值 `0x00`），覆盖 `AA` 到第 8 条记录的 param 字节（共 18 B） |
| 应答 | **不需要 ACK**，App 不得回 ACK |
| 分片 | 19 字节一个 notify 分片 |

```text
偏移  0     1     2..17（8 条 × 2 字节）        18
     AA   SEQ   [TYPE0 param0] … [TYPE7 param7]  CRC8
```

- 偏移 2 处的字节是**第 1 条记录的 TYPE**，它同时充当帧的“TYPE 位”。因为它最高 2 位恒为 `01`（LOG），
  解析器据此把帧长定为 19；这是本协议唯一“帧长不查表”的例外。
- 解析时先读偏移 2：`KIND = 该字节 >> 6`；若 `KIND == 1` 就按 19 字节取帧，再逐条解码。
- 末条之后的补齐记录 `TYPE = 0x00`、`param = 0x00`，App 必须跳过 `TYPE == 0x00` 的记录。

### 13.2 记录字节：TYPE + param

| 字节（1 B = 8 bit） | 内容 |
| --- | --- |
| 记录 TYPE | `(KIND_LOG << 6) | (等级分区 << 4) | 模块号`，`KIND_LOG = 1`，故基址为 `0x40` |
| 记录 param | 事件码或数值；`0x00` 表示“无附加数值” |

`param` 的取值语义：

| 区间（十六进制） | 含义 |
| --- | --- |
| `0x00` | 只有事件码、无附加数值（**也用作补齐**） |
| `0x01`~`0x1F` | 模块内事件码（见 13.5） |
| `0x20`~`0x2F` | BLE 模块：**未知 CMD** 的 item 编号（`0x20 + item`） |
| `0x30`~`0x3F` | BLE 模块：**参数非法 CMD** 的 item 编号（`0x30 + item`） |
| `0x40`~`0x7F` | 数值 / 码段（当前固件不产生） |
| `0x80`~`0xFF` | 预留，当前固件不产生 |

> 车端入队规则：`param != 0 ? param : code`。也就是说，**如果调用点同时给了事件码和参数，事件码会被参数覆盖**。
> 当前所有调用点都不传 `param`，所以第二字节就是事件码本身；新增调用点时不要两者同时给。

| --- | --- | --- |
| 0 | `SYSTEM` | 是 |
| 1 | `BLE` | 是 |
| 2 | `LOG` | **否**（编号已定义，无调用点） |
| 3 | `DAT` | 是 |
| 4 | `TFT` | 是 |
| 5 | `AUDIO` | 是 |

### 13.4 等级分区

等级分区占用记录 TYPE 的 bit5-4。固件把 5 个日志等级映射到 3 个分区：

| 分区（十进制） | 名称 | 固件等级 | 记录 TYPE 基址 |
| --- | --- | --- | --- |
| 0 | D（调试 / 信息） | `Debug`、`Info` **都并入 D** | `0x40` |
| 1 | E（错误 / 致命） | `Error`、`Fatal` **都并入 E** | `0x50` |
| 2 | W（警告） | `Warning` | `0x60` |
| 3 | 预留 | — | 不使用 |

- **LOG 只有 D / E / W 三档**；`Info` 并入 D，`Fatal` 并入 E，App 无法从帧中区分 `Debug/Info`、`Error/Fatal`。
- 举例：模块 1（BLE）的 W 记录 TYPE = `0x40 | 0x20 | 1` = `0x61`。

### 13.6 发送节拍与队列

| 项 | 值 |
| --- | --- |
| 队列容量 | 64 条（每条 2 字节，约 1.2 s 突发缓冲） |
| 每帧条数 | 8 |
| 最小帧间隔 | **20 ms** |
| 发送前提 | 已连接 **且** 已完成 `CMD_SESSION_INIT` |
| 队列满策略 | **丢最旧一条**并累加丢弃计数，绝不阻塞调用方 |
| 丢弃计数 | 通过 `DAT_MEM` 的 `logDropped`（偏移 14~15）上报，饱和 65534 |
| 待发计数 | 通过 `DAT_MEM` 的 `logPending`（偏移 12）上报，饱和 255 |
| 无 LEN 的后果 | 每次出队最多 8 条就封一帧，剩余留到下一轮，不跨帧拼包 |
| 优先级 | 每轮 `update()` 的顺序为：DAT 遥测 → DAT_MEM → 实时 LOG → 补发 |

- 未握手时，队列里的日志按“离线规则”处理（见 13.7），不会在握手完成后突然涌出旧日志。
- 实时 LOG 与 DAT 共用同一条 BLE 通知通道，每帧 19 字节一个分片，不等待 App 应答。

### 13.7 断连补发

| 项 | 规则 |
| --- | --- |
| 缓存对象 | **只缓存 W 和 E 两个分区**；D 分区（Debug/Info）断连即丢 |
| 容量 | 32 条，环形，满时丢最旧 |
| 时效 | 条目从“被捕获时刻”起算，超过 **30000 ms** 未补发即丢弃 |
| 出队时机 | 实时队列为空，且距上一帧 LOG ≥ 20 ms，且距上一帧 DAT ≥ 20 ms |
| 每帧条数 | 8 条（与实时帧同格式），`SEQ` 与实时帧共用同一计数器 |
| 重发 | 不重试、不重排；只按捕获顺序补最近 32 条 |
| 与握手关系 | 补发不要求重新握手，但要求已连接且已握手；否则继续留在环里等待或超期丢弃 |

- 补发帧与实时帧**格式完全相同**，App 无法区分，也不需要区分。
- 由于 30 s 时效，长时间断连后重连只会收到最近的 W/E，早期的错误不会补。

### 13.8 解析规则

1. 读偏移 2 的字节，确认 `KIND == 1`；否则不是 LOG 帧。
2. 固定取 19 字节整帧，校验 CRC（覆盖前 18 字节）。
3. 从偏移 2 起每 2 字节一条记录，共 8 条。
4. 跳过 `TYPE == 0x00` 且 `param == 0x00` 的空槽。
5. 按 `模块号 = TYPE & 0x0F`、`等级 = (TYPE >> 4) & 0x03`、`param` 查表显示。
6. 未知模块号 / 未登记事件码只按数字显示，不影响整帧处理；LOG 不做任何 ACK 或回执。

### 14.2 运动、应答与急停

```text
App →  AA 08 E1 5A E5                                      CMD_FORWARD(level = 90, SEQ = 8)
车  →  AA 08 00 E1 01 CF                                   ACK_RESULT[0xE1, 1]（已受理，持续运动）
App →  AA 09 E1 5A 8E                                      CMD_FORWARD(level = 90, SEQ = 9)，必须持续重发
车  →  AA 09 00 E1 01 D9                                   ACK_RESULT[0xE1, 1]
App →  AA 07 E0 0A                                         CMD_STOP(SEQ = 7，无 PAYLOAD)
车  →  AA 07 00 E0 03 06                                   ACK_RESULT[0xE0, 3]（完成，已停车）
```

- 运动命令 `level = 1~100` 只回 `ACK_ST_YES(1)`；不重发则 1000 ms 后车端自动停车并记 `W/MOTOR 1`。
- `CMD_STOP` 允许在握手前发送，用于急停兜底。

```text
车 →  AA 04 90 01 00 10 00 00 A0 00 80 00 00 00 00 04 FF 00 03 B6
                                                            DAT_MEM（16 字节，SEQ = 4）
车 →  AA 05 A0 02 00 02                                   DAT_REQ（code = 2 请求录音，param = 0，SEQ = 5）
```

- `DAT_BAT` 每 500 ms 一帧，`DAT_MEM` 每 1000 ms 一帧，二者共用 DAT 的 `SEQ` 计数器。

## 废弃原因

1. **只覆盖蓝牙一条链路，缺 WiFi 近程 / 远程与 AI 通道。** V2.0 全文只有 BLE NUS，没有 WiFi 的 ctrl / video / audio 三通道、没有公网 relay / 4G 直连、没有 AI 上行语音与下行文字 + 语音；江灵把三条链路分层并给出职责矩阵。
2. **TYPE 表没有把 LOG 等级与模块固化成完整码表。** V2.0 的 `TYPE→长度` 表只登记 ACK / DAT / CMD，LOG 以“19 B 特例”旁挂在表外；等级、模块号、事件码分散在 `LOG.md`，无法用一张 TYPE 表核对 `0x00`~`0xFF`。江灵把 LOG 单列成册，并完整收录 `Protocol.h` 已定义的事件码。
3. **没有定义模式切换与广播生命周期。** V2.0 只写连接 / 握手 / 断连，未写 BLE ↔ WiFi 切换、广播 15 s 后关闭、如何重新开广播、切换前后 SEQ 与缓冲如何保持；江灵把“广播 15 s 后关闭”列为新事实，并规定切换前发一次 `CMD_SESSION_INIT(SEQ = 0)`、SEQ 单调递增、缓冲不跨模式复用。
4. **AI / 视频与 ctrl 通道边界未写清。** V2.0 没有 AI 通道、视频通道、远程双向语音通道，也没有定义谁拥有 SEQ、谁可以跨链路；江灵明确 BLE 只承载 CMD / ACK / LOG / DAT，视频与 AI 永不走 BLE，AI 独立通道不占 ctrl 的 SEQ。
5. **单文件缺少分册维护粒度。** V2.0 原始以 `总文档 / CMD / ACK / DAT / LOG` 五份分册维护，合并为单文件后只能整体 diff、整体校验；江灵恢复“总览 / 命令 / 回复 / 日志 / 数据”五册，并对每册单独做 SHA-256 与字节数校验。
6. **握手与版本机制只服务单链路。** `CMD_SESSION_INIT` 只处理 BLE 连接，模式切换后无法保证 SEQ 与去重窗口连续；江灵把握手扩展到三链路共用的 ctrl 语义，并规定 `SEQ = 0` 免去重、切换时缓冲不跨模式复用。
7. **缺少远程双向语音与 AI 唤醒 / 超时 / 播报完成事件。** V2.0 只有本地录音回放与提示音，远程说话只能靠 App 手发 CMD；江灵新增远程操控（双向纯语音、AEC / 半双工取舍）与 AI 唤醒词、30 s 超时（从播报完成起算）及“播报完成”事件。
8. **调试输入约定没有进协议正文。** V2.0 的 App 调试面板只在源码里约束“TYPE 用十六进制、参数用十进制、只允许 CMD `0xC0`~`0xFF`、不输入 LEN、未登记 CMD 拒绝发送、参数 0~255”，协议正文没有固化；江灵把调试输入与校验规则写进正文，避免各端各写一套。
