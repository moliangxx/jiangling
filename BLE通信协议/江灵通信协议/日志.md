> 本文件是五份中的第 4 份，只写 **LOG**：车 → App。
> 权威目录：`d:\Esp32Project\index\江灵通信协议\`。

---

## 0. 方向与定位

| 项 | 约定 |
| --- | --- |
| 方向 | **只能 车 → App** |
| 用途 | 只记录「**发生了什么**」（事件、错误、状态变迁） |
| 不记录 | 测量值（电压 / 温度 / 内存水位 / 轮速）→ 走 DAT，不上日志 |
| 链路 | BLE / WiFi 同一套 |

---

## 1. 帧结构：19 B 定长

```
[HEAD 1B] [SEQ 1B] [记录 × 8：TYPE 1B + 参数 1B] [CRC8 1B]
 = 1 + 1 + 16 + 1 = 19 B
```

| 项 | 值 |
| --- | --- |
| 帧长 | **固定 19 B**（`1 B = 8 bit`，16 B 记录区 = 8 × 2 B） |
| 记录数 | **每帧固定 8 条**，不足补空槽 |
| 空槽 | `0x00 0x00`（TYPE=0 且参数=0），App 直接跳过 |
| 填充位置 | **只在尾部**；记录从槽 0 左对齐连续填充 |
| SEQ | `0~255`；车端 64 条去重窗口 |
| CRC | CRC-8/ATM，覆盖 `AA` 到最后一个记录字节（即前 18 B） |
| 长度表 | 第 3 字节 KIND=`01`（任意等级/模块）→ 帧长固定 19，**不查普通长度表** |

> 左对齐是硬约束：第 3 字节必须是一个 `kind=LOG` 的记录 TYPE；若首槽为空，第 3 字节会变成 `0x00`（kind=ACK），接收端会按 6 B 误判整帧。

---

## 2. 记录结构

| 字节 | 字段 | 说明 |
| --- | --- | --- |
| 1 | `TYPE` | `0x40 \| (等级 << 4) \| 模块`，自带 kind=LOG |
| 2 | `参数` | 1 B：事件码 / 数值 / 命令回显，含义由「模块 + 码段」决定 |

- 记录 TYPE 只有 4 个等级 × 16 个模块 = 64 种。
- App 解析出 `(等级, 模块, 参数)` 三元组后查码表转中文；**码表没有的码**必须显示 `UNKNOWN(模块N/参数0xXX)` 并保留原始字节，不能崩、不能静默丢。

---

## 3. 等级 = 分区

| 分区 | 等级 | 常量 | 说明 |
| --- | --- | --- | --- |
| 0 | **D** | `LOG_ZONE_DEBUG` | 调试/常规事件；原 `Info` 级并入 D |
| 1 | **E** | `LOG_ZONE_ERROR` | 错误；原 `Fatal` 级并入 E |
| 2 | **W** | `LOG_ZONE_WARN` | 警告 |
| 3 | 预留 | `LOG_ZONE_RSV` | 未使用，收到按 D 显示并标注「预留等级」 |

只有 **D / E / W** 三档，不存在 Info / Fatal 第四、第五档。

## 6. 参数码段规则

| 范围 | 用途 | 例 |
| --- | --- | --- |
| `0x00` | 空槽（仅当 TYPE 也是 0） | `00 00` |
| `0x01~0x1F` | 事件码 | 蓝牙 `0x0C` = 客户端已连接 |
| `0x20~0x7F` | 数值/回显码段 | BLE `0x20\|kindType`；音频音量 `0x20~0x7F` = 音量 0~95 |
| `0x80~0xFF` | 当前未分配 | 收到按 `UNKNOWN` 显示 |

- 单字节参数永远够用：需要带数值的日志一律用码段映射，不新增多字节日志。
- 音频音量码段：`参数 - 0x20` ∈ `0~95`，`0` = 静音；与 `CMD_VOLUME` 的 `0~100` 是两套刻度，展示时注明来源。

## 7. 发送节拍与补发

| 项 | 约定 |
| --- | --- |
| 打包 | 每帧固定 8 条，**左对齐**，尾部补 `00 00` |
| 节奏 | **每轮最多发 1 帧（19 B，≤8 条）**；队列超过 8 条时，下一轮继续发下一帧 |
| 队列 | 有界队列；满时丢最旧并记 `LOG_MOD_LOG` 溢出事件（该模块当前暂不发） |
| 断连 | 连接断开后队列保留（有界），重连后按轮次补发 |
| 去重 | 车端 64 条 SEQ 窗口；App 侧同样维护窗口，重复 SEQ 丢弃 |
| 优先级 | LOG 低于 ACK，高于 DAT 的周期性上报 |

## 8. 完整帧示例

1 条 `D/BLE/客户端已连接` + 7 个空槽：

```
AA 02 41 0C 00 00 00 00 00 00 00 00 00 00 00 00 00 00 AD
```

| 字节 | 含义 |
| --- | --- |
| `AA` | 帧头 |
| `02` | SEQ=2 |
| `41` | LOG + 等级 D(0) + 模块 1（`0x40 \| 0x00 \| 0x01`） |
| `0C` | `BLE_LOG_CLIENT_CONNECTED` |
| 7×`00 00` | 空槽 |
| `AD` | CRC（覆盖前 18 B） |
