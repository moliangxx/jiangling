# 江灵通信协议 · 回复（ACK）

> 本文件是五份中的第 3 份，只写 **ACK**：车 → App。
> 命令定义见 `命令.md`；DAT/LOG 见 `数据.md` / `日志.md`。
> 权威目录：`d:\Esp32Project\index\江灵通信协议\`。

---

## 0. 方向与总览

| 项 | 约定 |
| --- | --- |
| 方向 | **只能 车 → App**。App 不得主动发 ACK，唯一例外见 0.1 |
| 帧 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN |
| TYPE 数 | **3 个**：`0x00` / `0x01` / `0x10` |
| PAYLOAD | 全部 **2 B**，帧长固定 6 |
| 编码 | TYPE 十六进制，状态码/SEQ 十进制 |

### 0.1 唯一例外：方向非法的 CMD

App 若收到 CMD（正常协议里不可能），视为方向非法：**不执行、不建记录**，回 `ACK_RESULT` `[该 CMD 的完整 TYPE, 5=错误]`。除此之外 App 不发任何 ACK。

### 0.2 ACK 不按命令派生 TYPE

2.0 曾「一个命令一个 ACK TYPE」，本版收敛为 3 个：

| TYPE | 名称 | 分区/类型 | PAYLOAD（2 B） |
| --- | --- | --- | --- |
| `0x00` | `ACK_RESULT` | 0/0 | `[被应答 CMD 的完整 TYPE(1 B), 状态码(1 B)]` |
| `0x01` | `ACK_SESSION_INIT` | 0/1 | `[状态码(1 B), resetDone(1 B)]` |
| `0x10` | `ACK_ERROR` | 1/0 | `[被应答 CMD 的完整 TYPE(1 B), 错误码(1 B)]` |

好处：命令扩展不会挤爆 ACK 的类型空间；`PAYLOAD[0]` 同时解决「ACK 与命令对账」和「命令名可读」。

## 1. `ACK_RESULT` `0x00`

| 项 | 内容 |
| --- | --- |
| 触发 | 任意已登记的 CMD（除握手） |
| PAYLOAD | `[cmdType, status]`：`8 bit（1 B）` + `8 bit（1 B）` |
| SEQ | **原样回显被应答 CMD 的 SEQ** |
| 对账 | **必须 `SEQ` + `PAYLOAD[0]` 双条件**：只匹配 SEQ 会把并发命令的 ACK 弄混 |
| 丢失 | ACK 丢失不重发；App 超时判失败 |

状态码见第 4 节。

---

## 2. `ACK_SESSION_INIT` `0x01` 与握手

| 项 | 内容 |
| --- | --- |
| 触发 | 只应答 `CMD_SESSION_INIT`（`0xC0`，`SEQ=0`） |
| PAYLOAD | `[status, resetDone]`：`8 bit（1 B）` + `8 bit（1 B）` |
| `resetDone` | `1` = 车端复位过（App 需清空 SEQ 窗口与待确认队列）；`0` = 未复位 |
| 成功 | `status ∈ {0, 3}`，App 打开 DAT 解析、开始发命令 |
| 失败 | `status = 5`（版本不匹配）等：App **关闭 DAT 解析**，提示升级，不发运动命令 |

握手时序：

```
App                                  车
 |  CMD_SESSION_INIT (SEQ=0, ver=20)  |
 |----------------------------------->|
 |         ACK_SESSION_INIT           |
 |<-----------------------------------|
 |         DAT_INFO_* 一轮             |
 |<-----------------------------------|
 |  之后才允许普通 CMD                 |
```

- 版本判定**严格相等**（当前 `20`），不做向下兼容。
- 握手失败后 App 仍可读 LOG/ACK，但不得把 DAT 当本协议解析。

## 3. `ACK_ERROR` `0x10`

| 项 | 内容 |
| --- | --- |
| 状态 | **已定义、当前不发**（固件保留能力） |
| PAYLOAD | `[cmdType, errorCode]` |
| 语义 | 与 `ACK_RESULT` 的 `status=5` 不重复：`ACK_ERROR` 用于**协议级/链路级错误**，`ACK_RESULT+5` 用于**命令执行错误** |
| App | 按长度表接收；能显示 `错误码 X（命令 0xYY）`，不能崩、不能静默丢弃 |

错误码取值**尚未定义**（见第 7 节待确认）。在定义前，App 显示原始十进制即可。

## 4. 状态码表

| 值 | 名称 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 0 | `ACK_ST_RECEIVED` | 已收到，处理中 | 异步命令（录音、切换模式） |
| 1 | `ACK_ST_YES` | 有 / 是 | `CMD_QUERY_SEQ` 命中；音量设置成功 |
| 2 | `ACK_ST_NO` | 无 / 否 | `CMD_QUERY_SEQ` 未命中 |
| 3 | `ACK_ST_DONE` | 已完成 | 运动命令执行、录音完成 |
| 4 | `ACK_ST_UNKNOWN` | 无法识别 | 未实现命令（`0xD3`/`0xE7`/`0xE8`） |
| 5 | `ACK_ST_ERROR` | 参数或执行错误 | 模式值非法、录音时长越界、握手版本不匹配 |
| 6 | `ACK_ST_CANNOT` | 硬件不支持 | 无云台、无音频、无横移机构 |

规则：

- 一个命令**只回一条** `ACK_RESULT`；异步命令先回 `0`，完成后再回 `3`（同一 SEQ，可两条）。
- `4` 不等于协议错误：它是「命令已登记但未实现」的明确回复。
- 未登记 TYPE 不回 `4`，而是**完全不回**（见第 6 节）。

## 6. 未登记 TYPE 与超时

| 情况 | 车端行为 | App 行为 |
| --- | --- | --- |
| 未登记 CMD TYPE | **整帧静默丢弃，不回 ACK** | 局域网 4 s / 公网 6 s 超时，标记「超时无应答」，**不自动重发** |
| 已登记但未实现 | 回 `ACK_RESULT` + `4` | 提示「设备不支持该命令」 |
| 参数非法 | 回 `ACK_RESULT` + `5` | 提示参数错误，不重试 |
| 方向非法 CMD（App 收到） | — | 回 `ACK_RESULT` + `5` 后丢弃 |

超时是**唯一兜底**：不能死等，也不能靠重发解决（重发会造成重复执行风险）。

## 7. 完整帧示例

| 场景 | 帧（含 CRC） |
| --- | --- |
| 握手成功（SEQ=0，resetDone=0） | `AA 00 01 03 00 7A` |
| `CMD_STOP` 的应答（SEQ=33） | `AA 21 00 E0 03 BC` |
| `CMD_SELECT_MODE` 已收到（SEQ=42） | `AA 2A 00 C3 00 AE` |
| `CMD_SELECT_MODE` 非法值（SEQ=0） | `AA 00 10 C3 05 45` |

> CRC 均为 CRC-8/ATM 实算值。
