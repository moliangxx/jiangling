# 江灵通信协议 · 数据（DAT）

> 本文件是五份中的第 5 份，只写 **DAT**：车 → App。
> 权威目录：`d:\Esp32Project\index\江灵通信协议\`。
> 条目与长度全部取自固件 `Protocol.h` / `BLE.cpp`（`sendDatIfDue()`、`sendDatMemIfDue()`、
> `sendDeviceInfoRound()`、`sendDatRequest()`），不是示例值。
>
> 字段位宽统一写 `8 bit（1 B）`；`1 B = 8 bit`；`u16` = `16 bit（2 B）`、`u32` = `32 bit（4 B）`，多字节一律**大端**。
> 数值书写：TYPE、原始字节用十六进制；长度、字段值、SEQ 用十进制。

---

## 0. 方向与定位

| 项 | 约定 |
| --- | --- |
| 方向 | **只能 车 → App**；车端收到 DAT 帧静默丢弃 |
| 用途 | 上报**测量值与静态信息**（电压、轮速、版本、电源、存储、内存、板端请求） |
| 与 LOG 的区别 | 周期性/可量化 → DAT；一次性事件/错误 → LOG（见 `日志.md`） |
| ACK | **DAT 不产生、也不需要 ACK**；App 不得对 DAT 回任何帧 |
| 链路 | BLE / WiFi 近程 / WiFi 远程同一套定义，同帧同表 |

## 1. 节拍与 SEQ 去重

| 项 | 规则 |
| --- | --- |
| 帧格式 | `AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN；帧长 = `3 + 查表长度 + 1` |
| SEQ | 全部 DAT 帧共用**一个** 8 位计数器，与 CMD/ACK 同一个 App 侧全局计数器方向相反：这里是车端计数器 |
| SEQ 归零 | **只在设备重启时归零**（含 `CMD_SELECT_MODE` 触发的重启）；握手与断连重连**不重置** |
| 去重 | App 按 SEQ 去重（保留最近 64 条）；车端不重发、不补帧 |
| 发送前提 | 已连接 **且** 已完成 `CMD_SESSION_INIT`；未握手时车端不发任何 DAT |
| 分片 | BLE 下按 20 B 一片 notify；`DAT_INFO_VERSION` 整帧 24 B 拆成 20 + 4 两片。WiFi 是字节流，不需要按片重装，但仍按「第 3 字节 TYPE 定帧长」重组 |
| 优先级 | LOG > DAT（ACK 最高，与 DAT 无关） |

| TYPE | 名称 | 分区/类型 | PAYLOAD | 帧长 | 节拍 / 触发 |
| --- | --- | --- | --- | --- | --- |
| `0x80` | `DAT_BAT` | 0/0 | 2 B | 6 | **多发**，500 ms |
| `0x81` | `DAT_US` | 0/1 | 2 B | 6 | **无调用点，当前不上报** |
| `0x82` | `DAT_WHEEL` | 0/2 | 4 B | 8 | **无调用点，当前不上报** |
| `0x83` | `DAT_INFO_VERSION` | 0/3 | 20 B | 24 | **单发**，握手后一轮、`CMD_REQ_INFO` 后一轮 |
| `0x84` | `DAT_INFO_POWER` | 0/4 | 5 B | 9 | **单发**，紧跟 `0x83` |
| `0x85` | `DAT_INFO_STORAGE` | 0/5 | 6 B | 10 | **单发**，紧跟 `0x84` |
| `0x90` | `DAT_MEM` | 1/0 | 16 B | 20 | **多发**，1000 ms |
| `0xA0` | `DAT_REQ` | 2/0 | 2 B | 6 | **单发**，事件驱动 |

- `DAT_BAT`（500 ms）与 `DAT_MEM`（1000 ms）是两条独立节拍，相位不对齐；共用 SEQ，正常情况下每秒约 +3。
- `DAT_INFO_*` 三帧一轮连续发出，SEQ 取连续三个值；**不做周期重发**，漏收只能用 `CMD_REQ_INFO` 补拉。
- 模式切换（重启）后 SEQ 归零，App 的去重表必须同步清空，否则新 SEQ 会被误判为重复。

## 2. 状态上报（分区 0）

### 2.1 `DAT_BAT` — TYPE `0x80`

| 项 | 值 |
| --- | --- |
| TYPE | `0x80` = DAT(2) \| 分区 0 \| 类型 0 |
| PAYLOAD | 2 B |
| 帧长 | 6 |
| 节拍 | **多发**，500 ms |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `voltage` | `16 bit（2 B）` u16 大端 | 0.01 V | 0~65534 | `0xFFFF` = 电压无效 |

- **只报原始电压**，不报电量百分比：电量由 App 用 `DAT_INFO_POWER` 的 `cells` + `chemistry` 与电压曲线估算。
- 当前固件为**固定模拟值** `680`（6.80 V），无 ADC 采样，数值不随电量变化。App 不要把「电压不变」当故障。
- 帧内无充电标志、无状态位。

**ACK 行为**：不需要。

**示例**（6.80 V）：`AA 00 80 02 A8 5E`；电压无效：`AA 00 80 FF FF 01`。

### 2.2 `DAT_US` — TYPE `0x81`（已实现、当前不上报）

| 项 | 值 |
| --- | --- |
| TYPE | `0x81` = DAT(2) \| 分区 0 \| 类型 1 |
| PAYLOAD | 2 B |
| 帧长 | 6 |
| 状态 | **编码已实现，固件无调用点**（本车无超声波） |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `distance` | `16 bit（2 B）` u16 大端 | cm | 0~65534 | `0xFFFF` = 距离无效 |

- App 解析器保留该 TYPE 的帧长（2）；收到按距离处理，**没收到不是故障**。
- 示例（仅格式，固件不产生）：`AA 07 81 00 64 17`（100 cm）。

### 2.3 `DAT_WHEEL` — TYPE `0x82`（已实现、当前不上报）

| 项 | 值 |
| --- | --- |
| TYPE | `0x82` = DAT(2) \| 分区 0 \| 类型 2 |
| PAYLOAD | 4 B |
| 帧长 | 8 |
| 状态 | **编码已实现，固件无周期调用**（本车无轮速传感器） |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 取值范围 | 无效值 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `leftRps` | `16 bit（2 B）` int16 大端 | 0.01 r/s | −32768~32767 | `0xFFFF`（−1）= 该轮无效 |
| 2~3 | `rightRps` | `16 bit（2 B）` int16 大端 | 0.01 r/s | −32768~32767 | 同上 |

- **只报轮转速**，不换算 m/s、不报速度百分比；线速度换算用 `DAT_INFO_POWER` 的 `wheelDiameter`（mm）。
- 左右独立无效：一侧无效不影响另一侧。
- 示例（仅格式，固件不产生）：`AA 10 82 01 F4 FF FF 40`（左 5.00 r/s、右无效）。

## 3. 静态信息（分区 0）

三帧成组：**`0x83 → 0x84 → 0x85`**，顺序固定；任一帧发送失败则本轮中止（后续帧不发）。

### 3.1 `DAT_INFO_VERSION` — TYPE `0x83`

| 项 | 值 |
| --- | --- |
| TYPE | `0x83` = DAT(2) \| 分区 0 \| 类型 3 |
| PAYLOAD | 20 B |
| 帧长 | 24（BLE 下 20 B + 4 B 两片） |
| 触发 | 握手成功后一轮；`CMD_REQ_INFO` 后一轮 |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 当前值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0 | `fwMajor` | `8 bit（1 B）` u8 | — | `1` | 固件主版本 |
| 1 | `fwMinor` | `8 bit（1 B）` u8 | — | `10` | 固件次版本 |
| 2 | `fwPatch` | `8 bit（1 B）` u8 | — | `0` | 补丁号 |
| 3 | `protocol` | `8 bit（1 B）` u8 | — | `20` | **等于 `PROTOCOL_VERSION`**，必须与 `CMD_SESSION_INIT` 一致 |
| 4~19 | `model` | 16 B ASCII | — | `JiangLing-AI`（11 B）+ 5 × `0x00` | 固定 16 B、右补 `0x00`；不得含中文、不截断 |

- 型号字段整体 **16 B（128 bit）**，不是变长；App 按「遇 `0x00` 截止」解析后补空。
- 三个 `DAT_INFO_*` 的 PAYLOAD **不再有子类型字节**，长度就是 20 / 5 / 6。

**示例**：`AA 01 83 01 0A 00 14 4C 69 6E 67 59 75 61 6E 2D 41 49 00 00 00 00 00 60`
（`01` 主版本、`0A` 次版本、`00` 补丁、`14` = 20、随后 `JiangLing-AI` 与 5 个 `0x00`）。

### 3.2 `DAT_INFO_POWER` — TYPE `0x84`

| 项 | 值 |
| --- | --- |
| TYPE | `0x84` = DAT(2) \| 分区 0 \| 类型 4 |
| PAYLOAD | 5 B |
| 帧长 | 9 |
| 触发 | 紧跟 `0x83` |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 当前值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0 | `cells` | `8 bit（1 B）` u8 | 节 | `2` | 2S；未知填 `0` |
| 1 | `chemistry` | `8 bit（1 B）` u8 | — | `0` | `0` = 锂离子；其他值 App 按未知处理 |
| 2~3 | `wheelDiameter` | `16 bit（2 B）` u16 大端 | mm | `68`（`0x0044`） | 只报 mm，线速度由 App 换算 |
| 4 | `maxGearPercent` | `8 bit（1 B）` u8 | % | `100` | **最高速度百分比**，不是挡数 |

- `maxGearPercent` 是满量程百分比：App 的「挡位」应映射成 `0~maxGearPercent`，不要当挡位序号。
- `wheelDiameter` 示例：`00 44` = 68 mm（大端，高字节在前）。

**示例**：`AA 02 84 02 00 00 44 64 6E`。

### 3.3 `DAT_INFO_STORAGE` — TYPE `0x85`

| 项 | 值 |
| --- | --- |
| TYPE | `0x85` = DAT(2) \| 分区 0 \| 类型 5 |
| PAYLOAD | 6 B |
| 帧长 | 10 |
| 触发 | 紧跟 `0x84` |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 当前值（N16R8） | 无效值 |
| --- | --- | --- | --- | --- | --- |
| 0~1 | `flashMb` | `16 bit（2 B）` u16 大端 | MB | `16`（`0x0010`） | `0xFFFF` = 无法读取 |
| 2~3 | `psramKb` | `16 bit（2 B）` u16 大端 | KB | `8192`（`0x2000`） | `0` = 无 PSRAM（**不是** `0xFFFF`） |
| 4~5 | `capabilities` | `16 bit（2 B）` u16 大端位图 | — | `4`（bit2） | `0` = 无能力声明 |

**能力位**（仅低 7 位有定义，未定义位一律忽略）

| 位 | 值 | 名称 | 本板 |
| --- | --- | --- | --- |
| 0 | 1 | `CAP_VOICE` | 否 |
| 1 | 2 | `CAP_GIMBAL` | 否 |
| 2 | 4 | `CAP_DISPLAY` | **是** |
| 3 | 8 | `CAP_US` | 否 |
| 4 | 16 | `CAP_CAMERA` | 否 |
| 5 | 32 | `CAP_IMU` | 否 |
| 6 | 64 | `CAP_MECANUM` | 否（差速轮） |

**示例**：`AA 03 85 00 10 20 00 00 04 FF`。

## 4. 统计 `DAT_MEM` — TYPE `0x90`

| 项 | 值 |
| --- | --- |
| TYPE | `0x90` = DAT(2) \| 分区 1 \| 类型 0 |
| PAYLOAD | 16 B |
| 帧长 | 20（BLE 下正好一个 20 B notify） |
| 节拍 | **多发**，1000 ms |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 单位 | 含义 |
| --- | --- | --- | --- | --- |
| 0~1 | `ramFree` | `16 bit（2 B）` u16 大端 | KB | 当前内部 RAM 空闲 |
| 2~3 | `psramFree` | `16 bit（2 B）` u16 大端 | KB | 当前 PSRAM 空闲；`0xFFFF` = 无 PSRAM |
| 4~5 | `ramMinFree` | `16 bit（2 B）` u16 大端 | KB | 上电以来 RAM 最低空闲 |
| 6~7 | `psramMinFree` | `16 bit（2 B）` u16 大端 | KB | 上电以来 PSRAM 最低空闲；`0xFFFF` = 无 PSRAM |
| 8~9 | `uptimeHigh` | `16 bit（2 B）` u16 大端 | — | 运行秒数高 16 位 |
| 10~11 | `uptimeLow` | `16 bit（2 B）` u16 大端 | — | 运行秒数低 16 位 |
| 12 | `logPending` | `8 bit（1 B）` u8 | 条 | 待出队日志条数；`255` = 饱和（真实值更大） |
| 13 | `logQueueDepth` | `8 bit（1 B）` u8 | — | 固定 `255` = **该字段恒无效**（DAT 通道无队列） |
| 14~15 | `logDropped` | `16 bit（2 B）` u16 大端 | 条 | 上电后累计丢弃条数；`65534` = 饱和；`0xFFFF` 不出现 |

- 运行秒数是**一个 32 位量的两段**：`uptime = (uptimeHigh << 16) | uptimeLow`，不是两个独立量。
- 容量换算：字节 / 1024 取整；超过 65534 KB 一律写 `65534`（保留 `65535` 给「无效」）。
- 字节 13 在 App 必须显示「无效」，不能显示 255 条。

**示例**（RAM 空闲 256 KB、PSRAM 4096 KB、RAM 最低 160 KB、PSRAM 最低 128 KB、运行 0 s、待发 4 条、丢 3 条）：

```text
AA 04 90 01 00 10 00 00 A0 00 80 00 00 00 00 04 FF 00 03 B6
```

## 5. 请求 `DAT_REQ` — TYPE `0xA0`

| 项 | 值 |
| --- | --- |
| TYPE | `0xA0` = DAT(2) \| 分区 2 \| 类型 0 |
| 方向 | **车 → App**（板端请求 App 执行动作；车端永不发 CMD） |
| PAYLOAD | 2 B |
| 帧长 | 6 |
| 触发 | **单发**，事件驱动；需已握手，否则直接拒绝不发帧 |

| 偏移 (B) | 字段 | 类型（1 B = 8 bit） | 取值 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | `code` | `8 bit（1 B）` u8 | 1~10 | `0` 或 `>10`：车端拒绝整条请求，**不发帧** |
| 1 | `param` | `8 bit（1 B）` u8 | 随 `code` | 越界由车端**静默裁剪到上限**（全协议唯一裁剪点） |

| `code` | 含义 | `param` | App 应映射的 CMD |
| --- | --- | --- | --- |
| 1 | 请求停车 | 无（强制 `0`） | `CMD_STOP 0xE0` |
| 2 | **请求录音** | 无（强制 `0`） | `CMD_RECORD 0xD2`（秒数按 App 策略） |
| 3 | 请求左横移 | `0~100` | `CMD_LEFT_SHIFT 0xE7`（未实现） |
| 4 | 请求右横移 | `0~100` | `CMD_RIGHT_SHIFT 0xE8`（未实现） |
| 5 | 请求云台俯仰 | `0~255` | `CMD_PITCH 0xE5` |
| 6 | 请求云台偏航 | `0~255` | `CMD_YAW 0xE6` |
| 7 | 请求前进 | `0~100` | `CMD_FORWARD 0xE1` |
| 8 | 请求后退 | `0~100` | `CMD_BACK 0xE2` |
| 9 | 请求左转 | `0~100` | `CMD_LEFT 0xE3` |
| 10 | 请求右转 | `0~100` | `CMD_RIGHT 0xE4` |

**App 响应规则**

1. 按 `code` 映射成对应 CMD，`param` 作为参数；
2. 用**新的 SEQ**（`1~255`）发送该 CMD，等待 `ACK_RESULT`；
3. **不对 `DAT_REQ` 本身回 ACK**（ACK 只对应 CMD）。

**当前实际发送情况**

- 固件只有 `requestRecording()` 一个调用点，固定 `code=2`、`param=0`；
- 其余 `code` 有编码与裁剪路径，但**当前无调用点**（协议已定义、固件暂不产生）；
- `code=3/4`（横移）映射后只会得到 `ACK_ST_UNKNOWN(4)`，本车是差速轮。

**拒绝路径**（不发帧，只写 LOG `模块 3 数据`）

| 条件 | LOG |
| --- | --- |
| 未连接 / 未握手 / TX 不可用 | `W/DAT 事件码 2`（请求被拒绝） |
| `code` 不在 1~10 | `W/DAT 事件码 3`（请求码未知） |

**示例**：请求录音 `AA 05 A0 02 00 02`；左横移 50（仅格式、当前无调用点）`AA 05 A0 03 32 89`。

## 6. 字节序、无效值与单位

| 约定 | 内容 |
| --- | --- |
| 大小端 | 所有 `u16` / `int16` **一律大端**（高字节在前）；不存在小端字段 |
| 定点数 | 电压 `0.01 V`、轮速 `0.01 r/s`、轮径 `mm`、距离 `cm` |
| 无符号无效 | `0xFFFF`（65535） |
| 有符号无效 | `0xFFFF`（即 −1） |
| 饱和值 | 内存/计数类饱和到 `65534`，保留 `65535` 给无效；`u8` 饱和到 `254`，保留 `255` 给无效 |
| 百分比 | 一律 `0~100` 整数，无小数 |
| 单位换算 | 固件只发原始量，换算与显示全部由 App 完成 |
| 电量 | 固件不提供百分比；App 用 `voltage` + `cells` + `chemistry` 估算 |

## 7. 完整帧示例

CRC 均为 CRC-8/ATM 实算（多项式 `0x07`、初值 `0x00`、覆盖 `AA` 到最后一个 PAYLOAD 字节）。

| 场景 | 帧（含 CRC） |
| --- | --- |
| `DAT_BAT` 6.80 V | `AA 00 80 02 A8 5E` |
| `DAT_BAT` 电压无效 | `AA 00 80 FF FF 01` |
| `DAT_INFO_VERSION` | `AA 01 83 01 0A 00 14 4C 69 6E 67 59 75 61 6E 2D 41 49 00 00 00 00 00 60` |
| `DAT_INFO_POWER` | `AA 02 84 02 00 00 44 64 6E` |
| `DAT_INFO_STORAGE` | `AA 03 85 00 10 20 00 00 04 FF` |
| `DAT_MEM` | `AA 04 90 01 00 10 00 00 A0 00 80 00 00 00 00 04 FF 00 03 B6` |
| `DAT_REQ` 请求录音 | `AA 05 A0 02 00 02` |

SEQ 均为示例值；实际 SEQ 以帧内为准，App 只按帧内 SEQ 去重。

## 8. 待确认

1. `DAT_INFO_VERSION` 型号 16 B 的字符集与 trim：当前按 **ASCII + 遇 `0x00` 截止**；是否允许非 ASCII / 是否需要全局 trim。
2. `DAT_US` / `DAT_WHEEL` 的启用条件与单位：当前固件无调用点，启用后是否需要改单位或加新字段。
3. 电量百分比曲线：由 App 估算，但锂离子 2S 的电压→百分比标定表尚未定稿。
4. 远程（公网）链路下 `DAT_BAT 500 ms` / `DAT_MEM 1000 ms` 是否降频：公网流量与实时性取舍未定。
