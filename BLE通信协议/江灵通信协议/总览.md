## 0. 名词与书写约定

| 名词 | 含义 |
| --- | --- |
| ctrl 通道 | 承载 CMD / ACK / LOG / DAT 帧的控制通道（BLE 或 WiFi 都走它） |
| 近程 | 手机与车在同一局域网（路由器 / 热点），不经公网 |
| 远程 | 手机与车不在同一局域网，经云端 relay 或设备 4G 直连 |
| AI 通道 | 独立的语音上行 / 语音+文字下行通道，**不属于 ctrl** |
| 播报完成 | 设备本地判定「本轮 TTS 音频已播完」（I2S 缓冲排空 / 播放回调），不是云端事件 |

- TYPE、帧头、原始字节用**十六进制**（`0xC3`）；参数、状态码、SEQ 用**十进制**。
- 字段位宽统一写 `8 bit（1 B）`；`1 B = 8 bit`；多字节一律**大端**。
- TYPE 是**整字节语义编号**，`KIND(2) + 分区(2) + 类型(4)` 只是编号规则，不改变「一个字节一个语义」的事实。

## 1. 三条链路总览

```
                ┌──────────────────────────── 车端 ESP32-S3 ────────────────────────────┐
                │                                                                        │
   BLE ─────────┤ ctrl：CMD/ACK/LOG/DAT（NUS，广播 15 s）                                 │
                │                                                                        │
   近程 WiFi ───┤ ctrl：TCP 8080（同一套帧）   video：WS 81   audio：WSS 8443            │
   远程 WiFi ───┤ ctrl/video/audio：WSS 443（relay 转发，设备始终出站）                    │
                │                                                                        │
   AI ──────────┤ audio 通道：上行语音 / 下行语音 + 文字（独立，不占 ctrl 的 SEQ）          │
                └────────────────────────────────────────────────────────────────────────┘
```

| 链路 | 承载内容 | 是否可跑视频 | 是否可跑 AI | 命令协议 |
| --- | --- | --- | --- | --- |
| 蓝牙（BLE） | CMD / ACK / LOG / DAT | **否** | **否** | 江灵帧（与 WiFi 同一套） |
| WiFi 近程 | CMD / ACK / LOG / DAT + 视频 + AI | **是** | **是** | 江灵帧 |
| WiFi 远程 | CMD / ACK / LOG / DAT + 按需视频 + 远程对讲 | 按需拉流 | **否**（远程模式关 AI） | 江灵帧 |
| AI 通道 | 上行语音、下行语音+文字 | 否 | 是 | **不走 ctrl 帧**，独立消息集 |

**一句话边界**：BLE 只承载控制面四类帧；视频始终走 WiFi；AI 是独立语音通道且依附 WiFi。

## 2. 蓝牙（BLE）

### 2.1 职责边界

- **只承载 CMD / ACK / LOG / DAT**，不承载视频，不承载 AI。
- 帧格式与 WiFi 完全相同：`AA | SEQ | TYPE | PAYLOAD | CRC8`，无 LEN，长度查 TYPE 静态表。
- 方向强制：CMD 只能 App→车；ACK / LOG / DAT 只能车→App；唯一例外是收到方向非法的 CMD 时回一条错误 ACK。

### 2.2 连接与广播

| 项 | 值 |
| --- | --- |
| 蓝牙名 | `JiangLing` |
| 服务 | Nordic UART Service（NUS） |
| 服务 UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX（App 写入） | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX（App 订阅） | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |
| 角色 | 手机 = Central，车 = Peripheral |
| 广播窗口 | **上电/重启后广播 15 s；窗口内无连接即关闭蓝牙** |
| MTU | 默认 23，连接后协商 247；单次写入 ≤ `MTU-3` |
| 半帧超时 | 1 s |

**15 s 窗口的含义**：App 必须在窗口内完成连接，并在连上后立刻下发 `CMD_SESSION_INIT`（`SEQ=0`）建会话；窗口结束仍未连接，车端关闭蓝牙射频，只能通过**模式切换 + 重启**重新打开（见 3.4）。

### 2.3 与 WiFi 共用同一套协议

| 项 | 约定 |
| --- | --- |
| TYPE 表 | **同一张**，不因链路不同而变（BLE / 近程 / 远程完全一致） |
| 帧格式 | 同一套 `AA | SEQ | TYPE | PAYLOAD | CRC8` |
| SEQ | 同一套规则：App 侧单一全局计数器；**`SEQ=0` 免去重**，用于幂等/状态类命令 |
| 去重表 | 车端只有一份 64 条环，BLE 与 WiFi 共用 |
| 解析 | 同一个 `FrameCodec`：扫 `0xAA` → 查长度表 → CRC8；未知 TYPE 整帧丢弃、逐字节重扫 |
| 差异 | 只有传输层（BLE 通知分片 vs TCP 流），应用层零差异 |

### 2.4 切回蓝牙模式 = 模式切换 + 重启

**不再设计**「按键 / 摇晃 / 单独的重开广播命令」：

1. App 发 `CMD_SELECT_MODE`（`0xC3`，参数 `0` = 蓝牙），`SEQ=0`；
2. 车端**先回 ACK**（`ACK_ST_RECEIVED`），随后重启；
3. 重启后按持久化的模式初始化，蓝牙模式即重新开始 15 s 广播；
4. App 在新会话内重新握手（`CMD_SESSION_INIT`）。

> 若没有持久化，重启会回落到默认蓝牙模式，「切到 WiFi」将永远不生效。持久化到 NVS 是**必要设计**（【推导·必要设计】）。

## 3. WiFi

### 3.1 近程（局域网）

| 通道 | 内容 | 端口/协议 | 优先级 |
| --- | --- | --- | --- |
| ctrl | CMD / ACK / LOG / DAT（江灵帧） | TCP **8080** | 2 |
| video | 单帧 JPEG 流 | WS **81** | 3（最低） |
| audio | PCM/Opus 音频块 + 文字 side-channel | WSS **8443** | 1（最高） |

- 命令与 BLE **完全同帧**：TCP 字节流里直接扫 `0xAA`、查表、校验 CRC8，不需要额外分帧。
- 视频**始终走 WiFi**：蓝牙模式下没有可用视频链路，App 不显示视频入口。

### 3.2 远程（公网）

| 项 | 约定 |
| --- | --- |
| 入口 | 仅 **443 / WSS**，公网只暴露一个端口 |
| 拓扑 | 设备与 App **都出站**连 relay，relay 只做鉴权、1:1 配对、限速、字节透传，**不解析协议** |
| 通道 | ctrl / video / audio 三条独立 TLS，互不拖累 |
| 设备寻址 | 由 `devId` 决定，不用 IP；换网络（WiFi↔4G）App 无感 |
| 4G 直连 | 设备带 Cat.1 时可直接出站，业务层零改动（二期） |
| 鉴权 | TLS 内首条消息 `devId + ts + nonce + HMAC-SHA256`；时间窗 ±60 s、nonce 去重 |
| 心跳 | WS ping 15 s；App 30 s 收不到任何 DAT/ACK 判离线；设备 45 s 无上行成功主动重连 |
| 重连退避 | 1 / 2 / 4 / 8 / 15 / 30 s，±20% 抖动 |
| ACK 超时 | 局域网 4 s；公网 6 s（P99 往返 + relay 抖动） |
| 独占租约 | 同一 `devId` 同时只允许一个 App 持 ctrl 通道 |

### 3.3 App 的两种模式差异

| 能力 | 蓝牙模式 | WiFi 模式（近程/远程） |
| --- | --- | --- |
| CMD / ACK / LOG / DAT | 有 | 有 |
| 视频 | **无**（不显示入口） | 有（远程按需拉流） |
| AI 语音问答 | **无**（无 IP） | 有（仅近程；远程模式关 AI） |
| 远程对讲 | 无 | 有（仅远程） |
| 距离 | 约 10 m 内 | 同一局域网 / 任意公网 |

**模式矩阵一句话**：蓝牙模式 = 只有控制面；WiFi 模式 = 控制面 + 视频 + AI（远程模式下 AI 关闭）。

### 3.4 模式切换规则

**模式选择命令（已拍板）**

| 项 | 值 |
| --- | --- |
| TYPE | `0xC3` `CMD_SELECT_MODE`（占用原「语音预留」位，见 `命令.md`） |
| PAYLOAD | `mode` u8：`0` = 蓝牙，`1` = WiFi 近程，`2` = WiFi 远程 |
| SEQ | **`SEQ=0`**（免去重，可重发） |
| 时序 | 车端**先回 ACK，再重启** |
| 非法值 | 回 `ACK_ST_ERROR(5)`，**不重启** |
| 默认 | 蓝牙 |
| 持久化 | NVS；重启后按 NVS 中的模式初始化（【推导·必要设计】） |

**重启后的初始化**

| 模式 | 初始化动作 |
| --- | --- |
| 0 蓝牙 | 开广播 **15 s**；App 需在窗口内连上并下发 `CMD_SESSION_INIT` |
| 1 WiFi 近程 | 连路由器（凭据见 `命令.md` 待确认项），起 ctrl 8080 / video 81 / audio 8443 |
| 2 WiFi 远程 | 连 relay 443（或 4G 直连），完成 AUTH 后起三条 WSS |

**连贯性处理（App 侧必须遵守）**

1. 发出切换命令后立即进入「等待重启」状态：停止发运动命令，清空**未发送**队列；
2. 重启副作用：**SEQ 归零、去重表清空、会话标志重建**——App 侧新会话的 SEQ 从 1 重新开始，不复用旧值；
3. 未确认队列（已发未 ACK）**不跨模式重发**，统一标记「会话已重置」；
4. 重新连上后第一帧固定 `CMD_SESSION_INIT`（`SEQ=0`，版本 20），握手成功后才恢复 DAT 解析与命令发送；
5. 缓冲：BLE 通知缓冲与 WiFi 读缓冲**不跨模式复用**，切换即释放。

## 4. AI 通道（独立）

### 4.1 独立性

- AI 是**独立通道**，与 ctrl / video **互不干扰**；
- **不占用 ctrl 的命令 SEQ**，也不读写车端的 64 条去重环；
- 音频怕队头阻塞：不复用 ctrl 连接，不塞进 video 流。

### 4.2 上行与下行

| 方向 | 内容 | 规格 |
| --- | --- | --- |
| 上行 | 设备麦克风语音流 | PCM16 单声道 16 kHz / 16 bit，20 ms = 640 B；远程优先 Opus 24–32 kbps |
| 下行 | AI 回复**语音 + 文字** | 文字 = 喂给 TTS 的同一段文本（同源），按句下发；音频 20 ms/块 |
| 对齐 | `utteranceId + sentenceIndex` 把同一轮的音频与文本关联，不要求同帧到达 | |

- 文字与 TTS 输入同源：收到文本即可上屏，收到音频即播，**字幕与语音逐字一致**。
- 文本消息不得阻塞音频发送路径；发不出去就丢（字幕可补）。

### 4.3 唤醒词与问答边界

| 项 | 约定 |
| --- | --- |
| 麦克风 | **常开**，但只做**本地唤醒词检测**（`WakeNet` 一类），不上传、不联网 |
| 唤醒词来源 | **App 端配置**：写入设备（建议落 NVS），配置通道见 `命令.md` 待确认项 |
| 生效时机 | 写入成功并**重启 / 下一次 AI 会话开始时**生效（不热切正在进行的会话） |
| 问答范围 | **只有唤醒后才开始向云端推流**；未唤醒不产生任何上行流量 |
| 会话结束 | **30 s 内无新一轮问答**自动关闭，需重新唤醒 |

### 4.4 30 s 计时（纯设备端）

```
用户说一句 → 设备推流 → 云端 ASR/LLM/TTS → 设备收到语音+文字
                                              ↓
                          设备本地播放（I2S 缓冲排空 / 播放回调）= 「播报完成」
                                              ↓
                                     开始计时 30 s
                                              ↓
              30 s 内又检测到新一问 → 继续会话；否则关闭，等下一次唤醒
```

- **播报完成由设备本地判定**，因此 AI 通道消息集里**没有**「播报完成上报」这一条；
- 计时**从一次问答的回复语音播报完成之后**开始，不是从收到音频开始，也不是从云端返回开始；
- 30 s 内 App 只能看到字幕/状态，不参与计时。

### 4.5 AI 依附 WiFi，App 不参与

- AI **只在 WiFi 联网时可用**；蓝牙模式下设备没有 IP，**AI 不可用**（界面显示「需 WiFi」）。
- **AI 全设备侧完成**：麦克风采集、唤醒、推流、播放、30 s 计时都在设备上。
- **App 不推流、不调 AI 接口**（后续可扩展为 App 侧发起，属未来范围，不在本版）。
- **远程模式关闭 AI**，只保留远程对讲；两者互斥，切换时 AI 会话直接终止（见 5.1）。

## 5. 远程操控模式

### 5.1 开关与互斥

| 项 | 约定 |
| --- | --- |
| 开关 | App 端**单独开关**，与「AI 问答」互斥 |
| 开启后 | **AI 对话关闭**（AI 会话立即终止；唤醒词检测可停用），只保留远程通话 |
| 命令 | 远程命令**复用同一协议**（同一 TYPE 表 / 帧 / SEQ） |
| 与 AI 推流的区别 | 远程对讲是「人对人」，AI 是「人对助手」；**两条语音用途不要混写**，远程模式不产生 AI 上行 |

### 5.2 双向对讲

- App 可推**纯语音流**，板子也可推语音，实现双向对讲；
- 语音走 audio 通道（远程 WSS 443），命令仍走 ctrl；
- 板端语音可由喇叭输出，App 端语音由手机输出。

### 5.3 双向对讲的约束

| 约束 | 说明 | 取舍建议 |
| --- | --- | --- |
| 麦克风常开 | 对讲期间两端麦克风都在采集 | 仅在远程模式开启时打开，退出即关 |
| 回声消除（AEC） | 板端喇叭出声会被本机麦克风拾回，形成回声 | 一期**半双工**；二期上 AEC 再做全双工 |
| 半双工 | 同一时刻只允许一个方向说话（按键说话/自动让路） | **一期推荐**：实现简单、无回声风险 |
| 全双工 | 两端同时说同时听 | 必须有 AEC + 抖动缓冲，否则体验不可接受 |
| 抖动缓冲 | 公网延迟抖动 100–300 ms | 30–80 ms 缓冲；过大增加延迟 |
| 弱网降级 | 上行切 Opus 低码率，视频降 QVGA 5 fps | 保语音优先 |

## 6. 协议共性速查

| 项 | 值 |
| --- | --- |
| 帧头 | `0xAA`，1 B |
| 帧结构 | `AA | SEQ | TYPE | PAYLOAD | CRC8` |
| LEN | **不存在**；帧长 = `3 + 查表长度 + 1` |
| CRC | CRC-8/ATM（`0x07`，初值 `0x00`），覆盖 `AA` 到最后一个 PAYLOAD 字节 |
| TYPE | `KIND(2) + 分区(2) + 类型(4)`，共 256 个 |
| KIND | `00`=ACK、`01`=LOG、`10`=DAT、`11`=CMD |
| LOG | 19 B 定长：`AA | SEQ | 8×[TYPE+参数] | CRC8` |
| 协议版本 | `20`（`CMD_SESSION_INIT` 的 PAYLOAD） |
| 未知 TYPE | 整帧丢弃，逐字节重扫 `0xAA`，**不回任何帧** |
| 未登记 CMD | 车端**静默丢弃**，不回 ACK；App 4 s（局域网）/ 6 s（公网）超时判失败 |

## 7. 待确认

1. **唤醒词的配置命令**：TYPE、参数长度（唤醒词文本建议 ≤ 32 B）与生效时机（重启 or 下一会话）需定稿；当前只确定「App 写入设备并落 NVS」。
2. **WiFi 凭据下发命令**：SSID + 密码建议单独 TYPE（不占运动/音频分区），与唤醒词配置同通道；TYPE 待定。
3. **模式切换 ACK 与重启的时序**：ACK 发出后延迟多久重启（建议 ≥ 200 ms，确保通知送达）需实测。
4. **视频规格**：近程 JPEG 分辨率/帧率、远程按需拉流的触发方式，属视频文档范围，本协议不定义。
5. **AI 网关地址与鉴权细节**：沿用 `AI与网络方案`，不在本协议重复。
