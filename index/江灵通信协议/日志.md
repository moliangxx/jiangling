# 江灵通信协议 · 日志（LOG）

> 本文件只写 LOG（车 → App）。TYPE 与事件码取自固件 `Protocol.h` 与实际调用点。
> 帧结构：`AA | SEQ | 0x42（容器 TYPE） | LEN | 每条 [TYPE, LEN=1, param] | CRC8`，帧总长 `5 + LEN`。每条记录 3 B（记录 TYPE 1 B + 记录 LEN 1 B + param 1 B）；一帧**最多** 8 条，实际条数可变，`LEN = 3 × 条数`（3~24 B），**一个 SEQ 覆盖整帧**。记录左对齐、无空槽，帧第 3 字节恒为容器 TYPE `0x42`，记录的真实 TYPE 写在 PAYLOAD 内。
> 记录 TYPE 由三部分拼成：**高 2 位 KIND（`01` = LOG，固定）** + **中间 2 位等级** + **低 4 位模块**。等级位有实际语义，由固件 `makeLogType()` 拼出；模块与事件码查下表。
> `param` 是**事件码/数值**，不是等级；等级只出现在记录 TYPE 里。App 解析等级时按 `(TYPE >> 4) & 0x03` 取等级位，**不要**按 TYPE 整字节硬编码某条记录。

---

## 1. 等级编码（四级，定稿）

日志等级为 **D / I / W / E** 四级。这次调整把 **Info 从 D 里拆出来**：旧表只有 D/E/W 三档，Info 与 Debug 共用 D；现在 Info 独立占用原先预留的等级位 `11`，D 只保留 Debug。

| 等级 | 代号 | 等级位（TYPE bit5~4） | 等级位十进制值 | TYPE 基址 | 本表已用模块（0~9）的 TYPE |
| --- | --- | --- | --- | --- | --- |
| Debug | **D** | `00` | **0** | `0x40` | `0x40`~`0x49` |
| Error | **E** | `01` | **1** | `0x50` | `0x50`~`0x59` |
| Warning | **W** | `10` | **2** | `0x60` | `0x60`~`0x69` |
| Info | **I** | `11` | **3** | `0x70` | `0x70`~`0x79` |

- 等级位写死为：**D = `0x00`(0)、E = `0x01`(1)、W = `0x10`(2)、I = `0x11`(3)**；TYPE 整字节 = `0x40 | (等级位 << 4) | 模块号`。
- **为什么 I 用 `11` 而不是重排成 D/I/W/E**：D/E/W 的字节值已被 App 按下表解析（`0x50`=E、`0x60`=W），重排会让既有 E/W 记录整体位移；`11` 原本是 `LOG_ZONE_RSV` 预留位，直接启用即可，**既有记录的字节值一个都不变**，只新增 `0x70` 系列。
- 等级位与数值过滤使用同一套数值：固件 `Level` 枚举就是 `Debug=0(D) / Error=1(E) / Warning=2(W) / Info=3(I) / Fatal=4`（`Fatal` 并入 E），枚举值直接就是线路等级位；运行时「最低等级」按严重度 `D < I < W < E < F` 比较，**不按枚举数值比大小**。
- 容器 TYPE `0x42` 恒为 `KIND_LOG + D 等级位 + LOG_MOD_LOG`，**不表示任何记录的等级**，不要把它当 D 级记录。

**外网 / 双板 / 转发 / 拍照事件码**（模块同为 `LOG_MOD_SYSTEM`；等级决定 TYPE：I → `0x70`、W → `0x60`）

| param | 名称 | 含义 | 等级 / TYPE |
| --- | --- | --- | --- |
| `0x36` | `PEER_LOG_AI_OFF_NO_INTERNET` | 外网探测判离线，**AI 总开关被关闭**（停采集、丢 AI 音频、唤醒词失效）；**每次跳变只记一条**，不按探测周期刷屏 | I / `0x70` |
| `0x37` | `PEER_LOG_AI_ON_INTERNET_BACK` | 外网恢复，AI 重新允许（总开关置开），AI 停留 `AI_IDLE` **待唤醒**，不自动进入会话 | I / `0x70` |
| `0x38` | `PEER_LOG_PEER_BACK` | 副板心跳恢复 / 视频源上线（收到 `0xF4` 端点），推 `0x88 state=1` | I / `0x70` |
| `0x39` | `PEER_LOG_PEER_LOST` | 副板离线（600 ms 无有效板间帧），主板进 `S8`；控制与 AI 不受影响 | W / `0x60` |
| `0x3A` | `PEER_LOG_PEER_TIMEOUT` | 板间帧（`0xF0` 配置 / `0xF1` 命令）3 次重传后仍无 `0xF2`；转发命令超时回 `ACK 5`、拍照回 `0x02 err=7` | W / `0x60` |
| `0x3B` | `PEER_LOG_PEER_FRAME_BAD` | 板间帧 CRC 错、`LEN` 越界、TYPE 未知，**整帧丢弃**并重扫 `0xAA` | W / `0x60` |
| `0x3C` | — | **空闲**（预留，不分配） | — |
| `0x3D` | `PEER_LOG_PHOTO_FAIL` | 拍照失败或超时（对焦 / 内存 / JPEG 编码 / 副板忙 / 串口超时），与 `0x02 ACK_PHOTO.err` 对应 | W / `0x60` |

- `0x36` / `0x37` 与 WiFi 的 `0x26` / `0x27` 分工：`0x26`/`0x27` 是**探测动作本身**的结果（每次探测都可能记），`0x36`/`0x37` 是**AI 总开关的跳变**（只在开关翻转时记一条）。
- `0x3A` 与 `0x3B` 的区别：前者是「帧合法但副板没回」，后者是「帧在链路上就坏了」；排障时先看 `0x3B`。
- `0x3D` 只记**终态失败**；`0xCC` 的两段 ACK 中第一段 `ACK 0` 不产生日志。
- **一个事件码只对应一个等级**：同一 param 不允许在两个等级下出现（如 `0x27` 统一为 I，不再有 W 版本）。
- 参数码段：`0x01~0x1F` 事件码；`0x20~0x7F` 数值/码段（已停用的 BLE 码段 `0x20+n`/`0x30+n`、WiFi 的 `0x20~0x35`、双板的 `0x36~0x3D` 均落在此段）；`0x80~0xFF` 预留。
- 队列 64 条、满时丢新；「未满→满」一次性提示 `0x62 / 0x01`，不占队列。在线每 20 ms 最多一帧，不足 8 条时按实际条数封帧（`LEN = 3 × 条数`）；离线进 32 帧补发环（30 s 时效），**仅 W/E 记录入环，D/I 丢弃**。
- 日志队列满与 DAT 队列满复用同一个码 `0x62 / param=0x01`，**App 无法区分来源**。
- 车端 LOG 计数器单调 +1、不去重；App 按 SEQ 维护窗口去重。模块 6 与 10~15 无事件码，表中未出现的类型固件不产生。
