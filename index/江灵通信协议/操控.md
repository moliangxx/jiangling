# 江灵操控与运动命令 · 设计文档（定稿 2026-11-11 · 差速轮盘）

> 本文是**独立设计文档**，不属于五份协议分册；它在 `命令.md` 的落点是 `0xEB CMD_MOVE_VECTOR`（差速两分量）与 `0xEC CMD_GIMBAL_VECTOR`（云台两分量）两行。
> 本文解决三件事：**虚拟轮盘八方位如何落到差速车**、**流式下发的节奏与超时责任**、**App 侧的能力闸门**。
> 数值来源统一标注：**【代码】**= 从固件源码读出的既有值；**【推算】**= 由代码常量推导；**【设计】**= 本文定稿的约定值。
> 链路优先级引用《总览》：**手机语音 > AI 消息 > 普通数据 / 日志（含视频）**。

## 0. 定稿结论

1. **操控模型改为差速两分量**：`0xEB CMD_MOVE_VECTOR`，`LEN=2`，`[drive int8][turn int8]`，各 `-100`~`+100`（最大量百分比）。`drive` 正 = 前进，`turn` 正 = **左转**（俯视逆时针）。
2. **合成公式只有一套**：`左轮 = clamp(drive − turn)`、`右轮 = clamp(drive + turn)`，各自夹到 `±100`。旧 `vx/vy` 麦轮模型**作废**，不再有横向分量。
3. **轮盘八方位**：正前、正后、左前、右前、左后、右后有效；**正左、正右无效**——差速车不能横移，**App 在构造帧前拦截，不下发**。
4. **下发节奏**：按住期间约 **200 ms 一帧**（5 Hz），值不变也照发；松手**立即停发**，**不补发最后一帧**。
5. **超时自停**：车端 **300 ms** 收不到新帧即自动停车（可调常量 `MOTION_STREAM_TIMEOUT_MS`）。**App 只保证发，超时停是板子的责任**。
6. **停止最高优先**：`0xE0 CMD_STOP` 立即停、清目标、清计时，覆盖正在执行的移动与云台，不等超时。
7. **云台同样轮盘化**：`0xEC`，`LEN=2`，`[pan int8][tilt int8]`，斜向拆两轴；与移动**完全独立**（独立计时、可同时下发）。位置型 `0xE5`/`0xE6` 保留为绝对角度。
8. **App 发任何命令前过两道闸**：协议白名单 + 车端能力位（§9）。

## 1. 现状梳理：`0xE0`~`0xE8`

下表全部来自 `Protocol.h` 与 `Cmd` / `RuntimeCmd` 的实际实现。

| TYPE | 名称 | LEN | 参数 / 取值范围 | 固件实际行为 | 定位 |
| --- | --- | --- | --- | --- | --- |
| `0xE0` | `CMD_STOP` | 0 | 无参 | `stopMotion()`：目标轮速与 PWM 全清零，ACK 3 | 急停，**所有操控的收尾命令** |
| `0xE1` | `CMD_FORWARD` | 1 | `level` u8，0~100 = 最大线速度百分比；0 也须显式发送 | 两轮同向；`wheelRps = level × 5.00 r/s ÷ 100`；`PWM = level × 255 ÷ 100`；ACK 0/3 | 离散直线，保留但新 UI 不用 |
| `0xE2` | `CMD_BACK` | 1 | 同上 | 两轮反向（后退），其余同 `0xE1` | 同上 |
| `0xE3` | `CMD_LEFT` | 1 | `turn` u8，0~100 = 最大角速度百分比 | **原地左转**（两轮反向），其余同 `0xE1` | 同上 |
| `0xE4` | `CMD_RIGHT` | 1 | 同上 | **原地右转** | 同上 |
| `0xE5` | `CMD_PITCH` | 1 | `angle` u8，0~255 线性映射 0°~180° | 无云台硬件，**回 `ACK_ST_CANNOT(6)`** | 位置型，见 §6.2 |
| `0xE6` | `CMD_YAW` | 1 | `angle` u8，0~255 线性映射 0°~360° | 同上，**回 `ACK_ST_CANNOT(6)`** | 位置型，见 §6.2 |
| `0xE7` | `CMD_LEFT_SHIFT` | 1 | `level` u8，0~100 | **未实现**，无分支，ACK 4 | 横移入口；差速底盘**永远不用** |
| `0xE8` | `CMD_RIGHT_SHIFT` | 1 | 同上 | **未实现**，ACK 4 | 同上 |

补充事实：

| 项 | 值 | 来源 |
| --- | --- | --- |
| 离散运动命令失联自停 | **1000 ms** 内收不到新命令即停车（`enforceMotionTimeout()`，每轮 `loop()` 检查） | 【代码】`RuntimeCmd.cpp` |
| 最大轮速 | **5.00 r/s**（0.01 r/s 单位，值 500） | 【代码】`MAX_WHEEL_RPS_HUNDREDTHS = 500` |
| PWM 满量程 | **255** | 【代码】`MOTOR_PWM_MAX = 255` |
| 轮径 | **68 mm**（只上报给 App，App 自行换算线速度） | 【代码】`WHEEL_DIAMETER_MM = 68` |
| 底盘 | **差速两轮**（左/右各一轮），能力位 `bit6`（麦轮）上报为 0 | 【代码】`applyMotionCommand()` / `CAP_DISPLAY` |
| `0xE9`/`0xEA` | 预留给万向轮原地自转，当前不实现 | 【代码】`Protocol.h` 注释 |
| 运动命令 ACK | **每条 CMD 都会回 ACK**；回复栈容量 **8 条** | 【代码】`Cmd.h: CMD_REPLY_CAPACITY = 8` |

**为什么必须改**：离散四方向 + 旧麦轮向量都不匹配现在的操控方式。新 UI 是**八方位轮盘**，而差速车只有「前后 + 转向」两个自由度，所以协议只能收两个分量，横移必须由 App 在发送前拦掉。

## 2. 方案取舍

| 维度 | 路线 A：继续用 `0xE1`~`0xE4` 量化八方向 | 路线 B：`0xEB` 两分量（定稿） |
| --- | --- | --- |
| 手感 | 45° 阶梯；斜向要连发两条，后一条会顶掉前一条（`applyMotionCommand()` 每次覆盖目标轮速） | 一条帧同时表达「前进 70% + 左转 30%」，无阶梯、无覆盖跳变 |
| 横移 | `0xE7`/`0xE8` 未实现，差速也做不到 | 协议**不提供**横向分量，App 拦掉正左/正右，语义与底盘一致 |
| 改动面 | App 侧改造，固件 0 | `Protocol.h` +2 TYPE、`payloadLengthValid()` +2 行、新增两个控制类、App 发送路径；旧命令全保留 |
| ACK 压力 | 低（方向变化才发） | 较高（5 Hz × 1 ACK/路），见 `回复.md` §1.7 |
| 兼容性 | 100% | 旧 App 不受影响，新 App 才用新 TYPE |

**结论：采用路线 B。** 理由：轮盘是连续量，量化必然产生阶梯；差速车的两个自由度正好对应两个分量，协议与底盘一对一，不在 App 或固件里做额外的意图猜测。

**为什么复用 `0xEB` 而不是再新增一个 TYPE**：`0xEB` 此前只有文档、**固件从未实现**（当时按未知 TYPE 静默丢弃），App 也没有按 `vx/vy` 发布过版本，因此把它的 PAYLOAD 重定义为差速两分量不会破坏任何在跑的客户端，比再占一个编号更干净。编号、LEN、帧长全部不变（§7.4 已记录）。

## 3. `0xEB` 差速两分量

### 3.1 字段与符号

| 项 | 值 |
| --- | --- |
| TYPE | **`0xEB` `CMD_MOVE_VECTOR`** |
| LEN | **2** |
| PAYLOAD | `[0] drive` int8、`[1] turn` int8 |
| 帧总长 | **7 B**（`5 + LEN`） |
| 取值范围 | `-100`~`+100`，单位 = 最大量的百分比 |
| `drive` 正方向 | **前进**（车头方向）；负 = 后退 |
| `turn` 正方向 | **左转**（俯视逆时针）；负 = 右转（顺时针） |
| `0 / 0` | 等价于停车（车端回 `ACK 3`） |
| 超范围 | 车端夹到 `±100`，**不报错**（保持 5 Hz 推送不中断） |
| 坐标系 | 右手系，`z` 轴向上，绕 `z` 逆时针为正 —— 与 `turn` 正 = 左转一致 |

> **与旧版的关系**：`vx` = 前后、`vy` = 左移的麦轮模型**作废**。新协议里没有「左移」，`turn` 是**转动**不是平移。

### 3.2 轮盘八方位映射（App 端对照表）

`L` / `T` 为当前档位幅度（0~100，见 §3.4），斜向两分量同时给出。

| 方位 | 屏幕含义 | `drive` | `turn` | 左轮 | 右轮 | 下发 |
| --- | --- | --- | --- | --- | --- | --- |
| 正前 | ↑ | `+L` | `0` | `+L` | `+L` | 是 |
| 左前 | ↖ | `+L` | `+T` | `L−T` | `L+T` | 是 |
| 右前 | ↗ | `+L` | `−T` | `L+T` | `L−T` | 是 |
| 正后 | ↓ | `−L` | `0` | `−L` | `−L` | 是 |
| 左后 | ↙ | `−L` | `−T` | `−L+T` | `−L−T` | 是 |
| 右后 | ↘ | `−L` | `+T` | `−L−T` | `−L+T` | 是 |
| **正左** | ← | — | — | — | — | **否（App 拦截）** |
| **正右** | → | — | — | — | — | **否（App 拦截）** |

**为什么后退时 `turn` 符号反过来**：`turn` 按**车体**定义（正 = 逆时针），而用户推的是**屏幕方位**。后退时逆时针转会让车尾向右摆，所以「左后」必须配负 `turn`（顺时针），车尾才会朝屏幕左下走。这一条就决定了上表后两行，App 按表填值即可，不要自己推。

### 3.3 轮速合成

```
左轮百分比 = clamp(drive − turn, −100, +100)
右轮百分比 = clamp(drive + turn, −100, +100)
```

- 百分比 → `0.01 r/s`：`rps = 百分比 × 500 ÷ 100`；→ PWM：`pwm = 百分比 × 255 ÷ 100`（沿用【代码】既有换算）。
- 三个例子：
  - `drive=+100, turn=0` → 左 +100 / 右 +100：直行；
  - `drive=+100, turn=+100` → 左 0 / 右 +200→夹到 +100：左转弧线（内侧轮停，不反转）；
  - `drive=0, turn=+100` → 左 −100 / 右 +100：**原地左转**。
- 合成后再夹取，**不要**先夹 `drive`/`turn` 再合成以外的二次处理；一个公式贯穿 App 文档与固件。

### 3.4 死区、档位与限幅

| 环节 | 规则 | 数值 | 来源 |
| --- | --- | --- | --- |
| 归一化 | 轮盘偏移量 ÷ 最大半径 | `∈ [-1, +1]` | 【设计】 |
| 死区 | 模长小于阈值按 0 处理 | **5%** | 【设计】 |
| 方位判定 | 按 45° 扇区取八方位；**正左/正右直接丢弃** | 8 扇区 | 【设计】 |
| 档位 | 档位系数在 App 侧乘进 `L`/`T` | 慢 40% / 中 70% / 快 100% | 【设计】 |
| 量化 | 乘 100 后四舍五入取整 | 步长 1% = 0.05 r/s | 【设计】 |
| 限幅 | `drive`、`turn` 各自夹到 `±100` | — | 【设计】 |

> 死区只作用于轮盘**中心**的小圆，不影响方位判定：偏离中心超过 5% 就按所在扇区取值。

### 3.5 正左 / 正右为什么无效

- 差速两轮**没有任何横向自由度**：两轮同速只能直行，差速只能转向，横移在物理上不存在。
- 若把正左/正右硬映射成「原地转」，用户在屏幕上看到的是「往左平移」，车却在原地打转，属于**语义欺骗**；映射成「不动」则是死区，同样糟糕。
- 因此**拦截点放在 App**：轮盘判到正左/正右扇区就不构造帧、不下发。车端不实现任何降级，收到的只有合法分量（`操控.md` §9.3）。
- 需要的原地转向，走独立转向按钮（`drive=0, turn=±T`）或旧命令 `0xE3`/`0xE4`，都不需要改协议。

## 4. 下发节奏与超时

### 4.1 帧节奏

| 项 | 约定 |
| --- | --- |
| 周期 | **约 200 ms 一帧**（5 Hz），按住期间持续 |
| 值不变时 | **照发**。车端靠「收到新帧」续命，App 不做变化检测、不做去重 |
| 松手 | **立即停止下发**，不补发、不发零向量 |
| 滑动中方向变化 | 下一帧（≤200 ms）体现新方位，App 不插队、不补帧 |
| 两路并行 | `0xEB` 与 `0xEC` 各发各的，周期相同但**互不合并、互不刷新** |

### 4.2 车端超时自停

```
每次收到 0xEB → 刷新 lastMoveAtMs，写入目标轮速
loop() 里：now − lastMoveAtMs > MOTION_STREAM_TIMEOUT_MS → 目标轮速与 PWM 归零
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `MOTION_STREAM_TIMEOUT_MS` | **300 ms** | 【设计】1.5 × 帧间隔，留抖动余量；写成可调常量 |
| `GIMBAL_STREAM_TIMEOUT_MS` | **300 ms** | 云台独立一份，互不影响 |

- **为什么不是 200 ms**：帧间隔就是 200 ms，阈值等于间隔时任何一次 UDP 丢包或调度抖动都会误判停车，表现为一顿一顿。取 1.5 倍后单帧丢失不会停车，连续丢两帧（≥400 ms）才停，行为可预期。要严格 200 ms 只需改这个常量。
- 超时停车**不回 ACK、不记 ERROR**（否则松手后必然刷一条错误日志）；只在 DEBUG 级记一条「流式运动超时」。
- 超时只清目标与 PWM，**不改变** `drive`/`turn` 的历史值显示。

### 4.3 责任边界（写清楚，避免两端互相等）

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| **App** | 按住期间每 200 ms 发一帧；松手立刻停发；保证值在 `-100`~`+100`；拦掉正左/正右 | **不做**超时判定、**不做**超时后补发、**不假设**车一定收到 |
| **车端（主板）** | 300 ms 内没新帧就自己停车；收到即刷新计时；`0xE0` 立即停 | 不要求 App 发心跳、不因单帧丢失回错误 |
| 双方共同 | 同一套 CRC8、同一套 LEN 校验（§6 of `命令.md`） | — |

> 一句话：**App 只保证「发」，板子负责「停」。** 链路断掉时唯一能救车的是板端的超时自停。

## 5. 停止命令覆盖

| 项 | 约定 |
| --- | --- |
| 命令 | `0xE0 CMD_STOP`，`LEN=0`，ACK `3` |
| 优先级 | **最高**，高于任何正在执行的移动 / 云台 / 离散运动命令 |
| 立即性 | 收到即清零目标轮速、PWM、`drive`/`turn`/`pan`/`tilt`，并**清掉两个流式计时器**，不等 300 ms |
| 覆盖对象 | `0xEB`、`0xEC`、`0xE1`~`0xE4` 全部 |
| 之后 | 只有新的 `0xEB`/`0xEC` 帧才能重新起步；`0xE0` 本身不锁死后续命令 |
| 与副板 | `0xE0` 是双端执行：主板本地停完立即回 ACK，再经串口通知副板停视频/云台（副板失败不影响已回的 ACK） |

**App 侧动作**：按下停止 → 先停掉发送定时器 → 再发 `0xE0` → 收到 ACK 3 后回到空闲态。不要在停止后又补一帧 `0xEB 0/0`，那是重复语义。

## 6. `0xEC` 云台两分量

### 6.1 字段

| 项 | 值 |
| --- | --- |
| TYPE | **`0xEC` `CMD_GIMBAL_VECTOR`** |
| LEN | **2** |
| PAYLOAD | `[0] pan` int8、`[1] tilt` int8 |
| 帧总长 | **7 B** |
| 取值范围 | `-100`~`+100`，单位 = **该轴最大角速度的百分比** |
| `pan` 正 | 向右（俯视顺时针）；负 = 向左 |
| `tilt` 正 | 向上；负 = 向下 |
| `0 / 0` | 该帧不产生转动（等价停转） |
| 节奏 | 与移动相同：200 ms 一帧，300 ms 无新帧自停，松手不补发 |

八方位到两分量的映射是**直角分解**，没有车体符号翻转：

| 方位 | `pan` | `tilt` |
| --- | --- | --- |
| 上 | 0 | `+T` |
| 右上 | `+T` | `+T` |
| 右 | `+T` | 0 |
| 右下 | `+T` | `−T` |
| 下 | 0 | `−T` |
| 左下 | `−T` | `−T` |
| 左 | `−T` | 0 |
| 左上 | `−T` | `+T` |

云台八方位**没有无效格**（两个轴都能真正转动），与移动轮盘不同。

### 6.2 与位置型 `0xE5` / `0xE6` 的关系

| 命令 | 语义 | 用途 |
| --- | --- | --- |
| `0xEC` | **角速度分量**，松手即停 | 轮盘拖动、连续微调 |
| `0xE5` `CMD_PITCH` | **绝对角度** 0~255 → 0°~180° | 一键回中、预设机位 |
| `0xE6` `CMD_YAW` | **绝对角度** 0~255 → 0°~360° | 同上 |

- 两者**并存**，都归同一个云台控制类处理：`0xEC` 积分出角度，`0xE5`/`0xE6` 直接设角度。
- 先到先执行、后到覆盖目标；不做排队。
- 云台超时**只停转、不回中**——回中是 App 显式发 `0xE5`/`0xE6` 的事。

### 6.3 角度积分与限位（固件侧）

```
每帧 update(dt)：
  panAngle  += pan%  × PAN_RATE_MAX  × dt
  tiltAngle += tilt% × TILT_RATE_MAX × dt
  夹到 [0°, 360°) / [0°, 180°]；超时或 0/0 时停止积分，角度保持不变
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `PAN_RATE_MAX` | **90 °/s** | 【设计】`pan=100` 时满速 |
| `TILT_RATE_MAX` | **90 °/s** | 【设计】 |
| 限位 | 水平 `0°~360°` 循环；俯仰 `0°~180°` 夹取 | 【设计】，与 `0xE5`/`0xE6` 的映射范围一致 |

- 舵机是位置型，所以速度分量必须积分成角度再驱动；分解与积分都在云台控制类里，解析层不参与。
- 当前**无云台硬件**：`0xEC` 与 `0xE5`/`0xE6` 一样回 `ACK_ST_CANNOT(6)`，但状态照常维护，接上舵机后只补 PWM 输出。

## 7. 运行状态机（移动）

```
        ┌──────────┐  收到 0xEB(drive,turn) 非 0/0    ┌──────────┐
        │   IDLE   │ ───────────────────────────────► │ RUNNING  │
        │ 目标=0   │                                  │ 目标≠0   │
        └──────────┘ ◄─────────────────────────────── └──────────┘
             ▲          300 ms 无新帧 / 0xE0 / 0/0           │
             │                                              │
             └─────────────── 每 200 ms 新帧刷新 ◄───────────┘
```

| 迁移 | 触发 | 动作 |
| --- | --- | --- |
| IDLE → RUNNING | 收到 `0xEB` 且 `drive≠0` 或 `turn≠0` | 写目标轮速 / PWM，刷新计时 |
| RUNNING → RUNNING | 收到任意 `0xEB`（值不变也算） | 覆盖目标，刷新计时 |
| RUNNING → IDLE | `now − lastMoveAtMs > 300 ms` | 目标与 PWM 归零，清计时（记 DEBUG 日志） |
| RUNNING → IDLE | 收到 `0xE0` | 立即归零 + 清计时，不等超时 |
| RUNNING → IDLE | 收到 `0xEB 0/0` | 同 `0xE0`，但回 `ACK 3` 而非 `0` |

云台是**另一台同构状态机**，只把 `0xEB` 换成 `0xEC`、常量换成 `GIMBAL_STREAM_TIMEOUT_MS`，两台机器互不引用。

## 8. App 端换算（参考实现）

```text
// 1) 轮盘 → 归一化
dx = (touch.x - center.x) / radius      // 右为正
dy = (center.y - touch.y) / radius      // 上为正
r  = hypot(dx, dy)
if (r < 0.05) { stopStreaming(); return; }   // 死区：直接停发

// 2) 扇区判定（八方位，正左/正右拦截）
angle = atan2(dy, dx) * 180 / PI        // 右=0，上=90，左=180
sector = round(angle / 45)              // -4..4
if (sector == ±4) { stopStreaming(); return; }  // 正左 / 正右：不下发

// 3) 档位与分量
L = 100 * gear                          // gear: 0.4 / 0.7 / 1.0
T = 100 * gear * r                      // 斜向幅度可按半径缩放
switch (sector) {
  case  0: drive= 0; turn=-T; break;    // 右   → 纯右转（非轮盘网格，仅独立按钮时用）
  case  1: drive=+L*0.7; turn=-T*0.7;   // 右上
  case  2: drive=+L; turn=0;            // 上
  case  3: drive=+L*0.7; turn=+T*0.7;   // 左上
  case -1: drive=+L*0.7; turn=-T*0.7;   // 右下（后）
  ...
}

// 4) 组帧：AA | SEQ | EB | 02 | drive | turn | CRC8
```

> 上面的 `case` 只示意结构，**实际取值以 §3.2 的表为准**；尤其是「左后 / 右后」的 `turn` 符号与前进时相反。

## 9. App 能力闸门

### 9.1 第一道闸：协议白名单

- 只发 `命令.md` 表内登记的 TYPE；`0xEC` 与 `0xEB` 同属版本 21，握手 `0xC0` 版本不等时不发。
- 未登记 TYPE 车端静默丢弃（不回 ACK），App 侧也不允许发。

### 9.2 第二道闸：车端能力位

| 能力 | 位 | 判定 |
| --- | --- | --- |
| 视频 | `bit0` | 无视频源不显示视频入口 |
| 云台 | `bit1` | **为 0 时禁用云台轮盘**，不要靠 ACK 6 才发现没硬件 |
| 麦轮 / 横移 | `bit6` | **当前恒为 0**；为 1 才允许出现横向操作（届时另加 TYPE，`0xE7`/`0xE8` 仍不实现） |

### 9.3 第三道闸：方位合法性（本轮新增）

| 判定 | 处理 |
| --- | --- |
| 轮盘落在**正左 / 正右**扇区 | **不下发**，本地显示「差速车不支持横移」，发送定时器保持停止 |
| 轮盘落在其余六格 | 按 §3.2 组帧下发 |
| 落在死区 | 停止下发（不发 `0/0`） |
| 车端 `CAP` 无云台 | 云台轮盘置灰，不发 `0xEC` |
