## 0. 结论先行

| 问题 | 结论 |
|---|---|
| ESP32-S3 能直接插 SIM 卡上网吗 | **不能**。S3 没有蜂窝基带，必须外挂 4G/Cat.1 模块 |
| 家里有 WiFi 的远程，怎么做最省 | **设备连家里 WiFi + 公网 relay 中转**，成本约 ¥60–150/月，不需要公网 IP |
| 户外移动（没有可用 WiFi） | **外挂 Cat.1 模块（Air780E / EC200U / EC800M）+ 流量卡**，设备自己上网 |
| 为什么不用公网 IP + 端口映射 | 国内家宽/蜂窝大量处于 CGNAT 大内网，**没有独立公网 IPv4**；运营商侧不允许入站 |
| 远程命令协议 | **完全复用 V2.0**，共用 SEQ，`SEQ=0` 免去重，`ACK_TIMEOUT` 从 4 s 放宽到 **6 s** |
| 远程视频 | **QVGA 6–8 fps，0.5–1 Mbps**；按需拉流，避免常年烧流量 |

## 1. ESP32 能不能插卡自己上网

### 1.1 硬件事实

| 事实 | 说明 |
|---|---|
| **ESP32-S3 无蜂窝基带**【事实】 | 芯片只有 2.4 GHz WiFi + BLE 5，**没有 2G/4G/5G 射频与协议栈**，不存在"插卡即上网" |
| 没有 SIM 卡座接口 | S3 没有 ISO 7816 / SIM 接口，SIM 卡必须接在蜂窝模块上 |
| 可行做法 | 外挂蜂窝模块，通过 **UART + AT 命令**或 **PPP 拨号**把模块当成"网卡" |

### 1.2 模块选型

| 模块 | 制式 | 上行 | 接口 | 参考价 | 适用 |
|---|---|---|---|---|---|
| **Air780E**（合宙） | Cat.1 | 5 Mbps | UART AT / PPP | ¥30–50 | **性价比首选，物联网够用** |
| **EC200U**（移远） | Cat.1 | 5 Mbps | UART AT / PPP / USB | ¥40–70 | 出货稳定、资料全 |
| **EC800M**（移远） | Cat.1 | 5 Mbps | UART AT / PPP | ¥40–70 | 同上 |
| **SIM7600**（SIMCom） | Cat.4 | 50 Mbps | UART / USB | ¥100–150 | 需要高清视频上行才考虑 |
| SIM800 | 2G | — | UART | ¥20 | **淘汰**，多数地区 2G 已退网 |

> Cat.1 的 5 Mbps 上行对本项目 **0.5–2 Mbps** 的远程视频 + 0.06 Mbps 音频 + 10 kbps 控制完全够用；Cat.4 只在需要 VGA 15 fps 时才值得。

### 1.3 供电与天线（最容易翻车的地方）

| 项 | 要求 | 说明 |
|---|---|---|
| 供电电压 | **3.8–4.2 V**（不是 3.3 V） | 模块 PA 需要高压摆幅 |
| 瞬态电流 | **峰值 1.5–2 A**，持续 200–300 mA【实测区间/手册典型值】 | 必须独立 DC-DC，不能从 S3 的 3.3 V LDO 取电 |
| 去耦 | 模块电源脚就近 **470 µF + 100 µF + 10 µF** | 否则发射瞬间掉压导致复位 |
| 地 | 与 S3 共地，但电源走线要粗 | — |
| 天线 | 4G 天线需**净空区/地平面**，远离摄像头排线与 BLE 天线 | 天线隔离不足会导致 WiFi/BLE 灵敏度下降 3–10 dB【推算】 |
| 屏蔽 | 模块与摄像头尽量分置车体两端 | 4G 发射会耦合进音频链路（"哒哒"声） |

### 1.4 软件接入

| 方式 | 说明 | 复杂度 |
|---|---|---|
| **PPP 拨号（推荐）** | 模块当调制解调器，ESP32 侧跑 PPP，拿到一个 IP，之后所有 TCP/WSS 与 WiFi 完全一致 | 中（需 PPP 组件） |
| AT 命令直连 | 用 `AT+CIPSTART` 等让模块自己建 TCP，数据经 UART 透传 | 低，但吞吐受 UART 波特率限制（建议 ≥ 921600） |
| 双栈切换 | WiFi 优先、4G 兜底，或反之 | 中（路由选择逻辑） |

> 关键设计：**上层业务不感知底层是 WiFi 还是 4G**。只切换 `ITransport` 的网络出口，V2.0 与视频协议完全不变。

## 2. 两条路线对比

| | **A. WiFi + 公网 relay** | **B. 4G 模块直连** |
|---|---|---|
| 原理 | 设备连家里/场所 WiFi，主动出站连云端 relay；App 连同一 relay | 设备经 Cat.1 模块拨号上网，主动出站连 relay；App 连 relay |
| 适用场景 | **家里固定、办公室、有可用 WiFi** | **户外移动、无可用 WiFi、车载** |
| 额外硬件 | 无 | 蜂窝模块 + SIM + 天线 + 独立电源（约 ¥50–120） |
| 设备侧延迟增量 | 家庭宽带上行 10–30 ms | 4G 上行 30–60 ms（P95 80–150）【推算】 |
| 控制 P95（经 relay） | 同城 100–160 ms / 跨省 180–300 ms【推算】 | 加 30–80 ms【推算】 |
| 视频可用带宽 | 取决于宽带上行，通常 20–100 Mbps | Cat.1 上行 5 Mbps（实测 2–4 Mbps）【实测区间】 |
| 月成本 | VPS ¥60–150 + 家庭宽带（已有） | VPS 同左 + 流量卡（按 GB 计费） |
| 功耗 | 中（WiFi 常开 80–120 mA） | 高（4G 发射峰值 1.5–2 A，平均 200–400 mA）【实测区间】 |
| 运维 | 依赖现场 WiFi，换地方要重新配网 | 插卡即用，但要注意信号与流量 |
| 可靠性 | WiFi 掉线要 autoreconnect | 蜂窝覆盖差时会频繁重连 |
| 推荐 | **一期主线** | **户外场景必选增量** |

**判定规则（一句话）**：**设备 90% 的时间在一个有 WiFi 的地方 → 选 A；设备要移动或现场没有 WiFi → 必须选 B。** 两者可共存：WiFi 优先、4G 兜底。

## 3. 推荐路线与架构

### 3.1 推荐

- **一期：A（WiFi + relay）**。零新增硬件，成本最低，家里/办公室即可验证全链路。
- **二期：A + B 双栈**。加 Cat.1 模块，WiFi 优先、无 WiFi 时自动切 4G。业务层零改动。

### 3.2 架构（文字图）

```
                        公网 VPS  relay.example.com:443（唯一公网入口）

   车端（WiFi 或 4G，二者选一作为出口）          中转进程                    App
  ┌──────────────────────────┐        ┌─────────────────────┐      ┌──────────┐
  │ ctrl  出站 wss ──────────┼───────►│ /dev/<devId>/ctrl   │◄─────│ ctrl     │
  │ video 出站 wss ──────────┼───────►│ /dev/<devId>/video  │◄─────│ video    │
  │ audio 出站 wss ──────────┼───────►│ /dev/<devId>/audio  │◄─────│ audio    │
  └──────────────────────────┘        └─────────────────────┘      └──────────┘
        ▲                                       ▲
        │ 设备始终是"出站客户端"                  │ relay 只做：
        │ 不需要公网 IP、不需要端口映射            │ 鉴权 + 1:1 配对 + 限速 + 字节透传
```

| 项 | 取值 | 理由 |
|---|---|---|
| 端口 | **仅 443**（WSS） | 公网只暴露一个端口，各类网络都放行 |
| 连接发起 | 设备与 App **都出站** | 彻底绕开 CGNAT 与端口映射 |
| 通道数 | **3 条独立 TLS**（ctrl / video / audio） | 视频拥塞不能拖慢控制与音频 |
| relay 职责 | 鉴权、配对、限速、转发 | **不解析 V2.0**，协议升级不用改中转 |
| 设备地址 | 由 `devId` 决定，不使用 IP | 设备换网络（WiFi↔4G）时 App 无感 |

## 4. 连接时序 / 鉴权 / 重连

### 4.1 连接时序（8 步）

| 步 | 设备侧 | 云端 relay | App 侧 |
|---|---|---|---|
| 1 | 读 NVS 凭据，选择出口（WiFi 优先 / 4G 兜底） | — | — |
| 2 | 联网成功，SNTP 对时 | — | — |
| 3 | TLS 连接 `relay:443` | 接受连接 | — |
| 4 | 发 AUTH：`devId + ts + nonce + HMAC-SHA256` | 校验时间窗 ±60 s、nonce 去重 | — |
| 5 | — | 绑定 `/dev/<devId>/*`，回 READY | — |
| 6 | — | — | App 登录，发 user token |
| 7 | — | 校验 `allowedDevIds`，配对 ctrl 通道（独占租约） | 收到配对成功 |
| 8 | 心跳开始（WS ping 15 s） | 双向转发 | 同左 |

> **独占租约**必须在 relay 做：同一 `devId` 同时只允许一个 App 持 ctrl 通道。否则两份 App 各自从 SEQ=0 开始计数，"共用 SEQ"的前提就被破坏（设备端不做冲突防御）。

### 4.2 鉴权

| 项 | 建议 |
|---|---|
| 设备身份 | NVS 存 `devId`（16 hex）+ **32 B 预共享密钥** |
| 设备鉴权 | TLS 内首条消息做 HMAC 挑战应答，**token 不进 URL、不进日志** |
| App 鉴权 | 独立 user token（JWT 或等价），携带 `allowedDevIds` |
| 证书 | 设备侧用标准 CA + SNTP；无时间则用**公钥哈希 pin** |
| App 侧 | **SPKI 哈希 pin**，禁止"信任所有证书" |
| 传输 | **TLS 1.2+ 强制**，relay 拒绝明文 |

### 4.3 心跳与重连

| 项 | 取值 |
|---|---|
| WS ping | 每 **15 s** |
| 判离线 | App 侧 30 s 收不到任何 DAT/ACK |
| 设备侧主动重连 | 45 s 无上行成功 |
| 重连退避 | 1 / 2 / 4 / 8 / 15 / 30 s，±20% 抖动 |
| 重连顺序 | 先 ctrl，再 audio，最后 video |
| 视频降档 | 重连期间强制 QVGA 5 fps，稳定 10 s 后回升 |
| 断线期间命令 | 设备侧运动命令 **1 s 无新命令自动停**，天然安全 |

## 5. 远程命令：V2.0 复用与 ACK 超时

### 5.1 承载

| 项 | 做法 |
|---|---|
| 通道 | `wss://relay/dev/<devId>/ctrl`（设备侧）/ `wss://relay/app/<devId>/ctrl`（App 侧） |
| 消息粒度 | **一帧一条二进制消息**（3–23 B），不 base64 |
| 为什么能复用 | V2.0 帧自带 `0xAA` 同步头 + 静态长度表 + CRC8，不依赖 LEN；WS 保序 |
| 字节流备选 | 也支持一条消息里塞多帧（解析器本来就能切） |
| 乱序 | WS over TCP 保序，relay 不引入乱序 |

### 5.2 SEQ 与去重

| 项 | 远程场景是否成立 |
|---|---|
| 共用一条全局 SEQ | **成立**（SEQ 是 App 侧计数器，与链路无关） |
| 一份 64 条去重表 | **成立**（设备侧只有一份） |
| `SEQ=0` 免去重 | **成立**，且远程更有价值：断线重连后可用 `SEQ=0` 安全重发幂等命令 |
| 新增约束 | **同一 devId 只允许一个 App 持有控制租约** |

### 5.3 `ACK_TIMEOUT` 建议值

| 场景 | 建议 | 理由 |
|---|---|---|
| 局域网 | 保持 **4 s** | 前文口径不变 |
| 公网远程（WiFi 出口） | **6 s** | P95 往返 100–300 ms，留出蜂窝切换/relay 抖动缓冲 |
| 公网远程（4G 出口） | **6 s**（不变） | 4G P95 往返 200–400 ms，6 s 仍充足 |
| 运动类命令 | **不重试** | 设备 1 s 自动停，超时直接发 `CMD_STOP` |
| 重试白名单 | 仅 `SEQ=0` 的幂等命令 | 避免重复执行 |

## 6. 远程视频：档位、流量与成本

### 6.1 为什么远程必须降档

| 档位 | 分辨率 | fps | 单帧 | 码率 | 每小时流量 |
|---|---|---|---|---|---|
| 本地 VGA | 640×480 | 10–15 | 30–60 KB | 3–6 Mbps | 1.35–2.7 GB/h |
| **远程标准（默认）** | **QVGA 320×240** | **6–8** | **8–15 KB** | **0.5–1.0 Mbps** | **0.22–0.45 GB/h** |
| 远程极低 | QQVGA 160×120 | 5 | 3–6 KB | 0.12–0.24 Mbps | 0.05–0.11 GB/h |

计算方式（必须能自己算）：

```
每帧字节 × 帧率 × 8 = 码率（bps）
例：12 KB × 7 fps × 8 = 672 kbps
每小时流量 = 码率 ÷ 8 × 3600
例：0.672 Mbps ÷ 8 × 3600 ≈ 302 MB/h
```

### 6.2 成本

| 项 | 单价 | 远程标准档（0.7 Mbps）每小时 | 每月（每天 1 小时） |
|---|---|---|---|
| VPS 中转 | ¥60–150/月（含 3 Mbps 固定带宽） | — | ¥60–150 |
| 国内流量计费 | 约 ¥0.8/GB（以当期官网为准） | **约 ¥0.24–0.36** | ¥7–11 |
| 4G 流量卡 | 约 ¥1–3/GB（视套餐） | **约 ¥0.3–1.1** | ¥9–33 |
| 商用 IoT 平台 | 按消息条数计费 | **不适用视频** | — |

### 6.3 省钱三招

1. **按需拉流**：默认只建 ctrl 通道，用户点"看画面"才建 video 通道，退出即断（流量可降 90%）。
2. **只推关键帧**：1 fps 快照（5–8 KB/s ≈ 0.06 Mbps），当"仪表盘"用。
3. **纯控制 + 单张抓拍**：需要时通过 relay 的 HTTP GET 取一帧，不常驻视频流。

## 7. 限制（技术 / 硬件 / 网络）

### 7.1 技术限制

| 限制 | 数值 | 影响 | 缓解 |
|---|---|---|---|
| 无公网 IPv4 | 国内家宽/蜂窝大量 CGNAT【事实】 | 入站不可行 | 全部改为出站 |
| 4G 模块接入 | UART + AT / PPP | 吞吐受 UART 波特率限制 | 波特率 ≥ 921600 |
| TLS 开销 | 握手 40–60 KB heap/连接，200–600 ms【推算】 | 三条连接 = 三份 | ECDSA P-256；PSRAM 兜底 |
| relay 带宽成本 | 按 Mbps 或 GB 计费 | 视频是主要成本 | 降档 + 按需拉流 |
| `ACK_TIMEOUT` | 公网 P95 200–400 ms | 4 s 偏紧 | 放宽到 6 s |
| 单 App 租约 | 必须独占 | 两个 App 会撞 SEQ | relay 强制租约 |

### 7.2 硬件限制

| 限制 | 数值 | 影响 |
|---|---|---|
| S3 无蜂窝基带【事实】 | — | 必须外挂模块 |
| 4G 模块供电 | 3.8–4.2 V，峰值 1.5–2 A【手册典型值】 | 不能从 3.3 V 取电；需独立 DC-DC + 大电容 |
| 4G 天线隔离 | 与 WiFi/BLE 天线距离 ≥ 20–30 mm，且不同极化 | 隔离不足会降低 WiFi/BLE 灵敏度 3–10 dB【推算】 |
| 功耗 | 4G 平均 200–400 mA，峰值 2 A【实测区间】 | 电池续航显著缩短；需评估电源方案 |
| 发热 | 4G 模块 + 视频编码 + WiFi 同时工作 | 需要散热与降档策略 |
| 摄像头引脚 | 已占 14 个 GPIO | 4G 模块只能用 UART 剩余引脚 |

### 7.3 网络限制

| 限制 | 数值 | 影响 |
|---|---|---|
| 运营商 NAT | 绝大多数为 CGNAT | 设备只能出站 |
| 公网 IP | 基本拿不到 | 排除端口映射方案 |
| 4G 上行 | Cat.1 理论 5 Mbps，实测 2–4 Mbps【实测区间】 | 远程视频上限约 2 Mbps |
| 4G 延迟 | 30–60 ms 典型，P95 80–150【推算】 | 控制 P95 200–400 ms |
| 流量费 | 按 GB 计费 | 视频是主要成本项 |
| 信号覆盖 | 地下室/郊区弱 | 需断线重连与本地降级 |

## 8. 专业名词表

| 术语 | 人话解释 |
|---|---|
| **CGNAT（运营商级 NAT）** | 很多用户共用一个公网 IP，外部无法主动连到你 |
| **公网 IP** | 互联网上唯一可被外部访问的地址 |
| **端口映射** | 在路由器上把外部端口转到内网某台设备 |
| **relay（中转）** | 一台有公网地址的服务器，帮两端转发数据 |
| **反向隧道** | 内网设备主动连出去，让外部通过这条连接反向访问它 |
| **Cat.1** | 4G 的一个低速档，上行约 5 Mbps，适合物联网 |
| **PPP** | 拨号协议，让模块像网卡一样给设备分配 IP |
| **AT 命令** | 用文本指令控制通信模块的传统方式 |
| **WSS** | 加密的 WebSocket |
| **TLS** | 传输层加密，保证内容不被窃听篡改 |
| **HMAC** | 用密钥对消息做签名，用于证明身份 |
| **Token** | 一次性或短期凭证，用于鉴权 |
| **证书 pin（固定）** | 只信任某一个特定证书/公钥，防中间人 |
| **SNTP** | 网络对时，TLS 校验证书需要正确时间 |
| **租约（Lease）** | 一段时间内独占某个资源的授权 |
| **按需拉流** | 用户要看才推视频，不看就断开 |
| **背压** | 发送方过快时主动丢弃或等待的机制 |
