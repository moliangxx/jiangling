# 小智云服务接入实施方案（可照做版）

> 设备：ESP32-S3 N16R8（16 MB Flash / 8 MB PSRAM，`dio_opi`），Arduino / PlatformIO
> 音频硬件：I2S 麦克风 **INMP441** + 功放 **MAX98357A**，**无 AEC**
> 目标：接入小智官方云，实现"App 设定唤醒词 → 本地唤醒 → 语音问答 → 语音+字幕回复 → 播完 30 s 关闭"
> 边界：**不改动已定方案**（局域网主线、V2.0 帧、共用 SEQ、`SEQ=0` 免去重、视频始终走 WiFi）；本文只描述新增的 AI 通道。

> **术语校准（2026-11-10）**：文中「V2.0 帧 / 不新增 V2.0 TYPE」的协议现已更名 **V21**（`AA|SEQ|TYPE|LEN|PAYLOAD|CRC8`，版本号 `21`）。读作「V21 帧 / 不新增 V21 TYPE」；「不进 V2.0 命令区」即「不新增 CMD TYPE」，规则不变。落地结果见 `06-小智云接入实录.md`。

## 0. 结论摘要

| 问题 | 结论 |
|---|---|
| 走哪种接入形态 | **官方云 + 自研固件**（不烧官方固件、不自建服务端） |
| 传输 | **WebSocket over TLS**，`wss://api.tenclass.net/xiaozhi/v1/` |
| 音频 | **Opus / 16 kHz / 单声道 / 60 ms 帧**；下行可能 24 kHz，需降采样 |
| 字幕 | **与 TTS 同源**，来自 `tts` 的 `sentence_start` 文本；不走第二条通道 |
| 最大阻塞 | **① 中文唤醒词模型不在 Arduino 预编译库**　**② 无 AEC 导致"自己听见自己"**　**③ Opus 编码挤占 CPU** |
| 30 s 计时 | 本地实现，`tts.state=stop` 时启动；超时**关闭整条 WSS**，下次唤醒重连 |
| App 设置唤醒词 | 只能"从设备预置模型列表里选"，**不能自由输入文本**（WakeNet 是固定模型） |
| 与远程互斥 | 远程操控开启 → 设备侧主动 `listen.stop` 并关闭 AI 通道（本地策略，不新增 V2.0 命令） |

## 1. 三种接入形态与选型

| 形态 | 做法 | 代价 | 适合谁 |
|---|---|---|---|
| **A. 官方云 + 自研固件（推荐）** | 保留我们自己的 Arduino 固件，只实现它的 WebSocket 协议 | 需自写 Opus 编解码、唤醒、字幕解析；受公共服免费边界约束（并发/时长/**未核实**） | **本项目** |
| B. 自建服务端 | 部署社区开源服务端（如 `xinnan-tech/xiaozhi-esp32-server`），改 OTA/WS 地址 | 需要服务器与运维、模型 API Key、费用；**用户明确不能自建** | 有服务器、要多设备/商用 |
| C. 烧官方固件 | 直接用官方 `xiaozhi-esp32` 固件 | 丢掉我们全部业务：V2.0、视频、云台、录音、TFT 逻辑；等于换项目 | 只想体验语音助手 |

**为什么选 A**：
1. 用户不能自建服务端 → 排 B；
2. 官方固件会把 V2.0、视频、控制链路全部替换掉 → 排 C；
3. A 只新增一条独立 AI 通道，**不动已定的三条链路**，风险可控。

## 2. 官方云完整接入步骤

### 2.1 账号与设备绑定（控制台侧）

| 步 | 做什么 | 产出/凭据 | 状态 |
|---|---|---|---|
| 1 | 注册 `https://xiaozhi.me` | 账号 | 【已核实】第三方教程一致 |
| 2 | 控制台创建"智能体"（角色/音色/模型） | 智能体配置 | 【已核实】 |
| 3 | 设备首次联网，请求 OTA（`https://api.tenclass.net/xiaozhi/ota/`） | **6 位设备验证码**（设备侧显示） | 【已核实】第三方教程 |
| 4 | 在控制台"添加设备"，输入 6 位码 | 设备与账号绑定 | 【已核实】 |
| 5 | 绑定后设备再次唤醒即可对话 | `Device-Id`（MAC）作为设备身份 | 【已核实】 |

> **凭据说明**：协议头里有 `Authorization: Bearer <token>`，但 **token 的获取/生成方式未核实**（官方文档只给了字段，示例里用的是 `test-token`）。PoC 第一步就要在控制台确认是否提供 token；若公共服实际不校验 token，则仅靠 `Device-Id` 绑定，**这一点必须实测确认后写死结论**。

### 2.2 传输方式对比

| 传输 | 地址/端口 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **WebSocket（官方云默认）** | `wss://api.tenclass.net/xiaozhi/v1/` :443 | 一条 TCP 全双工、实现简单、穿透好 | 音频与文本同一条流，队头阻塞 | **本项目** |
| MQTT + UDP | 社区服务端提供 | 音频走 UDP，延迟更低、无队头阻塞 | 需要 UDP 打洞/端口协商，公网 NAT 下不稳定；**官方云是否支持未核实** | 自建服务端进阶 |

**选 WebSocket**：我们已有 `links2004/WebSockets` 经验，且官方云默认就走它。

### 2.3 连接时的四个 Header（已核实）

| Header | 值 |
|---|---|
| `Authorization` | `Bearer <token>` |
| `Protocol-Version` | `1`（与 hello 的 `version` 一致） |
| `Device-Id` | 设备 MAC |
| `Client-Id` | 软件生成的 UUID（存 NVS，重刷重置） |

## 3. 设备端协议层实现

### 3.1 握手

设备发 `hello`（JSON 文本帧）：

| 字段 | 取值 |
|---|---|
| `type` | `"hello"` |
| `version` | `1` |
| `transport` | `"websocket"` |
| `audio_params.format` | `"opus"` |
| `audio_params.sample_rate` | `16000` |
| `audio_params.channels` | `1` |
| `audio_params.frame_duration` | `60` |
| `features` | `{ "mcp": false }`（一期不做 MCP）；若要服务端 AEC 加 `"aec": true` |

服务端回 `hello`，**10 s 超时**（已核实）。必须校验 `transport == "websocket"`，并保存 `session_id` 与服务端下发的 `audio_params`。

### 3.2 音频参数

| 项 | 上行 | 下行 |
|---|---|---|
| 编码 | Opus | Opus |
| 采样率 | 16 kHz | 服务端 hello 示例 **24 kHz** |
| 声道 | 1 | 1 |
| 帧长 | **60 ms**（960 samples） | 同 |
| 位宽 | 解码前无位宽概念；PCM 中间态 16 bit | 同 |
| 码率建议 | **24–32 kbps**（60 ms ≈ 180–240 B） | 由服务端决定，**未核实** |
| libopus 参数建议 | `OPUS_APPLICATION_VOIP`、`complexity=0`、`bitrate=24000`、`frame=60 ms` | 解码后重采样到 16 kHz |

> 官方未文档化 libopus 的具体 profile，上述为**建议值**（`OPUS_APPLICATION_VOIP` + 语音信号），不是硬性要求。

### 3.3 控制消息

| 时机 | 设备动作 | 说明 |
|---|---|---|
| 本地唤醒命中 | 建 WSS → hello → 发 `listen{state:"start", mode:"auto"}` | 唤醒前**不建连、不推流** |
| 用户再次说唤醒词（打断） | 发 `abort{reason:"wake_word_detected"}` | 先停播放，再重新 `listen.start` |
| 收到 `tts{state:"start"}` | 停止上行（进入 speaking） | **半双工**，规避无 AEC 的回声 |
| 收到 `tts{state:"sentence_start", text:"..."}` | 把 `text` 上屏（TFT 字幕） | 字幕与语音同源 |
| 收到 `tts{state:"stop"}` | **启动本地 30 s 计时** | 用户明确的计时起点 |
| 30 s 到 | 发 `listen{state:"stop"}` → 关闭 WSS | 省流量、省功耗 |
| 远程操控开启 | 主动 `listen.stop` + 关闭 WSS | AI 与远程互斥，本地策略 |
| 收到 `stt{text}` | 可选上屏"我说了什么" | 非必需 |
| 收到 `llm{emotion,text}` | 情绪/表情展示 | 非完整回复文本 |

### 3.4 二进制帧

一期用 **v1（裸 Opus 帧）**：一个 WS 二进制消息 = 一个 60 ms Opus 包，**不要在一帧里塞多个包**。

若二期要用服务端 AEC，再切 **v2**：`version:u16, type:u16, reserved:u32, timestamp:u32, payload_size:u32, payload[]`。

## 4. 两端改造清单

### 4.1 设备端

| 模块 | 复用 / 新增 | 具体工作 |
|---|---|---|
| `audio/AudioBus` | **复用** | I2S 引脚与时钟不动（BCLK=40 / LRCLK=41 / MIC=42 / SPK=47） |
| `audio/Mic` | **复用 + 扩展** | 增加"按 60 ms 出块"的取数接口；现有 20 ms 逻辑保留给其它用途 |
| `audio/Speaker` | **复用** | `play()` 已是非阻塞；只需保证喂的是 16 kHz/16 bit/单声道 |
| `communication/` 分层 | **复用骨架** | 新增 `AiService` 作为第四条业务通道（与 Command/Log/Data 平级） |
| `ITransport` 抽象 | **复用** | 新增 `WssTransport`，与 BLE / TCP 并列 |
| **OpusCodec** | **新写** | 上行编码、下行解码、60 ms 分帧、24→16 kHz 重采样 |
| **WakeWord** | **新写** | 基于 `ESP_SR` 的 `SR_MODE_WAKEWORD`，从 App 下发的配置里选模型 |
| **AiSession** | **新写** | 状态机：Idle → Connecting → Listening → Speaking → Cooldown(30 s) → Idle |
| **Subtitle** | **新写** | 解析 `tts.sentence_start` 的 `text`，送 TFT 显示 + 本地缓存 |
| 唤醒词配置 | **新增存储项** | NVS 存"模型 ID + 灵敏度"；经 BLE 配置通道下发，**不进 V2.0 命令区** |
| 互斥策略 | **新增** | 远程操控开启时关闭 AI，反之亦然（本地策略，不新增 TYPE） |

### 4.2 App 端

| 项 | 结论 |
|---|---|
| 现阶段 | **不做 AI 接口**。App 只负责"设置唤醒词 + 开关 AI 权限"，不做对话 UI |
| 后续扩展 | 若要 App 显示字幕/历史，建议走 **audio 通道 side-channel**（复用 01 文档的 `kind=0x02`），**不新开 TCP** |
| 唤醒词下发 | 走 BLE 配置通道（NUS），字段：`模型 ID(u8) + 灵敏度(u8) + 使能(bool)`；**不新增 V2.0 TYPE** |

## 5. 五个阻塞点与解法

### 5.1 中文唤醒词资源（最高优先）

| 事实 | 结论 |
|---|---|
| 本地预编译库 `CONFIG_SR_WN_WN9_HIESP=1` | 只有 **"Hi ESP"** 可用【已核实】 |
| `CONFIG_SR_MN_CN_NONE=1` | **中文命令词模型未启用**【已核实】 |
| Arduino `ESP_SR` 库 | 只暴露唤醒/命令词，**不暴露 AFE/AEC**【已核实】 |

**影响**：用户要求"唤醒词由 App 设置"，但 WakeNet 的唤醒词是**训练好的固定模型**，App 只能"在设备内置的模型列表里选"，**不能自由输入任意文本**。

**解法（按优先级）**：
1. **一期用 "Hi ESP"**，在 App 里就写"当前仅支持 Hi ESP"，避免承诺做不到的事；
2. 需要中文唤醒词 → 换装含中文模型的 `esp-sr` 预编译库（工作量中，需重新编译框架或替换组件）；
3. 需要任意自定义词 → 属于模型训练/乐鑫定制，**不在本项目范围**。

### 5.2 无 AEC 的回声

| 问题 | 说明 |
|---|---|
| 结构 | INMP441 与 MAX98357A 同板近距离，喇叭声音直接被麦克风收回 |
| 后果 | 上行里混入 TTS 回声 → 服务端 ASR 可能识别成用户说话 → 自我触发 |

**解法（按代价从低到高）**：
1. **半双工（一期首选）**：`tts.start` 后停止上行，`tts.stop` 后恢复。协议本身在 listening 状态下丢弃下行音频，天然配合。
2. **静音填充**：播放期间上行继续发"静音 Opus 帧"而不是停发，避免服务端 VAD 超时误判（可选）。
3. **物理降回授**：喇叭朝向远离麦克风、加吸音棉/减震、降低数字音量。
4. **服务端 AEC**：hello 声明 `features.aec=true` + 二进制 v2 带 timestamp；**实际效果未核实**，且需要上行携带参考信号，属于二期。
5. **设备侧 AEC**：需按 IDF 组件接入 AFE，Arduino 库不暴露，**成本最高**。

### 5.3 Opus 编码 CPU

| 项 | 数值 |
|---|---|
| 编码（c0） | **约 26% 单核**（沿用前文数据） |
| 编码（c2 / c5） | 34% / 49% 单核 |
| 解码 | 约 10–15% 单核【推算】 |
| 与 JPEG + TLS 叠加 | 单核 60–80%【推算】 |

**解法**：
1. **只用 c0**，把 c5 从选项里删掉；
2. **核绑定**：音频编码固定在一个核，JPEG 编码/网络放另一个核；
3. **会话期视频降档**：`Listening/Speaking` 期间视频压到 QVGA 8–10 fps（可复用现有降档策略）；
4. 若仍不够 → 降低上行码率到 16 kbps（60 ms ≈ 120 B），音质略降。

### 5.4 与 WiFi 视频共存的射频 / 内存冲突

| 冲突 | 数值 | 解法 |
|---|---|---|
| 射频 | 2.4 GHz 单射频，WiFi + BLE 分时 | AI 会话期间视频降档；BLE 只保留 ctrl |
| 内存 | WSS+TLS 40–60 KB、Opus 编解码 50–100 KB、音频缓冲 ≈12 KB，合计 **≈120–180 KB**【推算】 | 优先放**内部 RAM**；PSRAM 只放摄像头帧 |
| 带宽 | Opus 24–32 kbps + 视频 1–2 Mbps | 上行总占用 < 2.1 Mbps，家庭宽带上行足够 |
| 队列 | 视频大包会阻塞 | 独立 socket + 独立任务，音频优先级最高 |

### 5.5 30 s 计时语义

| 风险 | 解法 |
|---|---|
| 把 `tts.start` 当起点 → 计时偏早 | **只在 `tts.state=stop` 启动** |
| 多句回复中间有停顿 → 误判结束 | 以"最后一次 `tts.stop`"为准；收到新的 `tts.start` 就取消计时 |
| 计时期间用户又说话 | 收到 `stt` 或 `listen.start` 即取消计时 |
| 超时后该不该断 WSS | **断开**：省电省流量，下次唤醒重连（握手 + hello < 1 s【推算】） |

## 6. 语音 + 文字双流落地

| 问题 | 结论 |
|---|---|
| 字幕与语音是否同源 | **同源**。`tts.sentence_start` 的 `text` 就是喂给 TTS 的那句文本 |
| 走哪条通道 | **与音频同一条 WS**（文本帧与二进制帧交替），不开第二条连接 |
| 下发时机 | `tts.start` 后，每句先来 `sentence_start(text)`，再来该句音频二进制帧，整段结束发 `tts.stop` |
| 设备显示 | 收到 `sentence_start` 立刻刷 TFT 字幕行；音频继续播 |
| App 显示 | **一期不做**（App 无 AI 接口）；二期走 audio side-channel 或复用 ctrl 的 DAT（需评估变长文本与 V2.0 定长约束，见 01 文档第 7 节） |
| 一致性风险 | TTS 可能改写数字/缩写读音，字幕与听感有细微差异——可接受，不做二次 ASR |

## 7. 分阶段路线

### 阶段一：最小闭环（MVP）

**目标**：唤醒 → 说一句 → 收到语音回复 → 播完起计时。

| # | 内容 | 验收 |
|---|---|---|
| 1 | WiFi 联网 + SNTP 对时 | 能解析域名、TLS 握手成功 |
| 2 | OTA 激活 + 控制台绑定 | 控制台显示设备在线 |
| 3 | WSS 连接 + 4 个 Header + hello 往返 | 收到 `session_id` |
| 4 | Opus 编码上行（60 ms / c0） | 服务端返回 `stt` 文本合理 |
| 5 | Opus 解码下行 + 24→16 kHz 重采样 + Speaker 播放 | 能听到回复 |
| 6 | `tts.stop` 启动 30 s 计时 → 超时断连 | 计时准确、断连后下次唤醒可重连 |
| 7 | 半双工（播放时停上行） | 不出现"自己回答自己" |

**MVP 明确不做**：字幕上屏、打断、MCP、App 显示、视频联动降档。

### 阶段二：可用性增强

| 项 | 内容 |
|---|---|
| 字幕 | `sentence_start` 上 TFT；缓存最近 N 句 |
| 打断 | 唤醒词命中 → `abort{reason:"wake_word_detected"}` + 停播放 |
| 视频联动 | AI 会话期间自动 QVGA 8–10 fps，结束后恢复 |
| 远程互斥 | 远程操控开启 → 关 AI；关闭 → 允许唤醒 |
| 唤醒词选择 | App 通过 BLE 配置通道切换内置模型 + 灵敏度 |
| 断线重连 | 指数退避 + 会话状态清理 |
| 资源观测 | 记录 CPU/内存峰值，确认与视频共存余量 |

### 阶段三：可选

| 项 | 内容 |
|---|---|
| MCP | `features.mcp=true`，把音量/云台/灯作为工具暴露 |
| 服务端 AEC | 二进制 v2 + `features.aec=true`，实现边说边听 |
| App 字幕 | audio side-channel，不新开 TCP |
| 自建兜底 | 若公共云边界不满足，改 OTA/WS 地址指向自建服务端（协议不变） |

## 8. 限制（技术 / 硬件 / 网络）

### 8.1 技术限制

| 限制 | 数值/状态 | 影响 | 缓解 |
|---|---|---|---|
| 中文唤醒词缺失 | `CONFIG_SR_MN_CN_NONE=1`【已核实】 | App 无法自由设置唤醒词 | 用 "Hi ESP" 或替换模型库 |
| 帧长 60 ms | 已核实 | 与我们 20 ms 约定冲突 | 双路径，独立缓冲 |
| 下行可能 24 kHz | 服务端 hello 示例 | 必须重采样 | 解码后降采样 |
| hello 超时 10 s | 已核实 | 弱网易失败 | 退避重连 |
| 免费边界未知 | **未核实**（并发/时长/商用/数据） | 不可作为长期依赖 | 预留自建降级 |
| token 机制未知 | **未核实** | 绑定流程可能卡住 | PoC 首日确认 |
| libopus 不在预编译库 | 【已核实】 | 需自行引入 | 固定点版本 |
| MQTT+UDP 官方是否支持 | **未核实** | 只能用 WS | 本项目本就用 WS |

### 8.2 硬件限制

| 限制 | 数值 | 影响 |
|---|---|---|
| 无 AEC | INMP441 + MAX98357A 同板 | 回声自触发 |
| PSRAM | 8 MB OPI（GPIO33–37 占用） | 摄像头帧与 AI 缓冲共享 |
| 内部 RAM | 约 512 KB | TLS + Opus + 队列需精算 |
| Flash | 16 MB，双 OTA 分区 | 唤醒词模型 + 固件体积要留余量 |
| 功放增益 | MAX98357A 由板载电阻固定 | 软件只能衰减，不能提升 |
| I2S 引脚 | 40/41/42/47【事实】 | 不可挪用 |

### 8.3 网络限制

| 限制 | 数值 | 影响 |
|---|---|---|
| 上行码率（Opus） | 24–32 kbps ≈ **11–14 MB/小时** | 蜂窝下可接受 |
| 若改 PCM | 256 kbps ≈ 115 MB/小时 | 不建议 |
| 公网 RTT | 同城 10–30 ms / 跨省 40–80 ms【推算】 | 影响首字延迟 |
| 公共服稳定性 | **未核实** | 可能排队、变更、关闭 |
| 防火墙 | 需放行 443 WSS + OTA HTTPS | 校园/企业网可能拦截 |
| 第三方数据 | **未核实** | 隐私合规风险 |

## 9. 专业名词表

| 术语 | 人话解释 |
|---|---|
| **OTA** | 设备启动时向服务器查询身份/升级，小智用它下发激活要求 |
| **激活码 / 验证码** | 设备首次联网时显示的 6 位数字，用于在控制台绑定设备 |
| **Device-Id** | 设备身份，通常用 MAC 地址 |
| **Client-Id** | 客户端标识，重刷固件会变 |
| **token** | 访问凭证，放在 `Authorization` 头里 |
| **hello** | 连上后双方各发一条"我支持什么格式"的自我介绍 |
| **session_id** | 一次对话的编号 |
| **Opus** | 低码率语音压缩编码 |
| **frame_duration** | 一个音频包覆盖多少毫秒，小智是 60 ms |
| **重采样** | 把 24 kHz 转成 16 kHz，匹配喇叭 |
| **AEC** | 回声消除，避免喇叭声音被麦克风收回 |
| **半双工** | 要么听要么说，不同时进行 |
| **WakeNet** | 乐鑫本地唤醒词模型（固定词，不是任意文本） |
| **MultiNet** | 乐鑫本地命令词识别模型 |
| **VAD** | 判断有没有人在说话 |
| **STT / ASR** | 语音转文字 |
| **TTS** | 文字转语音 |
| **barge-in** | 打断，AI 说话时用户开口即停 |
| **MCP** | 让 AI 调用设备能力的标准协议 |
| **WS / WSS** | WebSocket / 加密的 WebSocket |
| **PSRAM** | 片外内存，本项目 8 MB |
