## 0. 结论摘要

| 决策项 | 结论 |
|---|---|
| 设备端做什么 | 只做**离线唤醒 + 固定命令词**；不跑大模型 |
| 对话算力放哪 | 手机 App（主路径）或局域网服务；设备只做采集、截句、压缩、播放 |
| 音频怎么传 | IMA ADPCM 16 kHz/4 bit，**8 KB/s**；走独立语音通道，不进 `0xAA` 帧 |
| 短对话通道 | 独立 BLE GATT Service（MTU 247，建议连接间隔 15 ms） |
| 长对话通道 | Wi-Fi（UDP/WebSocket），按需开启，用完即关 |
| 识别结果怎么上报 | 只发 `DAT_VOICE` / `LOG_VOICE` 事件帧，**不回流成 App→板的 CMD** |
| 协议版本 | 新增类型建议升 **V1.8**；音频通道独立，不参与 `PROTOCOL_VERSION` 校验 |
| 框架 | **ESP-IDF**；过渡期可用 ESP-IDF + Arduino as component |
| 麦克风 | 先用现有单麦 INMP441 模块；双麦作为 P4 增强 |

一句话：**离线命令留在车上，AI 对话交给手机，音频压缩后走独立通道，现有协议只承载状态和短文本。**

## 一、离线语音控制（写死命令）

### 1.1 定位与边界

| 项 | 约定 |
|---|---|
| 目标 | 不联网、不接大模型，用 8~15 条固定命令词控制小车与云台 |
| 输入 | 单麦克风 INMP441，16 kHz / 16 bit PCM |
| 识别 | 乐鑫 **ESP-SR**：AFE 前端 + WakeNet 唤醒词 + MultiNet 命令词 |
| 执行 | 设备本地执行，直接复用现有 `CMD_*` 的运动语义与解算 |
| 上报 | 只上报语音事件帧，供 App 显示与联动 |
| 不做什么 | 不做自由对话、不做云端 ASR、不把识别结果变成 App→板的命令回环 |
| 断网要求 | 完全可用；Wi-Fi/BLE 全断也不影响唤醒与命令执行 |

### 1.2 技术方案：AFE + WakeNet + MultiNet

| 模块 | 作用 | 运行时机 |
|---|---|---|
| **AFE** | 回声消除、降噪、增益控制、VAD（语音活动检测） | 常开 |
| **WakeNet** | 唤醒词检测，输出唤醒/未唤醒 | 常开 |
| **MultiNet** | 固定命令词识别，输出命令词 ID + 置信度 | 唤醒后的命令窗口内 |

处理链：

```text
INMP441 → I2S 16 kHz/16 bit → AFE（降噪/VAD）→ WakeNet（常开）
                                                   │ 命中唤醒词
                                                   ▼
                                      MultiNet（3 s 命令窗口）
                                                   │ 命中命令词
                                                   ▼
                                      本地动作映射 + DAT_VOICE / LOG_VOICE
```

要点：

1. WakeNet 与 MultiNet 的模型都来自 esp-sr，**不能混用其他厂商的模型文件**。
2. AFE 的输入必须是 16 kHz、16 bit、单声道；双麦时是左右声道两路。
3. 唤醒后只开 3 s 命令窗口，窗口结束立即关 MultiNet，降低 CPU 与误识别。

### 1.3 资源占用与模型分区

| 项目 | Flash（模型） | RAM（运行时） | 说明 |
|---|---|---|---|
| AFE | 很小 | 单麦 50~100 KB；双麦 100~200 KB | 缓冲建议放 PSRAM |
| WakeNet | 约 0.5~1 MB/模型 | 约 50~150 KB | 常开，CPU 占用主要来源 |
| MultiNet（中文） | 约 1.5~3 MB/模型 | 约 100~300 KB | 只在命令窗口内运行 |
| 建议预留 | **3 MB `model` 分区** | **300~500 KB RAM** | 16 MB Flash / 8 MB PSRAM 余量充足 |

模型存放规则：

1. esp-sr 官方示例使用**独立的 `model` 分区**存放 `srmodels.bin`，通过分区名加载。
2. 当前 `default_16MB.csv` **没有 `model` 分区**，必须自定义分区表（见 3.4）。
3. 模型不要塞进 SPIFFS 当普通文件使用；esp-sr 按分区加载，路径方式不受支持。
4. PSRAM 使用建议：AFE 环形缓冲约 64 KB、ADPCM 缓冲约 20 KB、TTS 播放缓冲约 64 KB，合计 < 1 MB。

CPU 分配建议：

| 核 | 任务 |
|---|---|
| Core 0 | BLE/Wi-Fi、协议解析、日志与遥测 |
| Core 1 | I2S 采集、AFE、WakeNet、MultiNet、ADPCM 编解码、I2S 播放 |

任务之间用 FreeRTOS 队列解耦；**禁止在 BLE 回调里直接跑识别**。

### 1.4 采样率与 I2S 接线

引脚以《01-硬件配置文档》第八节为准：

| 信号 | ESP32-S3 | 说明 |
|---|---|---|
| BCLK | **GPIO4** | 麦/喇叭共用位时钟 |
| LRCLK | **GPIO5** | 字时钟 |
| DIN（麦克风数据） | **GPIO7** | INMP441 `SD` |
| DOUT（喇叭数据） | **GPIO6** | MAX98357A `DIN` |
| VCC | 5 V（DCP3512 5V 路） | 功放不要从 3.3 V 取电 |
| GND | 共地 | 必须与主板共地 |

参数：

| 项 | 值 |
|---|---|
| 采样率 | **16 kHz** |
| 位深 | AFE 输入 16 bit PCM；INMP441 为 24 bit 数据装在 32 bit 槽，软件右移取高 16 bit |
| I2S 格式 | Philips 标准 |
| 声道 | 单麦 mono；双麦 stereo |
| INMP441 声道选择 | `L/R` 接 GND = 左声道；接 3.3 V = 右声道 |
| MAX98357A 播放 | 16 kHz / 16 bit / mono，与识别采样率统一，省去重采样 |

注意：

1. 音频已移到 GPIO4~GPIO7（左侧排针），不再占用 JTAG；GPIO39~42 改给电机信号，占用后只失去外接 JTAG 探针，ESP32-S3 内置 USB-JTAG 与 UART0 串口日志（GPIO43/44）仍可用。
2. GPIO33~37 被 8 MB OPI PSRAM 占用，不能当普通 IO。
3. GPIO9 已作 TFT 背光，GPIO1/2/38~42/47 已作电机信号，不要重复分配。
4. 麦克风走线远离电机与喇叭；功放电源单独走 5 V 并加电容。

### 1.5 命令词清单与 CMD 映射

第一版固定 14 条命令词，全部写死，不支持在线增删。

| 编号 | 命令词 | 本地动作 | 映射 CMD | KIND_TYPE | PAYLOAD | 说明 |
|---|---|---|---|---|---|---|
| 1 | 前进 | 前进 60% | `CMD_FORWARD` | 1 | `LEVEL=60` | 默认中速 |
| 2 | 后退 | 后退 50% | `CMD_BACK` | 2 | `LEVEL=50` | 默认低速 |
| 3 | 左转 | 原地左转 60% | `CMD_LEFT` | 3 | `TURN=60` | 差速轮原地转 |
| 4 | 右转 | 原地右转 60% | `CMD_RIGHT` | 4 | `TURN=60` | 差速轮原地转 |
| 5 | 加速 | 前进 100% | `CMD_FORWARD` | 1 | `LEVEL=100` | 最大直线速度 |
| 6 | 减速 | 前进 30% | `CMD_FORWARD` | 1 | `LEVEL=30` | 低速巡航 |
| 7 | 停止 | 立即停车 | `CMD_STOP` | 0 | `LEN=0` | 最高优先级 |
| 8 | 抬头 | 云台俯仰 120 | `CMD_PITCH` | 5 | `ANGLE=120` | 0~255 映射 0°~180° |
| 9 | 低头 | 云台俯仰 60 | `CMD_PITCH` | 5 | `ANGLE=60` | 同上 |
| 10 | 云台左转 | 云台水平 90 | `CMD_YAW` | 6 | `ANGLE=90` | 0~255 映射 0°~360° |
| 11 | 云台右转 | 云台水平 270 | `CMD_YAW` | 6 | `ANGLE=270` | 同上 |
| 12 | 开始对话 | 进入 AI 会话 | `CMD_VOICE_SESSION` | 17 | `ACTION=1` | V1.8 新增 |
| 13 | 结束对话 | 退出 AI 会话 | `CMD_VOICE_SESSION` | 17 | `ACTION=0` | V1.8 新增 |
| 14 | 电量多少 | 触发一次 `DAT_BAT` 推送并播报 | 无 CMD | — | — | 本地动作，不走协议 |

映射规则：

1. 命令词的参数全部写死在固件里，App 不能改；要改档位只能重刷固件或走 App 遥控。
2. 一条命令词只产生一个动作；复合动作（如"云台归位"）暂不加入。
3. 同一命令词 300 ms 内重复命中只执行一次，防止连说触发两次。
4. 运动类命令执行后仍受现有 **1 s 运动命令失联保护**约束：1 s 内没有新运动命令自动停车。
5. 当前 `JiangLing_ai` 没有电机与云台硬件，P2 只能验证"映射与事件"，实际动作要等硬件接入。

### 1.6 唤醒后状态机

状态定义：

| 状态 | 名称 | 行为 |
|---|---|---|
| S0 | 待唤醒 IDLE | AFE + WakeNet 常开；MultiNet 关闭；不上传任何音频 |
| S1 | 已唤醒 WAKED | 播放提示音，屏幕显示"我在听"，启动 MultiNet，开启 3 s 命令窗口 |
| S2 | 识别中 RECOGNIZING | 等待 MultiNet 输出；置信度 ≥ 阈值进入 S3，否则进入 S6 |
| S3 | 执行中 EXECUTING | 执行映射动作，上报 `DAT_VOICE`（state=执行）与 `LOG_VOICE` |
| S4 | 反馈 REPLYING | 屏幕/提示音反馈，500 ms 后回 S0 |
| S5 | 对话中 CONVERSATION | 命中"开始对话"或 App 触发；MultiNet 暂停，AFE 继续，走 AI 链路 |
| S6 | 识别失败 ERROR | 提示"没听清"，允许一次重试；仍失败回 S0 |

转移表：

| 当前 | 事件 | 下一状态 | 动作 |
|---|---|---|---|
| S0 | 检测到唤醒词 | S1 | 提示音；`DAT_VOICE(state=1)`；启动 MultiNet |
| S0 | 收到 App `CMD_VOICE_SESSION(ACTION=1)` | S5 | 进入 AI 会话 |
| S1 | MultiNet 命中且置信度 ≥ 阈值 | S3 | 执行动作；上报事件 |
| S1 | 3 s 内无命中 | S0 | 上报 `DAT_VOICE(FLAGS.timeout=1)` |
| S1 | 命中但置信度 < 阈值 | S6 | 提示重说，允许 1 次重试 |
| S3 | 执行完成 | S4 | 500 ms 反馈后回 S0 |
| S3 | 命中"开始对话" | S5 | 发起 `CMD_VOICE_SESSION(ACTION=1)` |
| S6 | 重试成功 | S3 | 执行动作 |
| S6 | 重试失败 | S0 | 上报 `DAT_VOICE(FLAGS.low_confidence=1)` |
| S5 | 命中"结束对话" / App 停止 / 60 s 无语音 | S0 | 发 `CMD_VOICE_SESSION(ACTION=0)`，关闭会话 |
| 任意 | 命中"停止" / 收到 `CMD_STOP` | S0 | 立即停车，清空音频队列 |

超时值（固件常量，可调）：

| 项 | 值 |
|---|---|
| 唤醒后命令窗口 | 3 s |
| 识别失败重试次数 | 1 次 |
| 运动命令失联保护 | 1 s（沿用现有 `MOTION_TIMEOUT_MS`） |
| 对话空闲超时 | 60 s |
| 单轮对话总超时 | 30 s |

### 1.7 语音事件帧定义

识别结果**只上报**，不回流成 App→板的 CMD。事件分两类：

#### 1.7.1 `DAT_VOICE`（结构化状态）

| 项 | 值 |
|---|---|
| KIND | DAT（2） |
| KIND_TYPE | **3**（V1.8 新增） |
| TYPE | `(2 << 6) | 3` = **0x83** |
| 方向 | 板 → App |
| LEN | **4**（定长） |
| SEQ | DAT 滚动序号 0~255，接收方维护 64 条去重窗口 |

PAYLOAD：

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `STATE` | u8 | 0=idle，1=wake，2=listening，3=thinking，4=speaking，5=executing，6=error |
| 1 | `CMD_ID` | u8 | 命令词编号 1~14；0 表示无 |
| 2 | `CONFIDENCE` | u8 | 0~100，MultiNet 置信度 |
| 3 | `FLAGS` | u8 | bit0=超时，bit1=低置信度，bit2=噪声，bit3=会话中，bit4~7 保留 |

#### 1.7.2 `LOG_VOICE`（文本）

| 项 | 值 |
|---|---|
| KIND | LOG（1） |
| KIND_TYPE | **5**（V1.8 新增） |
| TYPE | `(1 << 6) | 5` = **0x45** |
| 方向 | 板 → App |
| LEN | **1~120** |
| PAYLOAD | UTF-8 文本，不带 `\0`，长度由 LEN 控制 |

用途：显示识别到的命令词、设备本地提示（如"没听清"）、调试信息。复用现有日志通道，不需要 ACK。

#### 1.7.3 为什么不用 CMD 上报

| 方案 | 问题 |
|---|---|
| 设备发一条 App→板 CMD 语义的结果 | 方向错误，App 要回 ACK，形成回环 |
| 复用 `CMD_REQ_RECORD` | 它的语义是"请求手机用手机麦克风录音"，与车上麦克风不符 |
| 新增板→App CMD | CMD 语义是"请求/命令"，语音结果不是命令；还要额外 ACK 往返 |
| **LOG/DAT 事件** | 单向、无需 ACK、App 可直接显示，语义正确 |

### 1.8 误唤醒、远场、噪声处理策略

| 问题 | 策略 |
|---|---|
| 误唤醒 | 唤醒词选 3~4 个音节、避开常用词；唤醒后必须 3 s 内命中命令词，否则自动退出；唤醒提示音让人知道设备被触发 |
| 近距离误触 | 运动类命令默认中低速（60%/50%），并受 1 s 失联保护；"前进"不设 100% 默认值 |
| 远场 | 单麦保证 1~3 m；超过 3 m 不承诺；需要 5 m 时上双麦 |
| 电机噪声 | 麦克风远离电机与轮组；AFE 开启降噪；结构上加减震 |
| 喇叭自激 | 播放 TTS 时暂停上行与 MultiNet（半双工）；P4 再做 AEC |
| 低置信度 | 阈值建议 60；低于阈值进入 S6 要求重说，不执行危险动作 |
| 连续误识别 | 同一命令 300 ms 防抖；连续 2 次低置信度后强制回 S0 |
| 环境切换 | 上电不做自适应；固定增益，避免空调/风扇突变导致误唤醒 |

### 1.9 离线验收标准

| 指标 | 验收值 | 测试方法 |
|---|---|---|
| 唤醒率（安静 1 m） | ≥ 95% | 10 次 × 3 轮 |
| 唤醒率（安静 3 m） | ≥ 85% | 同上 |
| 命令词识别率（安静 1 m） | ≥ 90% | 14 条 × 5 次 |
| 命令词识别率（安静 3 m） | ≥ 75% | 同上 |
| 电机全速 + 喇叭播放时 | ≥ 70% | 实车工况 |
| 误唤醒 | ≤ 2 次/24 h | 安静室内连续记录 |
| 唤醒→动作延迟 | P95 < 1 s | 串口打点 |
| 误动作率 | < 1% | 统计错误执行次数 |
| 稳定性 | 连续 200 次唤醒无死机、PSRAM 余量不下降 | 长时间压力测试 |
| 断网可用 | Wi-Fi/BLE 全断仍可唤醒与执行 | 拔网/关手机 |

> 以上为设计目标。当前无麦克风实物，**全部指标尚未实测**。

## 二、AI 语音交流

### 2.1 四条输入输出路径

| 路径 | 输入 | 输出 | 数据形态 | 触发条件 |
|---|---|---|---|---|
| A. 语音进 → 语音出 | 用户说语音 | AI 语音回复 | 上行 ADPCM 音频；下行 ADPCM 音频 | 唤醒词 + "开始对话"，或 App 点"按住说话" |
| B. 语音进 → 文字出 | 用户说语音 | AI 文字回复 | 上行 ADPCM；下行 `LOG_VOICE` / App 文本 | 同上，但关闭 TTS |
| C. 文字进 → 文字出 | App 输入文字 | AI 文字回复 | `CMD_TEXT_INPUT` 文本；`LOG_VOICE` 文本 | App 文本输入框发送 |
| D. 文字进 → 语音出 | App 输入文字 | AI 语音回复 | `CMD_TEXT_INPUT` 文本；下行 ADPCM 音频 | App 文本输入框发送 + 开启朗读 |

各路径的数据形态：

| 数据 | 形态 | 通道 |
|---|---|---|
| 用户语音 | 16 kHz/16 bit PCM → IMA ADPCM 4 bit | 独立语音通道 |
| 用户文字 | UTF-8，≤ 119 字节/条 | `0xAA` 的 `CMD_TEXT_INPUT` |
| AI 文字 | UTF-8，短句 ≤ 120 字节 | `LOG_VOICE`（设备显示）或 App 本地显示 |
| AI 语音 | TTS 输出 → ADPCM 16 kHz | 独立语音通道 |
| 语音状态 | 4 字节结构化 | `DAT_VOICE` |
| 会话控制 | 1 字节动作 | `CMD_VOICE_SESSION` |

### 2.2 拓扑与两条链路

设备只做四件事：**采集、VAD 截句、ADPCM 压缩/解压、播放**。ASR / LLM / TTS 不在设备上跑。

```text
链路 1：BLE 短对话（默认，低功耗、无需配网）

INMP441 → ESP32-S3（AFE/VAD/ADPCM）→ 独立 BLE 语音通道 → Android App
                                                          ├─ ASR（云或手机本地）
                                                          ├─ LLM（云或手机本地）
                                                          └─ TTS → ADPCM
ESP32-S3（ADPCM 解码）→ MAX98357A ← 独立 BLE 语音通道 ←──────┘
```

```text
链路 2：Wi-Fi 长对话（家庭/局域网，低延迟）

INMP441 → ESP32-S3（AFE/VAD/ADPCM 或 Opus）→ Wi-Fi UDP/WebSocket →
        手机 App 或局域网服务（ASR → LLM → TTS）→ 回传 → ESP32-S3 → MAX98357A
```

| 链路 | 适用 | 优点 | 缺点 |
|---|---|---|---|
| BLE 短对话 | 日常问答、移动场景 | 低功耗、复用现有连接、无需配网 | 带宽紧、延迟较高、受 MTU/连接间隔影响 |
| Wi-Fi 长对话 | 家里固定、连续多轮 | 带宽足、延迟低、可接局域网服务器 | 功耗高、需配网、与 BLE 2.4 GHz 共存 |

选择规则：

1. 默认走 BLE；单轮回答超过 10 s 或需要高音质时切 Wi-Fi。
2. Wi-Fi 只在对话期间开启，空闲 30 s 后关闭。
3. 两条链路不能同时传音频；切换时先停当前轮，再重建通道。

### 2.3 延迟预算

| 阶段 | 离线命令 | BLE + 手机云 | Wi-Fi + 局域网 |
|---|---|---|---|
| 唤醒 | 0.3~0.8 s | 0.3~0.8 s | 0.3~0.8 s |
| VAD 截句 | — | 0.5~1 s | 0.3~0.8 s |
| 上行传输 | — | 0.1~0.3 s | 0.05~0.2 s |
| ASR | — | 0.5~2 s | 0.3~1 s |
| LLM | — | 1~4 s | 0.5~2 s |
| TTS | — | 0.5~2 s | 0.3~1 s |
| 回传 + 播放 | — | 0.2~0.5 s | 0.1~0.3 s |
| **合计** | **< 1 s** | **3~8 s** | **2~4 s** |

验收目标：BLE 云链路 P95 < 8 s；手机本地模型 P95 < 5 s；Wi-Fi 局域网 P95 < 4 s。

### 2.4 音频编码与分包：IMA ADPCM

| 项 | 值 |
|---|---|
| 编码 | IMA ADPCM（4 bit/sample） |
| 采样率 | 16 kHz（降级可用 8 kHz） |
| 声道 | 单声道 |
| 码率 | 16 kHz：**64 kbps = 8 KB/s**；8 kHz：32 kbps = 4 KB/s |
| 帧长 | **20 ms = 320 samples = 160 Byte** ADPCM 数据 |
| 帧头 | 6 Byte：`SEQ u16` + `TS_MS u32` |
| 单包总长 | 166 Byte（MTU 247 下可一包发完） |
| 序号 | u16 递增，回绕周期约 21.8 min；接收方按差值判断 |
| 时间戳 | 设备本地毫秒，用于播放端抖动缓冲与对齐 |

分包规则：

1. 一包一帧，不做跨包拼接；包内不再二级分包。
2. 接收方维护 200 ms 抖动缓冲；不足 60 ms 时补静音，避免播放卡顿。
3. 丢包检测：`SEQ` 跳变即判定丢包，记录丢包数并上报到 `DAT_VOICE.FLAGS` 的噪声位或调试日志。
4. **音频不做重传**：实时性优先，丢包用 PLC（重复上一帧或淡出静音）掩盖。
5. 控制消息（会话开始/结束、文字、取消）**可靠传输**：BLE 用 Write With Response，Wi-Fi 用 TCP 或带 ACK 的应用层消息；最多重传 2 次。
6. 编码器/解码器状态每帧独立（ADPCM 每帧带初始预测值），允许中途接入，不需要从会话开头解码。

为什么选 IMA ADPCM：

| 格式 | 16 kHz 码率 | 设备端成本 | 音质 | 结论 |
|---|---|---|---|---|
| PCM 16 bit | 32 KB/s | 无 | 最好 | BLE 不可行；Wi-Fi 可选 |
| **IMA ADPCM 4 bit** | **8 KB/s** | 极低 | 电话音质，语音可懂 | **BLE 双向首选** |
| Opus 16 kbps | 2 KB/s | 高，需 PSRAM 与较多 CPU | 好 | Wi-Fi 长对话备选 |
| MP3/AAC | 8~32 kbps | 解码成本中高 | 好 | 仅在 App 侧使用，设备不做 |

### 2.5 为什么不把音频塞进现有 `0xAA` 帧

| 限制 | 现状 | 对音频的影响 |
|---|---|---|
| PAYLOAD 上限 | `LEN` 最大 255 | 20 ms 帧 166 B 勉强，但无法带多帧或冗余 |
| BLE 分片 | `MAX_NOTIFICATION_BYTES = 20`，未协商 MTU | 166 B 要拆 9 个通知，吞吐与延迟不可接受 |
| 每帧 CRC8 | 每帧都要组帧校验 | 音频包密度高，CPU 与开销浪费 |
| 64 条 SEQ 去重 | CMD/LOG/DAT 各维护窗口 | 音频包会被去重逻辑误伤，丢包处理复杂 |
| 与遥测争用 | 500 ms DAT、实时 LOG 共用 TX | 音频会挤掉遥测，App 电量/日志异常 |
| ACK 语义 | CMD 需要 ACK | 音频流不能每条都等 ACK |

结论：音频走**独立 GATT Service** 或 **Wi-Fi 通道**，使用自己的分包、序号、抖动缓冲与丢包策略；`0xAA` 只承载状态与短文本。

### 2.6 独立 GATT Service 设计

建议沿用现有 NUS UUID 前缀，新增第 5 段编号（**自定义 UUID，不是蓝牙 SIG 标准**，需 App 与固件同步登记）：

| 角色 | UUID 建议 | 属性 | 用途 |
|---|---|---|---|
| Service | `6E400004-B5A3-F393-E0A9-E50E24DCCA9E` | — | 语音服务 |
| RX（App→设备） | `6E400005-B5A3-F393-E0A9-E50E24DCCA9E` | Write / Write NR | TTS 音频、控制消息 |
| TX（设备→App） | `6E400006-B5A3-F393-E0A9-E50E24DCCA9E` | Notify | 用户语音音频、状态回执 |

连接参数建议：

| 参数 | 值 |
|---|---|
| MTU | 247（固件 `BLEDevice::setMTU(247)` 或 IDF 对应 API；App 侧主动 `requestMtu`） |
| 连接间隔 | 15 ms（优先 7.5~15 ms） |
| 从机延迟 | 0 |
| PHY | 2M PHY（若手机支持） |

实测目标：1 m 内稳定 **6~10 KB/s**，丢包 < 2%。达不到时把 ADPCM 降到 8 kHz（4 KB/s）。

### 2.7 文字通道

| 方向 | 通道 | 类型 | 说明 |
|---|---|---|---|
| App → 设备（用户文字） | `0xAA` | `CMD_TEXT_INPUT`（CMD 18，`0xD2`） | 可靠、有 ACK；设备显示并可选转发给模型 |
| App → 设备（AI 文字） | `0xAA` | `CMD_TEXT_INPUT`（`ROLE=1`） | 让设备屏幕显示 AI 回复摘要 |
| 设备 → App（识别文本） | `0xAA` | `LOG_VOICE`（LOG 5，`0x45`） | 单向；App 日志/对话区显示 |
| 长文本（> 119 B） | 独立语音通道 | `VOICE_TEXT` 分片消息 | 不进 `0xAA`，避免撑爆 LEN |

`CMD_TEXT_INPUT` PAYLOAD：

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `ROLE` | u8 | 0=用户输入，1=AI 回复 |
| 1~119 | `TEXT` | UTF-8 | 不带 `\0`，最长 119 字节 |

规则：

1. 超过 119 字节的文本：`0xAA` 只下发前 119 字节供屏幕显示，完整文本留在 App 或走独立通道。
2. 设备收到 `CMD_TEXT_INPUT` 后回 ACK `已执行`(3)，并刷新 TFT 对话区。
3. 设备不解析语义；LLM 在 App/服务器侧。
4. 若采用"设备作为网关"模式，设备收到文字后通过 Wi-Fi 转发给服务器；默认不启用，避免设备承担模型职责。

### 2.8 协议扩展建议（V1.8）

新增类型均占用现有预留编号，不改变帧结构、CRC、SEQ 规则。

| KIND | KIND_TYPE | TYPE | 名称 | 方向 | LEN | PAYLOAD |
|---|---|---|---|---|---|---|
| CMD（3） | **17** | **0xD1** | `CMD_VOICE_SESSION` | 板 → App | 1 | `[ACTION u8]`：0=停止，1=开始，2=取消 |
| CMD（3） | **18** | **0xD2** | `CMD_TEXT_INPUT` | App → 板 | 2~120 | `[ROLE u8][TEXT UTF-8]` |
| LOG（1） | **5** | **0x45** | `LOG_VOICE` | 板 → App | 1~120 | UTF-8 文本 |
| DAT（2） | **3** | **0x83** | `DAT_VOICE` | 板 → App | 4 | `[STATE][CMD_ID][CONFIDENCE][FLAGS]` |

`CMD_VOICE_SESSION` 规则：

1. 只允许**板 → App**，用于设备唤醒后请求 App 准备语音会话；App 必须回 ACK。
2. App 主动开始对话不需要发这条命令，直接在 App UI 进入会话。
3. `ACTION=2`（取消）用于用户打断；收到后停止播放、清空音频队列、回 S0。

`PROTOCOL_VERSION`：

1. 新增类型需要 App 解析，建议升 **V1.8（`PROTOCOL_VERSION = 18`）**，握手仍按"等于"判定。
2. 音频通道独立，**不参与** `PROTOCOL_VERSION` 校验；App 未实现语音功能时仍可正常使用运动/遥测。
3. 若暂不上报语音事件，可保持 V1.7；一旦上线 `DAT_VOICE/LOG_VOICE`，必须升版本并同步 App。

哪些进现有协议、哪些留独立通道：

| 内容 | 去向 | 理由 |
|---|---|---|
| 语音状态、命令词 ID、置信度 | `DAT_VOICE` | 小、结构化、低频 |
| 识别文本、短 AI 回复 | `LOG_VOICE` | 单向、无需 ACK |
| 会话开始/结束/取消 | `CMD_VOICE_SESSION` | 需要可靠与 ACK |
| 用户文字、短 AI 文字 | `CMD_TEXT_INPUT` | 可靠、有 ACK、长度可控 |
| 音频包 | 独立 GATT / Wi-Fi | 高密度、需抖动缓冲与丢包策略 |
| ASR 中间结果、长文本、TTS 分片 | 独立通道 `VOICE_TEXT` | 长度与频率不适合 `0xAA` |
| 音频序号、时间戳、抖动缓冲 | 独立通道 | 传输层私有，不进应用层协议 |

### 2.9 端到端时序、超时、取消与降级

```text
T0 唤醒词命中
T1 提示音 + 屏幕"聆听中" + DAT_VOICE(wake)
T2 VAD 截句（最长 10 s）→ ADPCM 编码
T3 上传（BLE 0.1~0.3 s / Wi-Fi 0.05~0.2 s）
T4 ASR（0.5~2 s）→ 文本
T5 LLM（1~4 s）→ 回复文本
T6 TTS（0.5~2 s）→ ADPCM
T7 回传 + 播放（0.2~0.5 s）→ DAT_VOICE(speaking) → idle
```

| 阶段 | 超时 | 取消方式 | 失败降级 |
|---|---|---|---|
| 唤醒 → 命令窗口 | 3 s | 再次唤醒词 / `CMD_STOP` | 回 S0，上报超时 |
| VAD 截句 | 最长 10 s | `CMD_STOP` / App 取消 | 丢弃本轮，回 S0 |
| 上行传输 | 5 s | App 取消 | 重试 1 次；仍失败提示"网络慢" |
| ASR | 5 s | App 取消 | 提示"没听清"，回 S0 |
| LLM | 15 s | App 取消 / `CMD_STOP` | 返回"网络不可用"文字，离线命令仍可用 |
| TTS | 5 s | App 取消 | 只显示文字，不播放 |
| 回传 + 播放 | 5 s | `CMD_STOP` 立即静音 | 播放失败只显示文字 |
| 整轮 | 30 s | 任意取消 | 清空队列，回 S0 |

取消行为：

1. `CMD_STOP` 最高优先级，任何时候都立即停车并静音。
2. 用户说"停止"命令词，等价于取消当前轮 + 停车。
3. App 点"取消"发 `CMD_VOICE_SESSION(ACTION=2)`；设备停止播放、丢弃未发送音频、回 S0。
4. 播放中再次唤醒词：先静音，再进入新一轮。

失败与重连：

| 场景 | 行为 |
|---|---|
| BLE 断开 | 立即结束会话、停止播放、回 S0；离线命令继续可用 |
| Wi-Fi 断开 | 降级到 BLE 短对话（若已实现）；否则提示"网络断开" |
| App 崩溃/切后台 | 设备 60 s 无控制消息自动结束会话 |
| 重连 | App 重新发 `CMD_SESSION_INIT`；设备回 `resetDone`；未发送的语音事件按 LOG 队列补推（现有队列 100 条） |
| 重连后的一轮对话 | 不跨连接续传；丢弃半轮音频，从新的一轮开始 |
| 音频包乱序 | 按 `SEQ` 排序；超过 200 ms 抖动窗口的旧包丢弃 |
| 音频包重复 | 按 `SEQ` 去重，直接丢弃 |

### 2.10 隐私、状态提示、半双工与功耗

| 项 | 设计 |
|---|---|
| 唤醒前不上传 | 原始 PCM 只进 AFE 与 WakeNet，环形缓冲 ≤ 2 s，覆盖即丢；BLE/Wi-Fi 不发送任何音频 |
| 明确触发 | 只有唤醒词或 App 主动开始，才打开上行音频 |
| 录音状态提示 | TFT 显示"聆听中/思考中/说话中"；板载 WS2812（GPIO48）用颜色区分：蓝=待唤醒，青=聆听，黄=思考，绿=播放，红=错误 |
| 物理开关 | 可选：麦克风电源串联自锁开关，硬件级断开 |
| 半双工 | TTS 播放期间暂停上行与 MultiNet，播放结束再恢复；P4 加 AEC 做全双工 |
| 数据留存 | 设备不落盘音频；App 是否缓存由用户设置决定 |
| 日志脱敏 | `LOG_VOICE` 只放识别文本，不附原始音频或用户身份信息 |

功耗预算（量级，需实测）：

| 状态 | 电流 | 说明 |
|---|---|---|
| 深度睡眠 | 10 µA 级 | 不适用：唤醒需要常开 AFE |
| BLE 空闲 + 待唤醒 | 40~90 mA | 主要开销是 AFE + WakeNet |
| BLE 对话中 | 80~120 mA | 含编码与通知 |
| Wi-Fi 流式 | 150~250 mA 峰值 | 只在对话时开启 |
| 喇叭播放 | 100~300 mA | 随音量变化 |
| 4 节 2000 mAh 镍氢（估算） | 待唤醒约 20~40 h；连续对话约 3~6 h | 实际按占空比与音量修正 |

1. `model` 分区名必须与 esp-sr 示例一致，类型为 `data`，子类型按所选 esp-sr 版本的 `partitions.csv` 填写。
2. 分区表改动后必须全片擦除再烧录，避免旧分区残留。
3. 8 MB PSRAM 不参与分区，只做运行时缓冲。

### 3.5 框架选择与迁移影响

| 路线 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 全量 ESP-IDF** | `framework = espidf`，BLE/I2S/esp-sr 全用 IDF API；TFT_eSPI 重新适配 | 官方支持、稳定、分区/组件管理完整 | BLE 与 TFT 代码需迁移 | **生产推荐** |
| **B. ESP-IDF + Arduino as component** | IDF 主工程，把现有 Arduino 代码、TFT_eSPI、BLE 库作为 component | 保留大部分现有代码 | 构建配置复杂，需单独验证 | **过渡推荐** |
| C. 纯 Arduino 硬挂 esp-sr | 手工加 `.a` 与头文件、改分区 | 改动看似最小 | 无官方支持、ABI 不稳、易出链接错误 | 仅实验，不交付 |

迁移影响：

| 项 | 影响 |
|---|---|
| 构建系统 | PlatformIO 环境需新增 `env:esp32-s3-jiangling-idf`；`extra_scripts` 的 XMC bootloader patch 需重新验证 |
| BLE | Arduino `BLEDevice/BLEServer` 换成 IDF NimBLE/Bluedroid 或保留 Arduino component |
| TFT | TFT_eSPI 在 IDF 下需重新配置 SPI 主机与引脚宏 |
| FreeRTOS | 现有 `loop()` 轮询改为任务 + 队列；10 ms 轮询逻辑可保留在单独任务 |
| 分区 | 使用自定义 CSV，替换 `default_16MB.csv` |
| 调试 | 音频已移到 GPIO4~7，不再占 JTAG；JTAG 39~42 改给电机，仍用串口日志 |
| 现有协议 | V1.7 的 CMD/ACK/LOG/DAT 逻辑保持不变，只增量新增 V1.8 类型 |

迁移原则：先保证 BLE + TFT + 遥测在 IDF 下跑通，再引入 esp-sr；不要一次性同时改框架和语音。

### 3.6 分阶段实施计划

| 阶段 | 目标 | 主要产出 | 验收标准 |
|---|---|---|---|
| **P0 方案与准备** | 决策定稿、接线与分区确认 | 框架决策、分区 CSV、引脚表、采购/核对麦克风 | 文档评审通过；接线表与硬件文档第八节一致；分区可编译 |
| **P1 采集 + 唤醒** | I2S 采集、AFE、WakeNet 跑通 | IDF 验证工程、串口唤醒日志、底噪与增益记录 | 1 m 唤醒率 ≥ 95%，3 m ≥ 85%；误唤醒 ≤ 2 次/24 h；无爆音/丢帧 |
| **P2 命令词 + 状态机** | MultiNet 14 条命令、状态机、事件帧 | 命令词表、状态机、`DAT_VOICE`/`LOG_VOICE` 上报 | 1 m 识别率 ≥ 90%，3 m ≥ 75%；响应 P95 < 1 s；事件帧可被 App 解析 |
| **P3 对话链路** | BLE 独立语音通道 + 手机 App ASR/LLM/TTS | GATT Service、ADPCM 编解码、时序与降级 | BLE 云链路 P95 < 8 s；1 m 丢包 < 2%；连续 20 轮无崩溃；断网离线命令可用 |
| **P4 增强** | 双麦/AEC、Wi-Fi 长对话、OTA | 双麦 AFE、Wi-Fi 通道、模型升级流程 | 噪声环境识别率提升 ≥ 10 个百分点；Wi-Fi P95 < 4 s；OTA 后模型仍可加载 |

每阶段结束必须回归：BLE 遥控、`DAT_BAT` 遥测、屏幕显示、XMC Flash 启动均不被破坏。

### 3.7 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|
| 当前无麦克风，指标未实测 | 识别率/延迟/功耗不可承诺 | P1 前不做对外承诺；先做声学测试 |
| 电机/风扇噪声 | 识别率下降、误唤醒 | AFE 降噪、麦克风远离电机、双麦、结构减震 |
| 远场 | 3 m 以上明显变差 | 限定近场；需要远场时上双麦 |
| 中文模型体积 | 占 1.5~3 MB/模型 | 独立 `model` 分区；只保留必要模型 |
| Arduino 框架 | esp-sr 无法稳定集成 | 切 ESP-IDF 或 Arduino as component |
| 分区表不含 model | 模型无法加载 | 自定义 CSV；改表后全片擦除 |
| 引脚冲突 | 40/41/42 与 JTAG 冲突；33~37 被 PSRAM 占用 | 按第八节接线；放弃 JTAG；避开 PSRAM 引脚 |
| BLE 带宽不足 | 音频卡顿、丢包 | MTU 247、连接间隔 15 ms、ADPCM 8 kHz 降级、长对话切 Wi-Fi |
| BLE/Wi-Fi 共存 | 2.4 GHz 干扰、延迟抖动 | 音频只走一条链路；Wi-Fi 按需开启 |
| 功放供电/地噪声 | 底噪升高、ESP32 重启 | 5 V 独立供电、加电容、共地规范 |
| 回声/自激 | 播放时误识别 | 半双工；P4 加 AEC |
| 隐私 | 常开麦克风 | 唤醒前不上传；状态灯；可选物理开关 |
| 协议扩展 | 旧 App 不认新类型 | 升 V1.8 并同步 App；未知类型可忽略 |
| 迁移风险 | 改框架破坏现有 BLE/屏幕/启动 | 分阶段迁移；每阶段回归 XMC 启动与遥控 |

### 3.8 待确认决策点

| 编号 | 决策 | 选项 | 影响 |
|---|---|---|---|
| D1 | 框架 | A 全量 ESP-IDF / B ESP-IDF + Arduino component | 决定迁移工作量与后续维护成本 |
| D2 | 对话主通道 | BLE 短对话优先 / Wi-Fi 优先 | 决定功耗、延迟与 App 复杂度 |
| D3 | 麦克风 | 先用单麦 INMP441 / 直接上双麦 | 决定 P1 硬件与结构、识别率目标 |
| D4 | 协议版本 | 升 V1.8 / 暂不升 | 决定 App 是否同步解析语音事件 |
| D5 | 文字输入模式 | App 直连模型（设备只显示）/ 设备做网关 | 决定 `CMD_TEXT_INPUT` 是否需要转发逻辑 |
